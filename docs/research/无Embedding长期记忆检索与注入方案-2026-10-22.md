# 无Embedding长期记忆检索与注入方案

2026-10-22，设计讨论及00实验更新。承接[主调研第9—18节](跨会话长期记忆参考调研-2026-10-21.md)：Python内部实现，只使用现有配置语言模型，不增加Embedding或独立检索/重排模型；七类主类、来源/生效、更正/遗忘和概览后台机制已确认。首期范围为当前工作目录记忆及个人记忆，个人记忆直接允许、不设权限审批。入口由主Agent正常工具选择，候选提取顺带生成可选别名，查询时可正常循环改词。用户已确认验证/切片并授权00，[实际比较](memory00/检索实验结果.md)选择中文二元字组/技术词项适配FTS/BM25，权重3/2/1、RRF60；短词噪声保留。本页下方为讨论形成过程，最新实施合同以[Spec127](../specs/127-memory-and-session-overviews.md)为准，生产功能尚未接线。

## 1. 先选择要读取的对象

| 用户问题 | 建议入口 |
| --- | --- |
| 其他会话做到哪里、继续哪个任务 | 近期会话索引→指定会话概览/历史 |
| 之前选的环境、测试规则、决定原因 | 精选长期记忆检索→按ID读详情/来源 |
| 当时的原话、某条工具输出 | 原始历史的有界查询/读取，不用记忆概括替代原文 |

有明确ID时直接读取并核对范围、状态和版本；无ID才检索。精选记忆与完整聊天不混成一个默认搜索池，避免日志/临时计划挤占有效约定。长期记忆无答案时，由当前主Agent决定是否查询历史，不在数据库工具内部另调模型做隐式研究。

已确认入口选择交给当前主Agent的正常工具选择：工具说明分别写清“任务进展/历史原文”与“可复用环境/规则/决策”的用途，并提供少量对比例子；不增加独立分类模型，也不写按“之前/继续”等关键词硬分流的规则。程序固定负责每轮少量记忆准备、首次近期会话目录和范围校验，语义判断由模型结合当前上下文完成。有明确ID时仍可直读；混合问题可先读会话进展，再检索相关环境/规则。错误选路能通过空结果、覆盖位置和来源不足的反馈调整，不承诺工具描述能保证模型每次选对。

## 2. 检索主路径（推荐候选）

1. 由可信运行上下文限定当前工作目录对应的记忆及个人记忆，直接允许、不增加权限审批；不由模型传入任意项目路径扩大范围。目录采用当前会话绑定的工作区根目录身份，工具内临时cd不改变它。排除已停用/遗忘/到期及明确失配的机器、模块或测试目标条件。条件未知需标记待核对，不把未知当确定适用。过滤在有限候选截断前生效，返回前再次核对权威状态。
2. 技术标识符保留原值和按字段合同允许的规范形式，用于精确匹配；NO_PROXY、TC-ID、路径、符号和数值不得因普通拆词被改成另一标识。完整标识符匹配与拆词补充召回分别处理，首版不默认拼写纠错。
3. 使用SQLite FTS5/BM25评估标题、主题标签/别名和正文的词项相关性；标题/主题命中优先于正文泛词命中，具体权重需实验。类别只辅助排序，用户显式限定时才作硬过滤；不固定让某个大类永远比其他类重要，也不让最近访问时间取代相关性。
4. 对中文先比较标准库可实现的连续二元字组＋英文/技术标识符处理，建索引和查查询复用同一规则。示意“测试规范”→“测试/试规/规范”，覆盖两字词，也会产生噪声，因此只是待实验候选。索引词项与展示原文分开；模型读取原文和真实来源，不把改写词当用户原话。
5. 加少量明确的概念别名，如虚拟环境/venv、代理/proxy。解释器与虚拟环境相关但不等同，相关词可作为显式扩展，不混成同一个事实；超时、401与代理故障不是同义词。
6. 保留精确查询；空结果或当前Agent发现明确缺口时才有限放宽关键词、尝试别名或补充查询。主Agent可在正常工具循环中生成更合适的词，不额外发起独立查询改写/重排模型请求；这些正常Agent轮次仍有调用成本。单字/短词可评估受限范围内的子串回退，不能声称其一定使用索引。

已确认别名机制：写入时可让现有候选提取请求一并返回少量常见别名/缩写，不为此新增模型调用，也不要求每条必填；别名只用于索引，不改写正文、证据或用户原话。查询时主Agent可在正常工具调用中提供等价表达，或初次无结果后再改词；工具只做确定性检索、合并与去重，不在内部请求模型。扩展保留原查询及技术标识符/模块等明确约束，设置少量扩展与总结果上限；不同改写各自检索后去重，不把全部词强制AND或无差别OR。虚拟环境/venv可作概念别名；解释器属于相关线索，需标注并按需放宽；401、超时和代理故障不得互相替代。具体字段及数量在实施Spec收束，不建设庞大同义词库。

最小路径可先用范围/状态过滤＋原文子串查询建立比较基线；推荐投入对比的是中英适配的FTS5/BM25，最终是否采用字组、字段权重和别名集合以相同样本实验决定，不把设计候选写成已验证算法。

## 3. 工具结果与失败边界

搜索先返回有界短条目：ID、主类、标题/原文短摘录、作用域/条件、当前版本、更新时间/最后验证时间、命中词或命中字段及详情入口；记录是否截断/还有更多。BM25排名不是语义正确率，不因词项相似就认定原因或适用条件一致。

按ID读详情时返回当前正文、依据与来源；需要旧决定时显式请求可追溯历史，仍不返回已遗忘正文。候选只作为明确标注的待核实线索按需读取，不混入默认有效结果。查询词由程序转为受控FTS表达式、数据库参数化，不让模型提交SQL。

无结果与读取故障分开：无结果如实返回；IO/索引故障有安全诊断和工具错误反馈，不伪造空列表。普通记忆读取是辅助能力，失败按合同降级，显式写入/遗忘失败仍必须反馈，不能假称操作成功。受限的原文查询可用于诊断/回退，是否使用须标明，不静默声称索引健康。

## 4. 注入职责与时点（总体方向已认可）

- 用户已确认的其他会话近期短索引：新会话首次实际模型请求前准备，有界目录＋概览覆盖位置；后续通过历史工具刷新，不因此每次循环注入详细历史。
- 长期记忆：建议每个新的根用户轮在准备上下文时，读取少量适用的稳定协作偏好短正文，并以本轮请求检索相关短索引；同一轮冻结，不在每次模型调用重做或追加。审批续跑/压缩不另触发全局召回；已读正文仍有来源和版本，后续工具查询核对当前状态。
- 复杂规范、流程、决定、环境及经验主要给索引，由主Agent按需读详情/当前规则或配置；稳定短偏好也有总预算，不因属于user/rule就全量常驻。记忆是带来源参考，不提升为新的权限或替代现行项目指令。
- 用户只说“继续”等弱查询时，优先用当前上下文和会话续接入口；不凭空拼造语义目标，也不随机注入热门经验。
- 条数和总文本/上下文预算有界，同ID/版本去重；放不下时少给条目，保留详情入口和截断信息，不挤占当前任务必要输入。预算数值、是否按字节或近似token等在实验/实施Spec中明确，不把局部记忆预算当整个模型窗口。

正常场景：用户给某模块补测试→可信范围与有效状态过滤→找到环境、规范与流程短索引→主Agent按ID读详情→读取当前Skill/配置/代码→执行与验证。失败场景：同义问法无结果→主Agent换词或查询原历史；旧机器环境明确失配→不进入本机默认候选；索引读失败→明确诊断，不杜撰历史选择。

## 5. 当前接线面与参考事实

当前项目每轮SessionExecution._prepare_resources→prepare_run_resources→freeze_run_resources冻结提示部分；compose_model_prompt用于执行与预览，PARTS和ContextPanel等是固定消费者。未来增加会话/记忆段必须同步预览、估算/预算、观测和持久结果，不另建平行提示装配器。当前主链尚未接任何本专题记忆段。

Claude Code采用短MEMORY.md索引、主题详情按需文件读取；只借鉴加载粒度，不将其描述为全部只用grep。[官方说明](https://code.claude.com/docs/en/memory#how-it-works)

OpenClaw固定c3f0c51d：manager-search-orchestration包含lexicalOnly/fts-only分支；searchKeywordWithFallback仅在正文/文件名均无命中且无错误时扩展；关键词正文使用SQLite BM25，技术路径有独立匹配。只借鉴其词项、路径及受控扩展，不采用它的Embedding/混合服务。[文档](https://docs.openclaw.ai/concepts/memory-search)、[检索源码](https://github.com/openclaw/openclaw/blob/c3f0c51d04ed12603fa9694a1d1cfa312128e010/extensions/memory-core/src/memory/manager-search.ts)

Pi社区pi-hybrid-memory固定068977fd：context hook→buildInjection，searchRecordsWithOptions/scoreRecord按词项、路径、符号、标签等规则选择；其词项正则不覆盖纯中文，不能直接复制。remem固定93d5a3d6的FTS路径按有效状态/项目/类型等过滤后BM25排序，另有查询扩展；其整体仍有向量通道，不等同于本方案。

SQLite FTS5支持BM25和列权重；内置trigram的MATCH不匹配不足三个Unicode字符的子串，“代理”等两字查询不能仅靠它解决。前轮只有机制探针，本轮未执行新的召回/性能实验。[FTS5](https://sqlite.org/fts5.html)、[trigram限制](https://sqlite.org/fts5.html#the_trigram_tokenizer)

## 6. 收敛前的实验

对同一组脱敏固定记忆/查询比较：原文子串基线、默认全文/BM25、中英词项与标识符/别名适配的BM25。样本包括两字中文、自然改写、NO_PROXY/TC-ID/路径、规则与流程交叉、不同机器/环境、被替代/遗忘条目、无答案及“继续”。

同时检查：关键条目能否进入前K、失配/失效条目能否排除、误召回与来源保真、查询/注入文本成本、耗时和故障反馈。没有样本评测就不宣称算法胜出、召回达标或性能保证；不会为填满K返回不相关条目。平台交付另检查目标Python的FTS5能力，不假定本机探针代表四个平台。
