# 记忆验证实验与实施切片方案

2026-10-22，固定样本、验收与00—06顺序已获用户确认，并授权00。00已完成总[Spec127](../specs/127-memory-and-session-overviews.md)、固定样本和[离线检索实验](memory00/检索实验结果.md)；01—06尚未实施。本页保留验收规则与后续顺序，真实模型初验在04另执行，没有批准现在请求供应商或历史回填。真实业务效果和用户掌握程度单独记录。

## 1. 先固定证据和样本

首期手工编写合成/脱敏样本并明确标注，不读取/导入真实私人会话或凭证。每个样本有稳定ID、输入来源身份/时间/机器条件、允许与禁止结果；不把助手陈述成功当成真实工具证据，不用实际产品界面展示合成记录。

| 集合 | 首期规模 | 覆盖 |
| --- | --- | --- |
| 提取/候选语义 | 12段对话＋相关工具记录 | 七类代表场景、明确长期约定/临时尝试、已验证观察/助手猜测、外部指令伪装、候选补证及例行/敏感内容排除。允许不同自然表述，检查断言、条件、状态与来源，不逐字比较模型摘要。 |
| 离线检索 | 24条查询＋同一固定记忆库 | 两字中文、自然改写/别名、NO_PROXY/TC-ID/路径、规范/流程交叉、跨机器/环境、到期/替代/遗忘、无答案及弱查询。12条用于调参，12条留出；禁止看留出结果后把它当独立验证。 |
| 完整流程 | 4个场景 | 新会话续接、测试编排复用、排障经验与环境复核、并发更正/遗忘及在途旧结果。分别包含正常结果与相应失败分支。 |

语义样本作为提取质量初验，不承诺覆盖所有措辞；条数不是统计显著性保证。无答案不能编造记忆；可能相关的检索线索不等于问题已经得到答案。场景以用户刚需为目标，不构造新的固定测试业务策略层。

## 2. 先做不调用模型的检索对比

00比较原文子串、默认FTS/BM25、中英词项/技术标识符适配的FTS/BM25三条路线。比较使用同一正文/别名/查询、范围和状态过滤、结果上限；区别仅在受试索引/分词与排名，不额外给某一路线人工改查询或更多别名。仅用Python现有运行时/标准库SQLite及临时库，不引入Embedding、分词服务或新依赖。

报告每条查询的期望ID、实际前8项、命中/漏召回/误召回、过滤原因、返回文本大小和耗时；汇总Recall@8及错误类型。关键必命中案例须进入前8，禁止返回的范围/状态条目不得进入默认结果；若某条基线已满足关键需求，只有出现可复现改进才增加复杂度。达不到关键案例要求先调整/收窄方案，不把算法候选直接写成已验证产品。

不将少量样本耗时宣称为SLA，也不为填满8条返回无关内容。样本与参数版本、SQLite/FTS能力和实际运行平台随报告保存；本机可用不能替代四平台能力检查。产品实现采用00选出的最小可用路线，不保留三个并行生产检索入口。

## 3. 模型语义与确定性机制分别验证

模型提取初验放在显式后台整理接通后、自动整理接入前：采用当时选定的一个已有配置model_id，12段各执行2次，初始上限24次逻辑请求；SDK尝试另计，输出/时间沿已确认配置。记录实际模型/提示及请求设置、候选断言/依据/状态、真实用量及失败原因，不新增供应商/模型，也不现在读取私有配置或请求供应商。

固定反例中的临时尝试不得替代长期选择、助手猜测不得成为已验证根因、外部引文不得冒充用户约定；逐条检查来源支持和条件，遇到错误先分析并调整，不放宽期望来制造通过。正常样本报告正确提取、遗漏、错误生效和仍候选；允许没有足够依据时少记，不将程序校验说成已证明语义。

确定性合同采用固定模型返回与真实临时SQLite/正式Agent图验证：可信范围、完整可见历史投影、来源/版本与CAS、跨库部分成功、候选转正及TTL、遗忘抑制、登记/保存区别、阈值OR/首次基线、队列/超时/停止、部分失败跳过和上下文预算/预览接线。时间用可控时钟，异步竞态用事件/屏障，避免紧sleep；必要保存与普通观察失败分别注入，不能吞掉主异常或测试断言。

真实模型未通过相应语义样本时，不宣称自动记忆质量达标；确定性链路通过也只证明这些机制分支。固定集合没有错误不能推出任意未来对话都不会误记，尤其同义改写与因果判断仍有模型依赖。

每片先读当时最新代码/Spec，按TDD确认行为红灯→最小实现→专项及所需回归，保留并行工作。新增模块必须有本片真实调用方并完成存在/实质/接线验证；阶段能力只按已接通部分描述，不把只读阶段说成已具备自动记忆。不在01—05提前发布不完整产品，当前也不包含提交/push/打标签/上传。

源头与结果关系：已保存原文由history读取；显式memory写入或后台双输出提出变更；确定性校验提交到权威SQLite；检索/注入再核对状态和版本。后台任务状态、模型调用成功、必要保存成功和业务效果分别记录，不能用一项代替另一项。

## 5. 验证命令与证据界限

实施后的现有门禁沿CI使用`.venv/bin/python -m pytest tests -q`、`npm --prefix frontend test -- --run`、`npm --prefix frontend run build`及`git diff --check`；原生工具加入验证命令PATH，研究测试独立执行，不收集并行参考项目克隆。按实际修改范围完成依赖/语法/单文件500行检查。候选交付沿现有`python -m scripts.build_release --target ...`和`python -m scripts.verify_wheel_install`，不新造构建入口，不升级依赖或改真实环境配置。

00实际入口为`.venv/bin/python -m docs.research.memory00.benchmark`，按calibrate→冻结→evaluate两阶段；执行命令与真实结果见[127-00](../specs/127-00-memory-retrieval-experiment.md)。选定中文二元字组/技术词项适配FTS/BM25，留出必命中10/10、禁止0、无答案2/2；返回精确率81.25%，短词噪声和校准遗漏完整保留。12段语义/4流程仅结构检查，未调用模型或跑产品流程。四平台构建/能力检查与同平台真实安装分开，本机临时SQLite实验不证明其他原机、线上稳定性或业务质量。

用户在00结果后要求深入实验，已完成[00b独立测试](memory00/检索调参与独立测试结果.md)：新测试精确率28/31、有答案召回28/28、无答案误返0/8；旧必命中保持、相关召回92.08%，保留主体提及/含混/重复噪声。当前先评审精度/召回折中并确认产品检索合同；01 history可以独立安排，不自动实施后续产品片或调用真实模型。
