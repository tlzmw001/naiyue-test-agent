# 子智能体续跑与用户直聊参考调研

日期：2026-10-22。状态：需求与[Spec126](../specs/126-subagent-continuation.md)/[四片文件地图](../specs/126-subagent-continuation-file-map.md)的设计已确认；max_model_calls仍为本次委派轮数上限，其余建议获认可，随后已授权并完成126-01首片，其余分片未实施。本文保留需求与参考核验，当前具体设计以Spec为准。

## 已确认的用户目标与范围

1. 一个任务的多个步骤可能反复调用子Agent；有时保留原子Agent上下文，有时使用新上下文。
2. 主Agent按实例ID继续委派时沿用该子Agent上下文；每次结果仍返回本次主Agent工具调用。用户继续通过主会话提出补充要求。
3. 用户明确本需求来自Codex产品体验，因此以Codex为首要参照，Pi/AgentX为辅助对照；不以现有前台子Agent范围否定新增需求。

用户最初还提出过直接与子Agent对话且回复不回主Agent；核验参考项目后，用户明确决定不做用户直聊子Agent，也不保留为后续待办。未来独立讨论由会话分叉/新会话承接；分叉从哪里取上下文、复制哪些内容，留到该功能单独设计。本期不增加子输入框、用户独立子run、直聊结果路由或运行中排队/插话机制，上轮相关三选不再需要回答。以下参考项目直聊能力保留为事实核验，不构成重新立项理由。

## Codex：已核实事实与证据边界

官方[Subagents文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)说明子Agent有自己的agent thread，客户端可打开查看；CLI可通过/subagents切换，主线程收集子结果。文档没有承诺所有客户端/版本均能直接输入或禁止父线程收到后续结果。

## Claude/Codex用户直聊复核补充

不能将上一节V2特定限制概括为“两家都没有做用户直聊”。用户据此决定是否舍弃需求前，必须保留以下区别：

- [Claude Code：Observe and steer running forks](https://code.claude.com/docs/en/sub-agents#observe-and-steer-running-forks)明确说明Enter打开fork对话并可发送后续消息，且fork或subagent对话打开时，后续普通消息/Skill直接发给该Agent；某些运行中提前读消息操作另有版本要求。该页也描述子任务结果回主会话，不能仅凭直接输入推导结果绝不回父。
- [Claude Code Agent teams：Talk to teammates directly](https://code.claude.com/docs/en/agent-teams#talk-to-teammates-directly)支持用户直接与teammate交互，但这是实验性团队机制，teammate是独立Claude Code会话；不以此替代普通子Agent证据或建议项目引入完整团队平台。
- [Codex：Switch agent threads with /subagents](https://learn.chatgpt.com/docs/developer-commands)明确说切换后可查看或继续该Agent工作。公开源码的V2特定直接输入拒绝仍然成立，二者说明客户端/运行模式存在边界，不足以否定整个产品的用户直聊能力。
- 两家以上材料没有建立用户要求的统一合同“直接用户轮次回复绝不自动回主Agent”。此事实与能否打开子线程发送消息分别记录。

项目取舍：主Agent复用既有子thread解决多步骤背景重复传递；独立用户直聊另增用户输入/事件交付、父委派竞争、审批/停止、必要保存和结果接收方规则。用户已决定取消直聊，以未来会话分叉/新会话满足独立讨论；决定不依赖“两家都没做”的错误前提。保留新建干净实例或按ID继续旧实例、结果仍回本次主工具调用；终态/每次委派限额/权限/保留等合同已收束到Spec126，本轮不实施。

## 本项目真实现状

- tools/subagent.py的SubAgentInput只有agent/task；每次新父调用生成新实例。
- application/subagent_history.py的subagent_identity由session/batch/tool_call摘要产生；subagent_records从父调用/结果派生历史记录，不是独立实例登记表。
- application/session_subagents.py的prepare_subagent_instance登记到当前_run.subagent_instances；ainvoke_subagent创建唯一driver并等待；assert_subagents_settled在父run结束时清除实例内存登记。清除登记不等于删除原child checkpoint/聊天档案。
- agent_runtime/subagents.py的ainvoke_subagent_step已有独立child_thread_id，初次任务标为delegated_task，不能作为真人授权；内部resume目前是审批Command，不是新的用户轮次。
- build_subagent_runtime没有根的steering/follow-up消费者；max_model_calls当前通过ModelCallLimitMiddleware(thread_limit=...)实施，每次新实例时等价于单次限制。新增同thread续跑须显式在新委派开始重置计数；审批恢复不重置，避免变成实例累计限制。
- Web/侧栏当前可查询、展示、按来源停止，尚无子聊天输入入口。不能只加输入框：实例生命周期、来源、必要保存、审批/停止、事件归属和结果投递都要同步。

## 已确认方向与技术合同

区分角色、可复用子会话和本次执行。角色是配置；子会话持有独立身份及历史；一次执行另有run和当前父调用。执行完成可回到空闲，不要求为保留历史一直运行模型或挂住协程。以下两种主Agent调用属于已确认范围，具体接口/状态/存储以Spec126为准。

| 入口 | 上下文 | 本次结果交付 |
| --- | --- | --- |
| 主Agent创建新子会话并委派 | 新历史，继续沿用现有不默认复制父历史的合同 | 回当前父工具调用 |
| 主Agent按已有实例ID委派 | 沿用该子会话历史 | 回本次父工具调用，不改写旧结果 |

结果回本次父工具调用，不改写以前的工具结果。同实例执行准入需防止并发；按角色名不能隐式选中任意旧实例。父委派仍需真实session/工作区/实例归属校验，工具权限仍在原执行边界检查。

正常链：父委派新建/定位子会话 → 该实例准入 → 原子图执行与必要保存 → 本次父ToolMessage；再次委派同ID延续历史。侧栏继续承担查看/停止，不新增直接发送入口。

失败链建议：未知/越界实例或当前不可接受新任务时，在模型/工具执行前拒绝；保存失败显式失败，不能自动重放已发生工具效果。

会话分叉仍是独立后续功能，本期不建立分叉接口或承诺可从任意子checkpoint创建完整主会话。

技术合同已确认：成功且保存确认后可继续，支持跨应用正常重开；max_model_calls每次委派独立计数，同次审批恢复不重置。角色指纹/当前权限重验、同实例准入/停止/必要保存和聊天档案/checkpoint稳定引用按Spec126执行，尚未实现。

建议最小验证点：新建与复用历史区别；同实例准入/跨实例隔离；再次父委派能继续同一历史且结果绑定本次调用；审批不可绕过；停止/保存失败无重放；持久引用不因父压缩或修剪失去实例。
