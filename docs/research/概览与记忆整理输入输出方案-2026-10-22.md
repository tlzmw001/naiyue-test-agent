# 概览与记忆整理的输入、输出与成本

2026-10-22，第二项讨论建议，待用户确认；不批准产品实现。存储按[已确认方案](长期记忆存储与数据归属方案-2026-10-22.md)，触发仍为成功保存点检查双阈值或显式memory登记。本专题只收束整理模型看什么、返回什么及调用边界。

## 1. 最小路径

应用确认根用户轮正常结束且必要保存成功→登记/合并待整理目标→冻结一批已保存来源→准备旧概览＋新增原始材料＋少量当前相关记忆→一次既有配置模型调用→分开校验概览和候选→核对来源版本/删除标记后保存→后台任务显示实际覆盖和结果。模型不运行工具或独立Agent循环，不回填旧根run消息/checkpoint，也不启动后续用户轮。

正常一批一次逻辑模型调用，同时输出概览与零到若干记忆候选；不是先概览、再独立抽取、再评分的多模型流水线。复用模型目录/请求适配、输出额度和观测能力，不直接复用上下文压缩算法/写回，也不直接使用面向UI的历史JSON作为模型输入。

## 2. 输入边界

| 输入 | 用途和限制 |
| --- | --- |
| 程序提供的来源信封 | workspace/session/当前历史分支、消息ID及版本、批次上下界、回复边界与运行终态；程序生成，模型不能扩大范围或自报已覆盖位置 |
| 旧概览 | 维持目标/进展连续性；明确是旧派生产物，不能作为新长期事实的独立证据 |
| 新增已保存用户/助手可见正文 | 区分用户约定、助手计划/推断/结果陈述；保留语义，不能把助手自述成功视为工具验证 |
| 相关工具记录的有界投影 | 工具名、脱敏参数/命令、成功失败/退出事实、正文有限片段、归档入口及截断标记；程序负责大小/字段过滤，模型判断重要性，不假装代码能按语义挑中全部关键内容 |
| 少量当前相关记忆 | 带ID/版本/范围/状态的短条目供去重/冲突参考，可为空；不全量读取个人记忆，不把已有记忆当新证据 |

原始历史走持久聊天档案及真实reply边界，不从可能已压缩的模型上下文重建全部证据；审批续跑不能重复计完整用户轮。先限定会话和保存上界，再逐条投影可见字段；reasoning_preview、隐藏思考、内部system/权限恢复材料、凭证字段和完整模型配置不进入整理输入。正文/工具参数中的已识别敏感信息仍要过滤，不能把字段过滤当作自然语言秘密绝对检测保证。

工具返回的外部文本作为引用数据，不能充当用户的长期要求。子Agent报告同样是助手陈述，首期不自动展开所有子历史；若缺少可核对的原始证据，就不能将其泛化成已验证观察。图片/二进制仅保留可见文字描述和引用，不在首版整理里额外做识图；相关证据缺口必须可见。

## 3. 输出合同

| 输出 | 模型负责 | 程序负责 |
| --- | --- | --- |
| 更新概览 | 当前目标、实际进展、阻碍、下一步；计划/已做/已验证分清 | 所属会话、来源覆盖/遗漏、历史分支与版本、生成时间、概览版本；实时运行状态仍读当前程序事实 |
| 少量记忆候选，可为零条 | 七主类、标题/正文、可选别名、建议范围/适用条件、依据种类、支持来源及短引文 | 范围/来源校验、类型和长度、已有版本/删除标记、重复/冲突、状态及ID/版本分配；不由模型的confidence决定生效 |

建议首版为固定JSON响应＋程序schema校验，先不把供应商原生结构化能力作为运行前提，不为格式错误另开模型修复循环。当前已确认的生效规则保持：明确用户持久约定和直接证据支持的观察可按条件生效，推断/冲突保留候选或丢弃；空候选列表是正常结果，不为产出条数而编造内容。

示意：用户确认“本项目以后用.venv”，工具确实在该环境跑测成功，可记录项目环境选择并附当次验证；用户只说“本次临时试试”，不替代原长期选择；助手猜测代理导致401且无验证，不生成有效因果经验。这些是设计样例，不是本轮实际模型/测试证据。

## 4. 输入超限、积压和首次启用

正常增量按自动处理位置选取新的来源，优先以完整轮次分批；不每次发送完整会话。旧概览、相关记忆、系统约束和输出预留都计入预算。工具正文先做有界投影，截断/遗漏有明确标记，禁止将未提供部分描述为已完整检查。

### 4.1 触发、分段与失败跳过（用户确认）

用户认可分批、分段推进，并明确记忆无需保证完整覆盖：已经失败的部分下次跳过，不为某段对话阻挡后续记忆。此合同替代上一版“失败来源留待下次阈值重试、必须恢复覆盖”的建议，不建设自动补漏/失败补偿队列。

- 触发基准：成功登记/合并自动整理目标时，记录当时已保存来源上界；下一次轮数和正文量只累计该上界之后新增内容。任务结束不再清零，旧失败量不能导致下一次对话立即再次触发；处理期间新增内容保留计数。显式请求可以绕过阈值，不绕过输入和来源校验。
- 分批/分段：多轮过大先缩小批次；单轮过大按消息/工具记录及必要原文区间分段，保留来源与未完信息。每批一次模型调用，仍受单任务批数/时间上限。正常尚未尝试的分段可按预算继续；中间进度服务正常推进，不承担失败补偿义务。
- 失败跳过：某批/片段经过既有单次调用策略最终失败，记录来源范围、原因和结果，移出自动待办。下一次阈值触发不会重读该失败范围；网络/超时、格式及保存失败同样不自动建立跨任务重试。条件改变或新增消息也不自动重新激活旧失败；只有用户显式要求重新整理指定历史时才允许另行有界处理。
- 独立成功保留：前面已经保存的结果不因后续片段失败而回滚；能独立解释的后续材料可继续。依赖未完成分段的中间结果不发布为完整概览或有效记忆，跳过后不能把缺少上下文的猜测当有效事实。
- 处理位置与结果分开：自动处理可前进到已处理或已跳过位置，但成功结果只描述实际来源，不把跳过写成已成功整理。不要求维护必须补齐的连续覆盖账本；轻量失败/不完整标记及每条有效记忆的真实来源足以查询诊断。跳过不删除原聊天，历史工具仍可读取。
- 状态保留：已登记目标、正常处理进度及失败跳过事实需保存，避免重启后重新把旧失败当自动待办；进程内后台任务本身仍不承诺重启接管或自动唤醒。失败后的主Agent结果保持原合同。

阈值示意（假设轮数阈值3且正文阈值未达到，不是默认值）：第11—13轮触发，登记基准为13；12轮对应片段失败并跳过，其他独立成功结果保留。第14/15轮不会因12轮失败马上触发；第16轮按新增14—16轮触发，12轮不再进入自动整理。正常未尝试分段与已经失败片段分开，前者可继续，后者不自动补做。

### 4.2 首次启用与存量历史（已确认）

用户已确认history＋memory两个工具及首期聊天管理，并认可本节首次启用策略。不在启用/启动时自动调用模型遍历全部旧会话，不把初始化等同于全库回填；保留已确认的成功保存点双阈值及显式登记机制。

| 场景 | 已确认行为 |
| --- | --- |
| 启用后新建会话 | 从新会话起点累计新增轮次/正文量，达到阈值或显式请求后有界整理。 |
| 已有会话首次启用自动整理 | 在启用后的新增用户轮开始前记录既有已保存上界作为触发基线；既有全部历史不直接计入新增阈值，打开/查看历史不自动启动模型任务。 |
| 已有会话首次达到阈值 | 冻结当次已保存目标，以预算内最近的完整轮次为首批上下文，可包含部分基线前旧轮；单轮过大仍按既定分段规则。实际提供范围之外明确未整理，后续按新上界增量推进，不自动向前补漏。 |
| 其他旧会话尚无概览 | 近期目录只给真实元数据及无概览状态；history仍可查询/读取原文，不伪造任务进展，也不为了填满目录自动调用模型补概览。 |
| 用户显式要求整理旧历史 | memory登记当前允许范围内的指定会话/区间，按已有后台机制、总时限/批数/来源/去重及遗忘校验有界处理；依赖完整当前轮的请求仍等该轮必要保存，不变成无限全量迁移。 |

例：已有100轮，新增轮数阈值假设为3；记录100为基线，101—103轮使其触发。若首批预算允许98—103轮，则概览/候选仅依据这些实际来源，1—97轮标未整理。后续从104轮增量，不自动补1—97轮。数值仅说明行为，不提前确定阈值/输入额度默认。

首次选取旧材料不改变其原始来源时间，不能重置记忆TTL；部分历史概览也不能声称全历史覆盖或把未知说成没有发生。显式重整可补充已知范围，不把自动跳过/失败重新放回待办；历史改写/版本冲突及必要保存失败沿第5节合同处理。本节设计已确认，不授权实际回填或产品实现。

## 5. 独立校验和失败

- 整次模型失败/超时、空输出、截断或顶层JSON不完整：不发布本批新概览/候选，保留旧数据，记录失败并跳过本批来源，不在下一次自动任务补做；不从半截文本抢救权威状态。
- JSON可解析且概览有效，但候选区结构失败：概览可以保存，候选部分单独标失败并跳过；概览来源和候选处理结果分开记录，不将概览成功记成候选也成功。仅用户显式要求时可重新整理指定来源，并保留来源去重。
- 候选结构有效但某条不符合来源/敏感/语义边界：跳过该条并记录安全原因，其他合格条目独立处理。推断保持候选不等于处理失败；不记录被拒秘密正文。
- 概览失败但某些候选独立符合全部来源/提交规则：可按条保存；后台任务显示部分成功，不能声称概览已更新。
- 历史被重生成/改写或目标已删除：重新核对受影响消息版本，不发布过期结果。仅在同分支追加新轮不必丢弃旧批次，保存到实际覆盖位置并明确落后。
- 记忆在模型等待期间被更正/遗忘：最终提交检查预期版本和抑制标记，旧输出不能覆盖或复活。单条冲突不推翻其他已确认保存，不承诺项目库/个人库跨库原子成功。
- 停止/失败/审批等待本身不触发自动整理；后续正常保存的有界原始区间可包含已持久化的失败/停止材料，需保留原状态，不把计划当完成。显式更正/遗忘已有条目仍按既定工具事务当场完成，不受完整轮整理等待约束。

## 6. 模型、成本与观测

建议默认使用触发整理时会话选中的既有配置模型；允许可选指定已登记model_id，不新增供应商、Embedding或独立评分模型。登记任务时冻结选中的模型及受支持请求设置，避免排队时会话切模改变同一任务的行为。首版不强行修改temperature/思考参数，输出额度经现有适配层限定，不变更共享模型实例。

每批输入、输出、候选数/正文大小、单任务批数/时间及后台并发均有界，具体配置名/默认值放第四项统一收束。自动/显式更新合并到已确认的同会话一个在途任务，避免相同来源重复生成；显式“记住这个”若已由主Agent提交清晰内容和来源，不为复述再调模型。

首次启用策略认可后，用户也已确认开关/模型/阈值及额度初值、启动读取和修改TTL不追溯既有截止时间，见[记忆配置与运行参数](记忆配置与运行参数方案-2026-10-22.md)；设计确认不代表配置已接入产品。

后台整理计入所属会话用量，以独立后台执行标识和purpose=memory归属，关联来源根run但不追加到已结束根run或伪造新用户轮；复用model_call_started/finished事件，SDK尝试仍单独观测。当前用途白名单、callback运行上下文、存储/汇总和前端标签必须一起接线，不是加一个tag就有完整记录。模型返回和schema解析/必要保存成功分开显示：模型调用可已消耗token但任务因解析/保存失败而失败；用量缺失显示未知，不填0。

不增加记忆专用的网络重试循环或格式修复模型；沿现有模型SDK策略并受本任务总时限约束。普通自动整理失败有诊断、保留旧概览，不改变已经结束的主Agent结果。
