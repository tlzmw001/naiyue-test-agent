## 1. 目标、边界与本次修订

1. **应用多项目**：统一查看和添加项目，在项目中创建会话；会话绑定的项目与执行环境明确。
2. **先做 R1**：Agent 循环、模型调用、审批、状态、history 和 memory 留在本机，项目文件与命令可以在远端沙箱执行。
3. **不做 git worktree**：每个沙箱会话独立容器和代码卷；默认仍可使用本机执行。
4. **纯本地流程继续可用**：不安装 Docker、不连接远端，也能使用本机项目和普通对话。
5. **R1 依赖本机应用服务推进任务**：本机服务停止后不会继续调用模型或安排下一步。远端已由 envd 接管的进程可能继续，取决于远端容器状态和关闭策略；本机 Docker 在本机关机后不能继续运行。正常服务退出与意外断线不能混为一谈。

本轮修订采纳：每项目各自绑定根图/子 Agent 图/saver；暂缓自动空闲回收；环境绑定与路径分开；远端操作 ID、结果未知和输出续读合同；三个 Git 版本与受控合入；独立 chats 库与个人记忆；stdio MCP 显式开放给沙箱会话；存储单向依赖；网络只做 external/none。

**不在第一版范围**：R2/RemoteRunExecutor/云端账号与多租户；跨库路由 checkpointer；项目级配置覆盖；非 Git 目录的沙箱执行；任意脏工作区三方应用；沙箱推送/发 PR；git/模型凭据自动注入；项目或沙箱自动空闲回收；IP/域名白名单；devcontainer 解析。白名单后续先做现成组件与防绕过成本验证，测试凭据注入另行设计。

## 4. 目标架构与依赖方向

```text
CLI / Web
    └─ 本机命令与事件协议
         └─ 本机应用服务（唯一资源拥有者）
              ├─ ProjectRegistry：项目登记、位置绑定与跨库操作状态
              ├─ 全局准入/会话路由：max_active_runs，核对会话项目归属
              ├─ ProjectHost × N
              │    └─ 项目库、saver、根图/子图、项目记忆、归档、用量/诊断
              ├─ 普通对话资源：chats 库、saver/图，无项目或文件执行权限
              ├─ 共享资源：模型客户端、适合共享的工具定义、个人库、MCP 管理
              └─ 会话环境绑定 → ExecutionEnvironment
                   ├─ HostEnvironment：本机文件与进程
                   └─ DockerEnvironment → envd：沙箱文件与进程
```

- ProjectHost 不简单重复打开整套 Application；应用级资源只由应用关闭，项目级资源由对应 ProjectHost 关闭。
- 执行图随所属项目绑定，不新增跨库路由 saver；全局运行额度不随项目数量倍增。
- **依赖规则**：contracts 保存必要共享类型/协议/异常；application 编排业务；storage 实现数据库与仓储；execution 实现环境操作；专门装配入口组合这些实现。
- storage 不导入 application；执行后端不依赖 CLI/Web 或应用服务实现。环境文件操作、工具反馈和业务审批职责分开。
- 接口只围绕当前真实替换点建立；FTS/SQL 留在 storage，业务选择与输入/结果编排留在 application。
- 架构测试覆盖绝对/相对/函数内导入及 from-package-import-child；迁移中允许清单只能精确记录存量且逐片缩减，不能把互相依赖永久合法化。

## 5. 项目、环境、服务与协议合同

### 5.1 项目注册表与普通对话

- Project 包含 UUID、名称、LocalSource/GitSource；数据库路径由应用存储布局派生。
- 注册/迁移/删除的操作状态（pending/active/migrating/deleting）与位置可用性、信任状态分开。
- 注册表与项目库不在一个既有 UoW 中：保存明确操作进度，步骤幂等；服务启动对账后继续或报告失败，不能凭注册表成功就声称项目库已创建成功。
- 旧库登记先保留原 UUID 与绑定位置，再验证目录；目录失效仍可读历史，禁止新执行。UUID/路径冲突明确报告，不任选一库。
- 新身份合同是用户确认的位置绑定，不是对目录内容的密码学证明。Git origin、根提交等仅作变化提示；仓库无提交、多个根、合法改 remote 均不能被伪装成可靠身份验证。
- 重新定位须明确确认、核对 expected_root 并关闭宿主。注册项目的 Local 会话/子实例引用 project_local，跟随该显式操作解析项目当前位置；不通过页面切换或 cwd 重绑。last_execution_path 仅展示/审计，审批额外绑定注册 revision，变更后旧许可过期。迁移与准入见 R1-07D；它替换 R1-03/04 原“旧会话继续固定原路径”的合同。
- 普通对话不伪造 Project。复用现有会话与检查点持久化；个人记忆按用户范围准入，不先要求 project_id 非空；其来源引用仍须按实际拥有该会话的库核验。
- --no-session 不注册项目、不创建身份文件、不持久化聊天、不开放项目 history/memory；有目录临时会话仍可明确绑定 Host 执行，不等同于无目录普通对话。
- 删除项目不得删除个人库或用户目录；运行中的任务和未取回产物必须先明确处理，跨库删除中断后可对账恢复。

### 5.2 会话环境绑定与文件职责

| 信息 | 来源与消费者 |
|---|---|
| project_id / session_id | 应用登记与会话状态；决定数据和会话归属 |
| 环境绑定记录 | 应用保存并核验：绑定 ID、项目/会话、环境类型、提供方、Docker 端点身份/实际容器 ID、内部根路径、平台 |
| EnvironmentRef | 提供给本次 run 的不可变环境描述；不含凭据或连接对象 |
| fs / exec 能力 | 由装配注入到 RunScope；文件/进程工具使用，模型不选择任意提供方或容器 |
| operation_id | 每次有副作用的操作在发送前确定，用于远端查询、重复提交核对与结果关联 |

- 每次新执行核对绑定记录与会话一致，再验证目标环境；模型/客户端传入 env_id 不能自行建立权限。
- 审批绑定冻结的执行目标；已有审批不能跨环境绑定、容器替换或本机/沙箱复用。注册表与提供方核验失败直接拒绝，不回退。
- Linux 沙箱路径按 PurePosixPath 语义；Windows Host 路径保留 Windows 语义。协议只传可序列化路径及所属环境，不在本机 resolve/stat 远端路径。
- 真正的符号链接、原子替换、句柄和摘要检查在文件所在环境执行；路径匹配不替代实际文件安全校验。
- 沙箱内文件操作与忙碌表由对应 envd 管理；本机不同会话继续共用按真实路径管理的忙碌表。同一文件不能因 session_id 不同而失去互斥。
- 一个沙箱内根 Agent 与子 Agent 默认共享该会话环境；子实例续跑核对原绑定，不借用父会话后来切换的环境。
- 环境健康检查只是执行准入，不承诺检查后环境不再变化；工具操作本身仍需处理真实 IO 失败。
- 不存在的执行身份不能补成 Host/Local；允许无目录普通对话，不意味着文件或进程入口也允许无环境。

### 5.3 单一服务、命令与事件

- 服务按 OS 用户＋规范化 data_dir 独占；核对客户端版本、data_dir、配置路径，配置冲突时拒绝，不启动第二个服务争用同库。
- 复用现有 HTTP/SSE、认证、幂等、回放与错误映射；第一版不同时增加 WebSocket。CLI 真正转为协议客户端后清理旧 owner-loop 桥，不在迁移中提前删除。
- 命令范围覆盖会话、run、审批、模型/工具/权限、压缩/重新生成、history、任务 list/output/stop、项目和变更集操作。
- 有副作用命令有请求 ID 与参数核对；事件有流标识和序号。回放过期时重新取快照，不承诺无限回放或“事件天然恰好一次”。
- 运行协议使用项目/会话/绑定 ID 与环境内路径；添加本机目录、服务握手等管理操作可以传经验证的本机路径。不能用“绝不传绝对路径”阻断这些真实入口。
- 协议不传 Python 对象、Path 对象、图、Future、锁或连接。R2 的所有权与远端持久化不在本期预先实现。
- Web 认证继续有效；新项目浏览/添加/删除 API 同样认证与验证。客户端断开不等于服务关闭。
- 服务异常退出后的注册表、任务和变更集恢复分别验收；同库事务不能替代跨进程或 Git/数据库之间的操作恢复。

### 5.4 执行消费者清单

| 消费者 | 沙箱会话中的位置与规则 |
|---|---|
| Read/Ls/Find/Grep/Write/Edit | env.fs；保留截断、授权、安全 IO 和变更反馈；rg/fd 位于环境内 |
| Shell/AITest/后台进程 | env.exec；保留字面 argv、停止、输出和前后台转换合同 |
| AGENTS.md / CLAUDE.md / Skills | 应用通过 env.fs 发现与读取；忽略文件不因隐含复制而自动进入沙箱，输入清单需说明 |
| 根/子 Agent 运行准备与恢复 | 从会话/子实例原绑定得到环境，不用进程 cwd 兜底 |
| stdio MCP | 本机启动；沙箱会话默认不可用，必须显式允许该服务器供沙箱会话使用 |
| HTTP MCP | 本机连接配置的服务端；不自动迁入沙箱，不因此免除原工具审批 |
| web_fetch / web_search | 本机请求；不受沙箱 none 模式约束，维持原网络/权限合同 |
| history / memory / 应用归档 | 本机服务按归属处理；项目库、chats 库和个人库各自清楚 |

stdio MCP 的可用工具筛选和实际调用入口均检查；恢复的旧调用也不能绕过。已有 stdio 配置不自动视为允许沙箱会话。显式允许后仍执行原审批，UI/审批显示“本机执行”，不声称整个会话的全部能力都已被容器隔离。

## 6. Docker、网络与远端操作

### 6.1 提供方与网络【决策】

- DockerEnvironment 支持本机 Docker 与 SSH 远端 Linux daemon；envd 通过 Docker exec stdio 等受控通道交互，握手核对协议版本。
- 本机主动建立通道只表示协议方向，不证明容器无法主动联网。镜像/rg/fd/envd 版本与必要运行时在 R1-10 冻结并验收；镜像选择使用全局配置，不扩展为 devcontainer 平台。
- 每个会话使用独立容器/代码卷；共享缓存只提供受控访问，不能成为任意读写其他会话代码的入口。
- 本期配置合同如下，已在 R1-10 接入并按创建时冻结；细节见该片 Spec：

```toml
[sandbox.network]
mode = "external"
```

| 值 | 含义 |
|---|---|
| external（默认） | 应用不额外限制沙箱出站，访问范围由公司/云网络/管理员策略决定；不声称检测到外部策略存在 |
| none | 禁止沙箱对外联网，保留内部回环；限制实际生效失败时拒绝启动，不降级到联网 |

- 创建沙箱时冻结模式；修改配置只影响之后新建环境，不静默切换或重建旧容器。
- 本机模型 API、Docker over SSH、镜像拉取、HTTP MCP 和 web_fetch 不属于沙箱进程出站，独立遵守自身配置与权限。
- 外部策略部署验收从实际沙箱验证用户提供的一个允许目标和一个拒绝目标；不接管公司防火墙，不凭宿主机结果推定容器路径一致。
- 第一版不加入未生效的白名单字段。未来先验证受控出口代理是否能以合理成本覆盖直连绕过、DNS/IPv6、重定向和故障拒绝。
- 不挂载 Docker socket、宿主凭据目录或用户工作目录作为可写执行空间；CPU/内存等通过实际支持的 Docker 能力配置，磁盘限制须验证所选卷/存储驱动，不先承诺通用配额。

### 6.2 远端命令与写入合同

正常路径：会话绑定核验 → 本机记录 operation_id/参数身份 → envd 接收并登记 → 执行 → 保存结果/输出序号 → 本机查询或接收 → 本机归档及任务投影。
失败路径：发送后断线 → 执行结果未知 → 按同一 ID 查询 → 已完成则返回旧结果，进行中则继续观察，仍无法确认则保持未知；禁止另分配 ID 自动重放。

- 后台 task_id 可作为 operation_id；本机重连/重启能找回它。现有内存登记不能直接算作持久去重。
- envd 核对 ID、环境绑定和请求指纹；相同 ID 参数不同拒绝，同一操作进行中不再启动另一份。
- 在保存操作记录与进程启动/文件替换之间存在崩溃窗口；不能仅凭一张记录表承诺跨崩溃恰好执行一次。
- 已知完成记录返回原结果，不再次修改文件；文件当前摘要等于目标值只能证明当前内容符合预期，不能单独证明该操作已执行。
- 无法可靠核对执行结果时返回“结果未知”，让后续显式处理，不伪报未执行或成功；R1-11 已冻结：默认最多1024条操作记录，完成墓碑不自动到期，满额拒绝新副作用，随显式销毁环境清除。
- 输出使用偏移量/序号续读与去重；断线期间远端需要有界输出暂存及溢出状态，本机持久归档依然位于沙箱外。
- list 返回最后确认状态并标记未知；output 可读本机已有归档，不能伪称最新；stop 未确认不能显示已停止。
- 本机必要归档真实 IO 故障沿既有失败合同处理，远端不可达时只能记录停止未确认；不能把所有断线都当成归档损坏并盲目重跑。
- 会话恢复、子实例续跑、文件读写、前后台命令均使用原环境绑定；环境不可用时历史仍可读，无本机回退。

### 6.3 生命周期与失败分类

- 生命周期为创建、运行、停止、启动、销毁；不把 Docker stop/start 称为保留进程内存的休眠。
- 第一版不做自动空闲停止/销毁或自动项目资源关闭；显式停止须明确影响运行进程，销毁须先确认未取回改动的保全。
- 已确认销毁报 env_expired；连接失败且无法确认存在性报 env_unreachable。两者不能互换，也不自动重建。
- 本机目录 missing/not_directory/unreadable 与实际项目/绑定不匹配分别报告；作用范围不一致不伪报 wrong_project。
- CLI/Web 客户端退出：应用服务继续拥有任务。意外断网或本机服务崩溃：远端任务可能继续，恢复后对账。
- 正常应用服务关闭已在 R1-11 接入：封新提交、等待已接纳提交结算，按原ID停止并确认；失败保留停止未确认且关闭报错，容器保留。单次RPC和stop使用冻结期限，不新增全应用总关闭硬期限；多项不可达时耗时会累积。
- 本机关机时本机容器不能继续运行；独立远端主机/容器仍正常且未被停止时，已接管进程可继续，但 R1 不再发起下一步。

## 7. 变更集：三个版本、传输与受控合入

### 7.1 版本与输入快照

| 字段（拟定） | 含义 |
|---|---|
| original_head | 送入任务前本机仓库 HEAD；GitSource 为本机裸镜像固定的源提交 |
| input_snapshot | 实际送入沙箱的快照提交，包含本次明确纳入的未提交改动 |
| output_commit | envd 汇报并经本机核对的任务结果提交 |

- 审查比较 input_snapshot → output_commit；不能用 original_head 的差异冒充 Agent 独立贡献。
- 临时索引生成快照，保留用户原暂存区和工作区，包括同一文件部分暂存状态；不得替用户 stash/reset。
- 输入清单明确处理已跟踪、未跟踪、忽略文件及隐藏 Skills；不自动夹带 .env/凭据。Git 历史也可能含敏感内容，bundle 不能被描述为天然无密钥的传输。
- 本机使用用户凭据 fetch；私有仓库同样由本机提供对象。固定不可变提交后发送 bundle，沙箱不直接依赖 git 凭据。
- 初次发送必要对象；增量只相对于接收端确认持有的基准；缓存缺对象时补传，不凭“有远端”假设基准存在。
- 接收端检出任务分支，记录固定输入快照；初版遇到 LFS/submodule 等未支持数据明确拒绝沙箱准备并说明，本机模式仍可用。
- 只有 git init、尚无 HEAD 的新空项目先支持本机执行；无提交仓库的沙箱输入策略由 R1-12 明确讨论，不暗中创建用户提交。

### 7.2 取回、验证与审查

1. 任务结果包含明确 output_commit；需要自动提交剩余任务修改时，按交付动作形成结果，不自动推送。
2. 本机在受控导入位置运行 bundle verify 和对象完整性检查，核对任务/绑定/输入快照、输出提交、允许引用及输入祖先关系。
3. 验证引用与 envd 回执一致仅是来源关联检查，不证明返回代码安全；只更新应用拥有的 refs/naiyue/tasks/<id>，不接受任意引用写入。
4. 导入到本机项目仓库或 GitSource 裸镜像，审查输入快照到输出提交的 diff，区分用户原有改动与 Agent 增量。
5. 对象导入不执行沙箱传来的 hooks；本机 Git 的 hooks/过滤器等实际行为须单独管控，不以 fsck 替代执行安全。提示属性、符号链接、权限位和大小写冲突。

### 7.3 第一版操作范围

- 导入和diff审查后，仅支持合入当前本地分支、建立本机新分支、丢弃应用任务引用。远端推送、PR和其他发布操作由用户自行决定并在应用外处理，当前应用不提供这些入口。
- **建立分支只建立引用**，不自动 checkout，不改用户工作区；分支可能包含输入快照中的用户原有改动，展示时说明。
- 自动合入同时要求：当前 HEAD 等于 original_head；暂存区/工作区干净且不存在会被覆盖的未跟踪文件；无未完成 Git 操作；input_snapshot 的树等于 original_head 的树。
- 再要求任务历史从输入快照开始线性展开、无 merge commit/异常历史；仅按顺序 cherry-pick 任务增量，不把合成快照提交带进正式历史。
- 不满足时只提供审查和建分支；执行前重核条件，预检不是未来写入的永久许可。
- GitSource 没有用户工作区，不提供“应用为未提交改动”；可在裸镜像中保留分支并显式推送。
- 脏工作区三方应用是后续独立切片，须处理新增/删除/重命名/二进制/模式位/暂存区保留/冲突，不在第一版实现。
- 应用注册表分别保存沙箱结果事实与独立本机交付状态、操作ID；项目会话库保存原会话身份，不混入envd进程日志；Git 与 SQLite 不在一个事务内，崩溃后据实际引用/提交对账，不重复合入或伪报完成。失败清理不擅自回滚用户修改。

### 7.4 实验与方案比较的修正

用户在 Git 2.50.1 的临时仓库复现实验：部分暂存的 user.txt 在快照后保持原暂存状态；original_head→output 同时包含 user.txt/agent.txt，input_snapshot→output 仅包含 agent.txt；目标干净时 apply --3way --check 成功，目标工作区与暂存区不一致时报 does not match index；单文件 merge-file 可产生冲突标记。
此前助手临时仓库实验也观察到基准差异和 --3way 的 index 限制。以上验证不覆盖完整产品合入流程或所有平台。
Git --binary 补丁能够保留二进制/模式信息，拥有基准对象时也可以三方应用。bundle 的优势是运输 Git 对象和历史，不是自动解决脏工作区、大小写或行尾检出问题。
主要依据：[git bundle](https://git-scm.com/docs/git-bundle)、[git apply](https://git-scm.com/docs/git-apply)、[git cherry-pick](https://git-scm.com/docs/git-cherry-pick)。

## 9. 第一片 R1-01：执行身份必须明确，错误如实报告【已完成本机验收】

### 9.1 用户能看到的变化与范围

- 正常会话启动前后台命令行为保持；内部调用方漏传执行目录时，在启动进程之前明确失败。
- 路径/请求 cwd/会话执行身份不一致，按范围错误拒绝，不伪报项目 UUID 不一致。
- 路径或身份文件因权限/IO 问题不可读，显示“执行目录不可用：无法访问或检查执行目录”；历史仍可查看。
- 本片只修既有入口和错误链，不创建 ProjectRegistry、EnvironmentRef、Docker/envd、网络配置或新的数据库表。
- 不搬 storage，不全面改 workspace_root 名称，不移除历史类型来假装完成 worktree→沙箱迁移。

### 9.2 实施前正常与失败调用链及本片修正

正常：Shell → tools.background_tasks.task_context → 从 RunScope.identity 取得执行根与 project_id → submit（后台）或 foreground（前台） → _register → require_execution_directory → validate_execution_root → 登记操作 → worker/runner。
实施前缺口：submit/ProcessTaskPort/_register 都允许 execution_root 缺省 → _register 临时构造 Local → project_id 若为空便跳过项目校验 → 操作记录仍可能保存 execution_root=None。
实施前另一个缺口：validate_execution_root 捕获第一次 stat 的 OSError 后报 wrong_project；随后 is_dir 又触发一次 stat，异常可能直接漏出。

目标正常：明确的 Local＋匹配 cwd → 目录与必要身份检查通过 → 冻结操作登记 → 只启动一次。
目标失败：缺身份/错范围/不可读 → 在 ProcessCapture、任务表登记和 worker 创建前抛出对应错误 → 不生成假任务、不启动进程；调用方正常投影工具失败或会话不可用状态。

### 9.3 接口与错误合同

| 情况 | 本片行为 |
|---|---|
| 内部 submit 调用省略 execution_root | 必填关键字缺失，调用契约错误；不得启动进程 |
| 显式传 None/错误类型，或 execution_root.path 与 workspace_root/request.cwd 不一致 | 复用 scope unavailable 的 ToolException 分支；不是 execution_root_unavailable: wrong_project |
| 明确 Local、project_id=None | 合法临时会话；检查目录，不创建 marker，不开放项目 history/memory |
| 有 project_id | 检查已有项目身份；不因 UUID 缺失而自动建身份或重新绑定 |
| 根路径不存在 / 不是目录 | 保留 missing / not_directory |
| 根路径 stat 或身份读取发生权限/其他 OS IO 失败 | execution_root_unavailable: unreadable，记录受控诊断 |
| marker 缺失、格式无效或 UUID 不同 | 保留真实身份失败 wrong_project；不把该语义与访问失败混同 |
| 历史遗留 worktree 类型 | 仍明确拒绝 not_registered；本片不实现 worktree 登记 |
| 无目录普通对话 | validate_execution_root(None) 的现有允许语义保留；文件/进程入口自身拒绝缺环境 |

- ProcessTaskPort、submit、_register 同步要求 execution_root 显式提供；foreground 的 scope 进入同一准入路径，拒绝缺失/None。project_id 可以为空，不能用“必须 UUID”破坏 --no-session。
- 不改变已明确创建 Local 的会话装配逻辑；只删除执行入口根据未知信息推断 Local 的兜底。
- 根路径只读取一次 stat，用结果的文件类型位判断是否为目录，避免 is_dir 第二次 IO；这不宣称消除了所有文件系统竞争。
- marker 检查区分 OSError 和内容/身份错误；不扩大成改写所有存储安全检查。
- 保留外层 code 与现有四原因，新增 unreadable；同步 TypeScript union、UI 文案、HTTP/CLI 错误投影和回归。
- list/output/stop 及关闭已有后台任务不新增目录可用性门槛；本片不改变进程组停止和必要归档故障处理。
