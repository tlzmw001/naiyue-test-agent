# 场景10：子Agent生命周期

日期：2026-10-20。源码基线HEAD `c5ca965`；学习复盘，无产品修改。已讲解；用户独立调试/实现未评估。下列输入、短ID均为示意，不是供应商运行记录。测试只阅读，未在本轮重跑。

## 1. 问题、例子与边界

根模型用通用工具`subagent(agent, task)`委派独立任务；父模型等待本批工具结果齐备后继续。当前是一层、前台、同进程委派，同级是否并行沿场景4的批次规则；不是后台工作服务。

示意父消息：

```python
AIMessage(id='BP', content='', tool_calls=[
    {'name': 'subagent', 'id': 'DA', 'args': {'agent': 'tester', 'task': '检查登录接口测试'}},
    {'name': 'subagent', 'id': 'DB', 'args': {'agent': 'tester', 'task': '检查订单接口测试'}},
])
```

角色是`SubAgentSpec(name, description, system_prompt, tool_names, model_id, max_model_calls)`；注册时校验工具/模型、编译成功后发布`{'spec': spec, 'agent': graph}`。同角色图可共享，每次委派的实例/thread/控制器独立；模型未显式配置则在实例创建时取当前根会话模型。子模型使用`model_default`思考设置。

子首轮消息只有委派任务：

```python
HumanMessage(content='检查登录接口测试', id='subagent-seed:H', additional_kwargs={
    'naiyue_input_source': 'delegated_task',
    'naiyue_reply_id': 'subagent-seed:H',
    'naiyue_input_kind': 'delegated_task',
})
```

它不是新增用户授权。子模型不继承父完整messages/根system_prompt；使用角色提示词、run共享prompt_parts、自己的消息及工具结果。父真实人类输入另作为`_human_review_messages`进入权限审查，不能把模型写的委派task升级为人类同意。

父收到的结果形状为`ToolMessage(tool_call_id='DA', name='subagent', status='success', content='登录测试报告', artifact={agent_path, agent, model_id, status:'completed', usage, truncated})`。子read/bash等结果不整体拼进父messages。独立上下文不构成工作区文件隔离或沙箱；父子可操作同一工作区，副作用不会因子失败回滚。

## 2. 职责与身份

| 所有者 | 职责与状态 |
| --- | --- |
| tools/subagent.py | 角色/输入schema、工具入口、核对执行permit；通过context端口调用应用 |
| SessionSubagentControls | 共享角色/编译图；按session_id路由到拥有者 |
| AgentSessionSubagents / ActiveRun | 本根run的实例dict、唯一driver、RunControl、status/phase/settled；结算与移除 |
| AgentSessionApproval | pending快照、随机审批批次/行ID、future、接纳决定、作废/唤醒 |
| agent_runtime/subagents.py | 建子图、一次执行/恢复、局部失败转换、最终报告投影 |
| LangGraph/checkpointer | 子messages、工具状态、计数、调度与interrupt持久状态；共享backend、独立thread |
| 父SessionExecution/Persistence | 等待拥有的子工作、归档根/子图、必要保存、释放根busy |

| ID | 生产与保存 | 使用/核对 |
| --- | --- | --- |
| S、R0 | 会话与根ActiveRun | session路由、当前根run校验；live审批origin_run_id=R0 |
| BP、DA | 父AIMessage.id即permission batch_id；该消息的tool_call.id | prepared calls与实际id/name/args一致；permit绑定整个subject |
| H | `sha256(json.dumps([S, BP, DA]).encode()).hexdigest()` | `root/tester/H`、`subagent:H`、`subagent-seed:H`；完整哈希不在例中展开 |
| C1→C2 | 实例创建及每次审批恢复uuid4 | 子每执行段run_id；实例/path/thread/driver保持，根R0保持 |
| P1、Q1 | register_live_approval生成UUID，保存在pending | UI提交P1/Q1，服务端只在当前S/R0的实例表中寻找；不是前端决定当前批次 |
| I1 | LangGraph interrupt.id，保存于checkpoint及pending | result与snapshot中断ID相同；resume映射I1到decisions |

当前实例状态示意：`running/execute/False → awaiting_approval/awaiting/False → running/execute/False → completed|failed|stopped/finalize → settled=True`。停止中为`stopping`；无审批直接走终局。status、phase、driver完成、MCP释放与settled是不同事实，不能只看status放行父run。

## 3. 正常调用链

```text
父图准备权限/审批/批次调度
 → ExecutionAuthorizationMiddleware核对call/必要时消费一次grant，产生permit
 → delegate.require_tool_permit
 → SessionSubagentControls.ainvoke_subagent路由
 → AgentSessionSubagents.prepare_subagent_instance
 → create_task(_subagent_steps, context=Context())，登记唯一driver
 → await shield(driver)
 → 子RunObservation/RunServices
 → ainvoke_subagent_step
 → ainvoke_with_message_observation → 子graph.astream（durability='sync'）
 → 子模型—权限/审批—工具—消息回填循环
 → 读取最终子snapshot → _finish_subagent_result
 → 子执行段run_finished → 释放实例MCP/审批/driver，标记settled
 → 父subagent ToolMessage → 本批结果齐备 → 父模型继续
 → 根finish：settle/assert → 必要归档/保存 → release_run → 根run_finished
```

prepare核对父agent_path=root、session相同、prepared batch中DA/name/args与当前调用完全一致，以及permit==permission_binding(context, BP, call)。再锁内核对ActiveRun.run_id=parent_context.run_id、根未停止、角色存在、path未启动。父Ask许可在ExecutionAuthorization中消费一次；工具/prepare只复核permit，不再次消费。

实例存入`ActiveRun.subagent_instances[path]`。该重复检查拒绝当前run中同一父调用再起driver，不是跨重启exactly-once执行承诺。角色工具名单/模型在此固定；权限模式、session_allow等仍按既有权限准备路径读取，父活动工具名单不直接替代角色名单。禁止SubAgentSpec包含subagent，prepare也校验root路径，子RunServices不注入委派端口。

`Context()`创建干净ContextVar环境，避免继承父观察器/控制器；子进入driver后主动安装自己的RunServices。`shield`使父await被取消时不直接打断拥有的子driver；外层catch随后请求子停止并`await_settled(driver)`，再传播原取消。不是脱离父生命周期。

首轮输入是`{'messages':[seed], 'active_reply_id':seed_id}`；config为`{'configurable':{'thread_id':'subagent:H'}, 'max_concurrency':4}`（4为示意/代码回退值，实际取父context）。子图复用压缩/溢出恢复、模型门禁、权限/Auto/HITL、授权、工具批次与停止；不装根Steering/Follow-up消费者。

可选`max_model_calls`接当前LangChain1.4.2的`ModelCallLimitMiddleware(thread_limit=..., exit_behavior='error')`；before_model读计数、after_model递增，thread状态跨审批恢复保留。这是图model轮次计数，不能当作所有摘要/Auto/SDK请求尝试的总预算。

## 4. live审批：同一driver，多次子执行段

假设A产生一项Ask、B仍在模型请求。审批在子图工具批次前中断，当前批次未进入正常工具分发。driver取得result后读同thread的snapshot；register_live_approval先用is_pre_tool_approval证明固定审批节点、唯一task/interrupt、无error/result/substate、最新AI批次与tool_execution完整匹配，再比较result与保存pending及interrupt.id。

锁内复核实例对象确在本会话当前ActiveRun表内、根R0仍活动、无已有approval；若根/子已停止则不创建future，转入带停止控制的恢复以结算。正常时生成P1、Q1，deepcopy prepared，保存I1及future，置awaiting_approval/awaiting，随后才发approval_requested。

当前子执行段C1以interrupted结束，driver继续`await pending.future`，父subagent工具没有返回，根run不释放busy。B可继续；即便A先完成，父仍等整批结果。已有子MCP连接可跨此等待保留。

示意提交：

```python
await app.asubmit_subagent_approval(
    'S', approval_batch_id='P1', origin_run_id='R0',
    decisions=[{'approval_id':'Q1', 'decision':'approve'}],
)
```

服务端在S的锁内检查当前根run恰为R0且未停止，按P1查本run真实instance.pending；检查pending/pending.future/instance.status/control/origin。提交每行必须恰含approval_id/decision，行ID集合完整且唯一；拒绝缺失、多余、重复、额外args、非法remember。按服务端行顺序还原决定。批准的一次grant绑定`{session_id:S,agent_path:'root/tester/H',batch_id:子AI批次,call_id:子调用,tool_name,args,subject}`；不能借Q1批准兄弟的同名工具/同call_id。

pending.status=accepted、保存decisions，必要时添加明确记住的会话规则；锁外future.set_result((ordered,grants))，回执`{'accepted':True,'run_id':'R0'}`。回执不证明已执行。driver醒来释放pending，run_id改C2，以同thread及`Command(resume={I1:{'decisions':[{'type':'approve'}]}})`执行；新RunObservation mode=approval_resume，恢复pending_turn。节点重执行到interrupt取得决定，不重新调用父模型或重新插入子seed；工具执行再核对/消费精确grant。

reject同样恢复官方审批hook，生成未执行的error ToolMessage；子模型可解释拒绝并报告。因而子技术run completed/父报告success不代表每项业务动作都获准或业务成功。

## 5. 结果、必要保存与事件时点

_finish_subagent_result拒绝仍interrupt、run_stopped、末项非AI/仍tool_calls/无非空文本。仅从最终AI提取文本，按配置行数/UTF-8字节截断并附标记；artifact没有完整messages，usage仅在当前所取AI消息全部有usage_metadata时汇总，否则None，不能据此声称完整请求成本。

返回前子snapshot须没有next/interrupts。实际driver返回时，finally先发本执行段run_finished；外层ainvoke_subagent finally随后释放该实例MCP资源、取消未决approval、移除driver并按driver.done标记settled。必要资源清理失败在无主异常时继续抛出，有主异常则诊断而不覆盖它。

根finish先settle_subagent_drivers，再assert检查root归属、终态、settled且无driver/approval才移除实例；随后根必要保存collect_chat_updates从真实父调用推导H，读取根/子checkpoint历史，finish_run事务提交聊天归档与根会话状态。child checkpoint在执行时保存，可读聊天归档在父必要保存收集；事件不是存储源。子没有另建一个独立根SessionState/准入名额。

外层事件仍为`{session_id:S,run_id:R0,sequence:N,event_type,data,source}`。子source为`{agent_path:'root/tester/H',agent_id:H,agent_run_id:C1,parent_run_id:R0,parent_tool_call_id:DA}`。AgentEventPublisher.run_id返回C1，但最终RuntimeEvent.run_id仍是根R0；所有子共享根sequence。for_agent先核对source.parent_run_id=R0。恢复后source.agent_run_id=C2，path/thread不变。

| 事件/阶段 | 已发生 | 尚未证明/消费者 |
| --- | --- | --- |
| 子run_started(mode=message/approval_resume) | 实例/本段观察器已建立 | 未完成模型或工具；前端/CLI标记该子运行 |
| 子模型/消息/工具事件 | 沿当前通用生产点并附source | 语义沿前面场景，tool_started仍可早于实际工具主体 |
| approval_requested(P1,tool_call_ids,items) | 已保存的pre-tool中断已核对，pending/future已登记 | 决定未提交、该批工具未执行；前端/CLI展示来源，API读真实pending |
| 子run_finished(interrupted) | C1已返回图中断 | driver还活着，父还busy；前端映射awaiting_approval |
| 子run_finished(completed/failed/stopped) | 本段结果/报告校验或异常已分类 | 实例MCP清理、父消息提交与根保存尚未全部完成 |
| 父subagent tool_call_finished | 父工具分发已得到报告/错误反馈或异常 | 观察早于后续父模型及根必要保存 |
| 根run_finished(source=None) | 经根正常必要收尾路径 | 与子终局不同；主/次异常及保存不确定沿场景11 |

**当前子控制观察边界（只读源码结论）**：submit_subagent_approval没有调用ControlObserver.accept。C2的RunObservation.bind虽调用submit_approval，但新observer没有审批record；hook的approval_applied也以record存在为前提。因此不能将根审批的control_accepted→control_delivery_started→control_applied保证套到live子审批。当前接纳事实由API回执/pending.future表达，执行由Command/grant驱动。子停止路径还直接发布带source的control_accepted，没有像根一样建立_stop_id记录，不能把它写成完整配对保证。是否统一属于待讨论协议，不在本轮实施，也不凭此宣称已复现执行bug。

前端events.ts优先按source路由agentEvents.ts的agents[path]；interrupted映射awaiting_approval，不结束根view。CLI按path分组；根StreamingMessageProjection忽略带source消息。诊断/用量沿同一来源关联。订阅失败隔离不能删除pending或推动工具；test_failed_notification_does_not_remove_saved_approval_or_execute_tools给出对应确定性断言。

## 6. 失败、停止与重启

| 分支 | 当前处理 |
| --- | --- |
| 子普通叶子工具RuntimeError等 | 子工具error ToolMessage，子模型继续分析；不自动结束整组 |
| 已识别的子模型Timeout等 | 只在异常对象与模型wrapper记录相同时转ToolException；父subagent变error反馈，父可继续 |
| 子model轮次超限、无有效最终文本、子checkpoint IO错误 | 转明确ToolException反馈；checkpoint失败提示副作用不回滚、勿自动重试；不等于系统禁止新的委派 |
| 响应门禁/权限机制错误、其他未转ToolException异常 | subagent反馈边界不吞，继续抛到根失败收尾；不保证兄弟继续 |
| 只停A | 校验R0/path、非finalize/settled，A.control停止；pending未提交则invalidated并唤醒([],None)，已接纳决定保留；停止hook结算，A父反馈error，B/root可继续 |
| 停根/close | 标记根并通知所拥有子control、唤醒等待；父不提前释放，不把停止后的旧模型回答继续当有效执行 |
| 父外部取消 | shield保留driver；请求子停并等待实际工作settle，然后原CancelledError继续传播；同步SDK线程不能靠取消await证明已停止 |
| 进程崩溃重启 | 恢复持久图/归档，不复活driver/future/一次许可；根未确认委派补result_unconfirmed反馈，不重放旧子任务；原子checkpoint/副作用保留可查 |

批准与停止竞争都先在同一会话锁内修改状态，再锁外唤醒；批准先行仍不保证工具一定执行，停止边界会再次检查。stop_one_pending_child测试用事件同步覆盖approve_first两种顺序，无极紧sleep。

## 8. 参考与当前判断

Pi固定73f8de80的examples/extensions/subagent/index.ts是一条扩展示例链：registerTool.execute→runSingleAgent→spawn Pi JSON/print/no-session进程→收stdout message_end等并onUpdate→等待close→报告/details回父工具；parallel用有界workers等完结果。signal触发终止子进程。与本项目同进程独立thread/持久checkpoint不同；本例不是与我们live_child批次/future等价的审批协议，也不能把进程分开等同文件副作用回滚。参考源码已按固定提交重新读取，未执行Pi。

AgentX本地3fcfa0e核对TaskExecutionHandler：processEvent按task依次executeSubTask（当前传null toolProvider）→构造含之前任务结果的prompt→AiServices建Agent→agent.chat→记录任务结果/状态；失败写FAILED并继续计数。handleToolCalls主要构造/保存工具消息，不据命名误称同等子driver。它是该工作流子任务链，本次未证实具有本项目live审批/独立thread合同；不以它推动迁移。Java/LangChain4j不是本项目Python API证据。

保留：独立上下文、共享角色图/独立thread、唯一driver、精确权限、前台批次等待、按范围停止、必要结算与不重放。代价：实例dict同时含身份、状态和task/future，合法组合需跨函数追踪；子执行段终局早于完整实例清理，控制观察与根有差异。可记录待讨论点，但本轮不批准状态重构、事件补齐、后台任务、跨重启自动恢复或新预算。
