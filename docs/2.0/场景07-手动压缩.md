# 场景7：手动压缩

从[十二组场景总览](十二组场景总览.md)整理为独立文件；保留原讲解内容和当时的版本、验证边界。

- **问题**：用户明确要求压缩，目标是维护模型上下文，不是生成一次普通助手回答，也不删除聊天归档。
- **当前路径**：SessionService.acompact准入→SessionExecution.arun(compact=True)→compact_checkpoint；仅允许安全完成checkpoint；摘要后aupdate_state(as_node=model)再END；重读验证；进入共用必要收尾。
- **状态**：执行配额/busy、源checkpoint、上下文替换、摘要事件、聊天归档和操作结果；它复用run寿命，不实际运行正常模型—工具图。
- **失败**：摘要失败与提交不确定分开；ManualCompactionCommitError触发核对/阻断；已开始写入需settle。
- **判断**：独立维护操作及共用准入合理。`arun(compact=True)`的任务类型分支与内部节点模拟降低语义清晰度；只看arun不容易知道可能完全不跑图。
- **目标**：应用显式发起上下文维护操作，复用运行所有者/收尾保护；由图状态维护适配完成基于源版本的替换与确认。摘要生成和提交是两阶段，不能为统一接口掩盖。
- **保护**：审批中禁止压缩、源状态一致、失败不误报成功、展示历史保留。
- **测试入口**：`tests/test_manual_compaction.py::test_replacement_failure_is_not_reported_as_summary_failure`。

## 场景7补充：手动维护、两次写入与失败边界（2026-10-20）

本轮讲解当前实现，不新增改造授权。手动压缩复用独立run的准入、停止、配额、必要保存与交付；不会运行正常Agent模型—工具循环，不自动继续任务，不接纳Steering，不改变待审批决定。

例子（教学代号，非实际请求）：源thread TH1的完成checkpoint P0含`[h0,a0,h1,a1]`，next为空、任务无error/interrupt。用户发起compact操作；摘要旧轮次h0/a0，目标上下文为`[hs,h1,a1]`，聊天归档仍保留原四条。

```text
Web POST /sessions/S1/compact {request_id: Q1}
  → RunDelivery.compact/_launch（会话+请求ID+正文/操作指纹）
  → AsyncApplication.acompact_context
  → SessionService.acompact/_admit(mode=compact)
  → AgentSession.admit_run：核对无manual_review/pending/busy及容量，安装ActiveRun
  → SessionExecution.arun(compact=True)：run_started、必要start、run资源/模型/提示词/工具
  → compact_checkpoint：读取P0并检查完成状态
  → _acompact_messages(force=True, trigger=manual)
  → 候选更新：[RemoveMessage(REMOVE_ALL_MESSAGES), summary, *preserved]
  → 给summary生成UUID hs，expected=[hs,h1,a1]
  → await_settled(commit)：aupdate_state(P0,update,as_node=model)→P1
                         →aupdate_state(P1,None,as_node=END)→P2
  → 从TH1重读最新状态，验证完成状态及messages IDs == expected
  → MessageStateObserver/ContextOperationObserver报告可读结果
  → 共用_afinish_run：必要保存、条件释放busy、run_finished
```

Q1是客户端请求身份，R是服务端新run身份，TH1沿用原图thread，P0/P1/P2是框架checkpoint身份，hs由compact_checkpoint在写入前uuid4生成。operation_id由ContextOperationObserver生成，用于压缩事件配对；手动路径没有开始正常model turn，因此该压缩的model_call_id通常为None。

Web的有界内存receipts以`(session_id,request_id)`查找，并比较包含`_operation=compact`的规范化请求指纹；同Q1同正文返回原run回执，复用Q1发普通消息等不同操作返回冲突。不由前端自报checkpoint决定修改目标；Web回执不承诺跨重启可靠幂等。

当前一致性不是CAS：compact_checkpoint只先检查P0的next/tasks及checkpoint_id；写入时使用已读到的snapshot.config，随后重读最新状态检查结果。没有在摘要后重新读取并比较“最新checkpoint_id仍等于P0”的独立步骤。正常应用并发由独占ActiveRun、准入锁及持久运行保护控制，不能把传入源checkpoint解释成框架自动比较最新版本。

`aupdate_state(as_node=model)`使用模型节点对应的状态写入/路由规则，不调用模型函数；`None/as_node=END`在本机LangGraph1.2.12中清理待执行任务并保存完成状态，不是再跑一轮图。两次更新不是单一原子事务；第二次失败时第一步可能已经提交，不能笼统声称原checkpoint仍未变化。最终检查为：saved.next为空，tasks无error/interrupt，且消息ID列表与expected逐项相等；不逐字复核正文。生成摘要与预算/工具配对验证由共用算法在写入前完成。

manual的force=True绕过自动触发阈值，但不会任意丢弃内容：没有完整旧轮次时可skipped；手动候选只接受HumanMessage轮次边界，不能为了塞入小模型而切开最新用户轮次。它不属于overflow恢复，压缩完也不重试原任务。

| 分支 | 当前返回/异常及后果 |
|---|---|
| 空会话/无旧轮次 | 必要时以END初始化空checkpoint，随后skipped；不调用摘要模型、不新增聊天消息 |
| 共用算法抛ContextCompactionError | 策略已报告failed；适配层返回compaction_status=failed，未开始替换，允许安全继续 |
| 正常生成并确认 | compaction_status=applied；维护run通常completed，原任务不续跑 |
| 替换写入/END更新/重读确认失败 | ManualCompactionCommitError上抛；SessionExecution._on_failure(require_review=True)标manual_review_required，run failed，阻止后续运行 |
| 摘要期间停止、写前看到停止 | 返回run_stopped；原消息未替换；原控制合同与必要保存保持 |
| 已开始commit后停止/外部取消 | await_settled先结算已开始IO；不承诺回滚。用户停止可在完成替换后被报告；外部取消仍传播并按原核对合同处理 |
| 必要最终保存失败 | 作为必要失败报告并阻断；不得因compaction_finished(applied)已发而声称整个操作保存成功 |

压缩失败与维护run失败是两层结果：摘要空/无效等已知策略失败，可能是compaction_finished failed加run_finished completed；其含义是维护操作已正常处理“本次未能压缩”。写入不确定则是run failed及manual_review_required。Web使用manual的compaction_finished投影compaction_result，并在维护run结束时显示结果；202仅确认已有run回执，不证明压缩成功。

健康路径事件为run_started(compact)→compaction_started(manual)→可选摘要模型invocation(purpose=summary)→图写入/确认→message及compaction_finished(applied)→必要保存→run_finished。当前产品仍使用model_invocation_*；Spec118单套model_call名称尚未实施。没有普通model_call/turn_started，因为未经过正常图模型wrapper。applied先于应用最终保存；观察器只报告已读到的状态，不能成为写入前提。摘要失败为failed，无安全前缀为skipped；提交不确认时不能发布applied。

代表性确定性测试（本轮仅阅读）：

- `test_manual_compaction_summarizes_once_saves_and_is_idempotent`：临时Web/SQLite和StreamingToolModel；先生成两轮历史，再消费第三个fake回复作摘要。断言applied、模型上下文变成摘要+最近轮次、聊天内容不变、同请求返回同run且不再调用模型；重开后上下文/归档仍分别保持。不能证明真实摘要质量或跨进程幂等。
- `test_replacement_failure_is_not_reported_as_summary_failure[1/2]`：仅替换图的aupdate_state，在第一或第二次写入注入OSError；断言没有applied、run failed、错误类型ManualCompactionCommitError、manual_review_required且can_run=False。不把提交故障降为普通摘要失败。

固定参考：Pi73f8de80的AgentSession.compact先abort当前操作，准备/摘要后appendCompaction、刷新正式上下文并报告compaction_end(willRetry=false)，同样不自动继续；我们明确要求会话空闲、审批已处理，并复用run门禁。其append+projection不等同Python图checkpoint写法。AgentX3fcfa0e的ContextProcessor→TokenDomainService→SummarizeTokenOverflowStrategy先产出retainedMessages/summary，再更新ContextEntity的activeMessages/summary；没有据此宣称具有本项目手动维护、工具配对或checkpoint确认合同。
