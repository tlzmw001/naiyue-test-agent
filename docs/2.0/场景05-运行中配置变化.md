> 版本提示（2026-10-20整理）：正文保留本轮讲解时点的基线。并行开发已开始Spec118模型事件迁移；文中的旧32类目录、两套模型事件或“Spec118未实施”属于当时状态。当前事件名称及实际消费者见[事件功能总结](总结01-事件的实际功能.md)，开发验收以对应Spec/交接为准。

日期：2026-10-20。阶段：当前源码走读与设计讨论，无产品修改。核对本机 LangChain 1.4.2 / LangGraph 1.2.12；参考 Pi 73f8de80、DeepSeek Harness 687f282e，均为固定版本。下述 S1/R1/C1/A1/T1 是教学缩写，不是真实模型运行。

## 1. 本节的问题与地图

会话设置已保存、某次模型请求已准备、某批工具已获决定，是三个不同事实。配置不能笼统地说成“立即生效”或“下一轮生效”，需要指出具体读取边界。

```text
SessionState：当前选中的模型/思考档位/活动工具/权限模式
  ├→ run 准备：项目指令、Skills 索引、资源读取范围 → ActiveRun
  ├→ 工具视图准备：工具名 → 原 ToolSpec 元组 + 图中 tool_names
  ├→ 模型 wrapper：选模型/思考，装配提示词与工具 → ModelRequest
  └→ 响应后的权限准备：模式/会话规则 → tool_execution 批次
       → Auto / 人工审批 → 原批次授权/工具执行 → 下一模型请求
```

本节只分析配置的所有者、读取时点、身份和失败边界。压缩算法、停止完整收尾和子生命周期分别留在相应场景。

## 2. 贯穿例子

用户要求读取工作区外的接口契约，再把报告保存到指定的外部目录。假定文件有效、无显式 Deny，当前模式为 Auto 且已经配置审查模型。

```python
# SessionState 的相关字段投影
{'model_id': 'A', 'thinking_level': 'model_default',
 'active_tool_names': ('read', 'write'), 'permission_mode': 'Auto'}

# A 的第一份响应；路径和内容仅为示意
AIMessage(id='A1', content='', tool_calls=[{
    'id': 'T1', 'name': 'read', 'args': {'path': '/shared/api-contract.md'}
}])

# prepare_local_batch 产出的关键字段，subject 等内容省略
{'tool_names': ['read', 'write'], 'batch_id': 'A1', 'mode': 'Auto',
 'session_allow': [], 'calls': [{
     'id': 'T1', 'name': 'read', 'args': {'path': '/shared/api-contract.md'},
     'validation': 'valid', 'decision': 'ask', 'source': 'default', 'subject': '...'
 }]}
```

Auto 等待期间，用户把模型改为 B、活动工具改为 write、模式改为 NoAsk，并在磁盘修改项目指令。假定 Auto 对 T1 返回 allow：T1 仍按旧工具视图和本批 Auto 决定执行；下一次根模型请求使用 B 和 write，但仍装配本 run 冻结的项目指令。若 B 提议向外部路径 write，其默认 ask 在新的 NoAsk 批次变为 deny，返回未执行 ToolMessage。这里 NoAsk 只拒绝需要 ask 的调用，不拒绝所有工具。

这个组合例子依据多个既有合同推演，并不是一条已执行的组合测试。配置按钮也不是一个跨四项设置的原子事务。

## 3. 生效边界

| 内容 | 所有者与读取点 | 运行中变化后的行为 |
|---|---|---|
| 根 model_id / thinking_level | SessionState；模型 wrapper 调用 resolve_model | 之后的模型选择点读取新值；在途请求保留已选模型 |
| 活动工具 | SessionState；ToolSetMiddleware 准备视图 | 首视图在 before_agent 准备，首个 before_model 跳过刷新；后续 before_model 刷新 |
| 已发请求的工具 | context 原 ToolSpec 元组与图 tool_names | 修改会话选择不改写当前请求/批次；未活动工具回填 error 且不执行 |
| 项目指令 | prepare_run_resources → ActiveRun | 本 run 不重读；下一 run（含根审批恢复）重新准备 |
| Skills 索引 / 资源根 | 同上 | run 内冻结；Read 读取正文时仍读取当时文件内容 |
| 权限模式 / session_allow | 响应后 prepare_local_batch 读取 | 准备批次之前改，可能影响当前响应的批次；准备后改，不重算原批次 |
| 待人工审批的旧批次 | checkpoint tool_execution 与应用 pending | 按原调用/参数/决定恢复；新设置供后续请求和新批次读取 |
| Auto fast/detailed 模型 | AutoPermissionReviewer 构造时从 catalog 取得 | 切换根主模型不替换审查模型 |
| 基础 system_prompt、模型目录、静态 Allow/Deny 与工具预算 | 应用装配的对象/设置 | 当前会话 setter 不重载 models.json/settings.toml 或基础提示词 |
| 子模型/工具 | 创建实例时保存 model_id、角色 tool_names | 根后续切换不改既有子实例；权限仍经会话模式在各子批次准备时读取 |

ToolSpec 元组保留原对象，不是整棵 BaseTool/Pydantic 对象树的深度不可变快照。注册器拒绝重名注册；JSON Schema 合同另有变更检查。不能把正常活动集合切换的保证扩大为任意原地修改注册对象也安全。

## 4. 按时间追主链

### 4.1 修改会话选择

WebService → AsyncApplication.aselect_model/aset_active_tools/aset_permission_mode → run_blocking → AgentSession setter。

setter 先验证模型、工具名或模式；同类设置使用选择锁串行化；有持久化时先写 SessionStorage，成功后才在状态锁内改 SessionState。保存期间读取仍可见旧值；保存失败抛出且内存保持原值。设置入口不因根 run busy 就一律拒绝；Web 恢复受限状态另有门禁。

切模型同时重置 thinking_level=model_default。select_thinking(model_id, level) 先校验能力，再核对提交的 model_id 等于会话当前模型，避免把旧模型档位误用到新模型。with_thinking 返回模型浅副本，复用客户端，不改共享默认参数。

### 4.2 准备 run 与模型请求

SessionExecution._prepare_resources → prepare_run_resources → freeze_run_resources：读取 AGENTS.md（优先）或 CLAUDE.md、发现 Skills，把 prompt_parts/project_instructions 放入当前 ActiveRun。

ToolSetMiddleware.prepare_tool_view：读取会话活动名，registry.select 返回原 ToolSpec 元组，放入 context['_naiyue_tool_view']；图中仅保存 tool_execution.tool_names。首视图供初始压缩及首请求使用，后续请求 before_model 重取活动集合。

模型 wrapper 的 _prepare：SessionPort → SessionService → AgentSession.resolve_model，生成 model_call_id，取得本次模型对象。工具 wrapper 的 _model_request 再用同一工具视图和 run 内 prompt_parts 装配请求。实际顺序为：

```text
select_model → toolset → overflow recovery → ModelInput
  → request observation → 框架 _get_bound_model / bind_tools → model.ainvoke
```

LangChain amodel_node 创建 ModelRequest；项目通过 request.override 返回修改后的请求对象。ModelInput 转换发往供应商的消息，不把转换副本作为新消息历史提交。选模型、装配请求、观察通知和图提交是不同阶段。

### 4.3 响应后准备权限批次

PermissionMiddleware.prepare_local_batch 先找最后 AIMessage。如果保存批次的 batch_id 等于 AIMessage.id 且已经有 calls，返回 None，不用当前模式重审旧批次。

新批次读取 resolve_permission_context 得到 mode/session_allow/project_instructions，验证模式，准备真实目标、静态规则和默认决定，再把 mode/calls 等放进批次。Auto 的异步等待继续使用这一批数据；中途 setter 改 SessionState 不改本地 batch。审查完成后返回 tool_execution 更新，由图提交。

例中配置切换发生在该步骤读取之后，因此旧批仍 Auto。如果切换发生在模型等待、尚未准备权限之前，同一份 A1 的批次可以读到 NoAsk。权限快照不等同模型请求起点快照。

### 4.4 执行及下一请求

batch_tool_specs 优先用与保存 tool_names 同序相等的 context 视图；恢复等情况下没有匹配视图则 registry.select 保存名，不读取会话最新活动集合。

ExecutionAuthorizationMiddleware 按 tool_call_id 找原 call，再比较 name/args；ask 消费匹配的一次许可，allow 构造本次 permit，deny 返回未执行消息。工具再复核真实目标。工具结果入图后，下次 before_model 才更新工具视图，模型 wrapper 才重新选模型。

原工具结果仍保留 ToolMessage.tool_call_id=T1；切模型不清历史，不另建 thread，不需要重新编译图。

## 5. 失败、暂停与身份

- 无效模型、重复/未知工具名、未配置 Auto、不可用思考档位：验证失败，不写入新选择。
- 配置保存失败：原异常传播，内存不先改成新值；不自动把旁边正在执行的 run 标失败。
- 下一 run 读取无效项目指令：加载失败，在模型调用前退出；不静默回退到低优先级文件，按既有必要收尾释放。
- 模型返回本请求不可用的工具：ToolSetMiddleware 返回配对 error ToolMessage，不执行；模型可继续处理反馈。
- 新 NoAsk 批次的 ask：转 deny，返回 not_executed；无需因此将整 run 标 failed。
- 人工审批期间关工具/改模式：恢复旧批不重审，批准仍只能用于原 session/agent_path/batch/call/name/args/subject；后续请求采用新选择。关闭活动工具不是撤销旧批的操作。
- 停止与外部取消：仍经场景2合同处理；修改配置本身不发停止，也不回滚已开始工具。

关联键：session_id 路由配置；run_id 限定本次资源/执行；model_call_id 关联一次逻辑模型调用；AIMessage.id 作 batch_id；tool_call_id 关联准备、执行和 ToolMessage。当前没有统一 config_revision，也没有用单个版本号同时比较四类配置。选择锁及模型档位归属检查不能等同全配置原子快照。

## 6. 事件时点

设置 setter 不发布 control_accepted，也没有通用 config_changed 事件；成功 HTTP/API 返回表示设置操作成功，不证明在途模型请求已经改用它。

| 事件 | 已发生 | 尚未证明/消费者 |
|---|---|---|
| model_call_started(C1, A) | _prepare 已选定 A 并生成 C1 | 尚未发供应商请求；CLI/诊断使用，不调度配置 |
| model_context_snapshot(C1) | 已组装并适配当前请求，读取该请求模型/工具/提示词估算 | running 不是接受响应；Web 上下文投影使用 |
| model_invocation_started | 框架开始实际模型调用 | 与逻辑调用、HTTP 重试分开；用量/诊断消费 |
| model_call_finished(C1, A, accepted) | 响应通过项目门禁 | 权限/工具尚未全部完成；不改会话选择 |
| tool_call_started/finished(T1) | 旧批分发/结果事实，时点沿用场景4 | started 不证明主体开始，finished 不证明图已合入 |
| 后续 model_call_started(C2, B) | 新选择点取得 B | 才是该次请求使用 B 的观察依据 |

上下文诊断中的 schema SHA256 用于描述定义，不是审批许可；事件 sequence 只排序。页面当前选择 B 与尚未完成的 C1/A 请求可以同时成立。

## 7. 设计评价与参考

保留项：共享图、会话选择隔离、请求工具视图、批次权限决定、run 内项目指令/索引、先保存再改内存、思考参数副本与审批绑定。它们有明确消费者与当前行为合同。

待讨论项：多个设置独立读取，没有统一请求配置版本；初始压缩解析模型与真正请求选模型分在不同时点，摘要等待期间切模型可能让两步读取不同模型。该事实需要场景6结合预算讨论，不在未复现时报告为缺陷，也不自动新增统一快照类/热重载/撤权系统。

2026-10-20用户确认的设计方向（未实施）：把是否需要压缩的决策纳入每次正常模型请求的准备阶段，按本次实际准备发送的模型、系统提示词、工具定义和消息判断预算；满足触发条件时先尝试安全压缩、复核后再请求模型。保留供应商明确拒绝输入后的强制压缩与当前请求单次重试，不以被拒绝后的恢复代替主动预算处理。请求准备收拢的具体接线，以及摘要等待期间切模型的生效规则，尚未定案。

该方向现进入[Spec118讨论草案](../specs/118-request-preparation-and-context-budget.md)：首请求与后续统一，压缩后仅按本地发送预算复核；建议turn_started覆盖请求准备。用户确认不新增超大单条输入通用兜底，并在核对Pi后确定只保留框架callback的一套模型执行事件、对外使用model_call_*名称。上述第6节仍描述当前双组源码；单套目标及消费者迁移见Spec第6节，尚未实施。

输入边界已核对：前端useContextView只传api/session/run，不接输入框draft；空闲预览估算已有图消息，运行时快照估算request.messages。未提交草稿不计入；已提交并进入本次请求的HumanMessage计入；仍在队列且未被选入当前请求的补充输入不提前计入。新的主动检查应在本次消息接入之后，不能直接拿页面预览数值作为执行依据。无法安全压缩、摘要失败或估算不可用等分支须在后续Spec明确，不能把达到软阈值表述为保证一定能生成有效摘要。

- [Pi AgentSession 固定版本](https://github.com/earendil-works/pi/blob/73f8de80bc87021375f8b525292ac07492253002/packages/coding-agent/src/core/agent-session.ts)：_installAgentNextTurnRefresh 刷新提示词/活动工具/模型，_installAgentRequestProjection 从当前 agent.state 和会话投影准备请求；[核心 loop](https://github.com/earendil-works/pi/blob/73f8de80bc87021375f8b525292ac07492253002/packages/agent/src/agent-loop.ts)接收 prepareNextTurn/prepareRequest 结果后才调用 streamAssistantResponse。边界更显式，也有会话投影与工具变化声明的成本。
- [DSH 固定版本](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/agent-loop/src/agent.ts)：step → prepareRequest（agent/request waterfall 与 prepareCall）→ buildRequest → stream；记录 request/header/context，冻结请求消息/工具描述。这里 waterfall 有返回值并参与执行，不等同本项目普通观察事件；日志、投影和配置挂载也增加协议成本。不据此推断它与本项目具有相同热切换/撤权合同。
- AgentX 本机 3fcfa0e 旁查：TaskExecutionHandler.processEvent → executeSubTask → LLMServiceFactory.getStrandClient（provider/model 来自 ChatContext）→ AiServices.builder.chatModel → agent.chat。该链说明配置落到客户端的位置，不能证明模型内部每轮工具循环都重新读配置。

以上对照未运行参考产品/模型；仅据实际链路评价职责表达，不批准架构改造。
