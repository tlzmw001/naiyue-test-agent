# 总结二：十二组复盘后的学习路线取舍

日期：2026-10-20。依据[原学习路线](../1.0/learning-roadmap.md)与[十二组场景](十二组场景总览.md)覆盖情况。本文是供用户取舍的建议，尚未据此删章、删除历史笔记或改变课程安排。已讲解、自述理解、独立调试/实现及功能验证分别记录。

## 1. 判断依据

这轮已串起任务如何运行、受到控制、暂停、恢复、保存和交付。后续应减少重复画同一张流程图，把精力放到尚未展开的实现细节、数据实物与实际任务。

机制已讲过，足以减少重复讲授；不足以证明用户能独立实现。下一轮不为评估能力而重学前六章，不把助手实现/测试通过记为用户能力。遇到具体困惑，引用现有地图再定位源码。

## 3. 第七章怎样收紧

1. **上下文组成与来源**：围绕“读取项目说明并测试接口”，展示最终请求中的系统提示、项目指令、适用Skills、历史消息、新输入、工具schema和请求配置。说明哪些进消息、哪些是调用参数、哪些仍只是UI草稿。场景5的配置时点不能替代每份上下文的拼装合同。
2. **窗口、预算和估算**：代入具体数字，手算输入估算、输出预留、可发送范围；区分当前上下文、将发送请求、未提交输入框文字和累计用量，说明估算为何不等于计费。Spec118正并行实现，以届时源码和验收为准，不把旧准备路径当目标，也不提前宣布新路径已完成。
3. **安全切点、摘要与校验**：选具体Human/AI/tool_calls/ToolMessage序列，走保留区/可压缩区，解释为何不能拆工具配对、摘要怎样验证及替换。失败/停止/恢复生命周期引用场景6/7，只补算法的新职责。
4. **可选定点调试**：前三项若已覆盖则合并；需要时挑一个预算或安全切点的既有确定性测试。不默认加探针、强制复写或一次列完所有参数。

## 4. 第八章哪些能省，哪些不能省

可以引用场景8/9/11/12，不再重复：恢复分类和阶段、重新生成候选thread、必要保存/异常优先级、busy释放、观察不能代替归档。

仍保留两个看实物的专项：

1. **一份会话在数据库中长什么样**：session行、thread/checkpoint、聊天归档、revision和恢复marker的关联；一次保存/激活事务原子地改什么，哪些图写入在另一边界。使用临时测试库或已有材料，不操作真实用户会话库。
2. **CLI怎样连接异步应用**：输入、工作线程、事件循环桥、display、停止/追加输入及命令返回如何衔接。事件用途已讲，不代表CLI输入循环已完整理解。

推荐第一项接到上下文保存/实际任务，第二项接到Web入口对照或实践，第8章可不再独立成大章。若更喜欢完整章节，也可保留标题只做这两项专项；两种安排不重复上课。取舍由用户决定。

## 5. 第九、十章为什么保留

第九章仍要理解React的state、ref、effect清理、闭包值、请求取消和过期响应隔离，以及useConversation如何组织提交和订阅。场景12解释SSE为何如此交付，不等于已经能安全修改切会话、重连、消息覆盖和审批交互。

建议顺序：必要TS/React结合实际组件 → 会话选择/提交及正式API → 查询/订阅合并和过期响应隔离 → 聊天/工具/审批/子面板的一条交互链。SSE底层、重放游标、根子身份引用场景12/10，疑问再展开。CSS、图标和构建配置不作默认主课，不为教学改IDE或页面。

第十章承担从听懂系统走向能用它工作、定位问题、准确描述个人参与。用一个真实HTTP/RPC测试任务串起需求/预期、提示词/Skill/工具、执行轨迹/产物、故障定位；确定性测试、真实模型集成、业务评测分别给证据。实际修改或外部操作届时按授权执行，本次仅整理学习记录。

- 无明确问题的参考项目全量迁移、跨重启可靠Inbox、新事件调度系统及未授权架构候选，不变成必修或实现任务。
