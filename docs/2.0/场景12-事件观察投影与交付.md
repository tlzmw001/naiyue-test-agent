## 1. 问题、例子与权威状态

用户要求读取登录失败日志并说明原因。主模型先调用read，随后流式生成“登录失败原因是配置缺失。”；浏览器中途断线，服务端继续运行，恢复连接后显示当前结果，不能重新执行read/模型。

真实数据结构示意：

```python
# 图执行适配接收LangGraph v2 part；不是应用RuntimeEvent
{'type': 'messages', 'ns': (), 'data': (
    AIMessageChunk(id='A1', content='登录失败'),
    {'langgraph_node': 'model', 'langgraph_step': 8, ...},
)}
```

```json
{
  "version": 1, "event_type": "message_delta",
  "session_id": "S", "run_id": "R1", "sequence": 17,
  "timestamp": "示意时间", "source": null,
  "data": {"message_id": "A1", "text": "登录失败", "index": 1, "reply_id": "G1"}
}
```

第二个是Web wire结构，version=1由序列化层加入。投影行形如`{id:'A1',type:'ai',content:'登录失败',provisional:true,state:'draft',delta_index:1,run_id:'R1'}`。完整消息到达后同ID替换，而非再追加一条消息。

| 数据 | 所有者/地位 |
| --- | --- |
| 图messages、interrupt、执行返回/异常 | LangGraph及执行适配；决定业务继续的事实 |
| RuntimeEvent / publisher sequence | 当前run内的事实通知；不承诺跨重启可靠投递 |
| MessageStateObserver hashes/IDs | 去重与识别消息修订，不是另一份持久状态 |
| DeliveredRun projection / replay deque | 当前进程内显示状态与有界重放缓存；不是执行入口/聊天真相源 |
| SSE帧、前端RunView/MessageRow | 传输与可重建显示；草稿不等于已提交/已保存 |
| checkpoint及聊天归档 | 真实图保存与必要归档，沿场景11；显示恢复可据此校准 |

## 2. 主链与边界

```text
前端POST /sessions/S/runs {request_id:Q,text,expected_conversation_revision}
 → WebService.start → RunDelivery._launch
     先订阅job.observe，再创建_produce task
 → application.arun → 准入R1 → runtime执行适配
 → graph.astream执行模型/工具循环
     ├─ messages chunks → message_delta / message_reasoning_delta（草稿）
     ├─ values完整状态 → MessageStateObserver → completed/revised/context变化
     └─ updates interrupt / custom progress → 对应状态与观察
 → RunEventPublisher同步有序通知
 → DeliveredRun.observe：先更新显示投影，再保留可重放帧
 → GET /runs/R1 取得当前有界视图
 → GET /runs/R1/events?after=N → SSE runtime帧
 → decodeSSE → validateEvent → applyEvent → React/history合并显示

图checkpoint → 场景11必要归档 → session/history/detail读取校准
断线：只解除显示订阅；producer不随SSE iterator结束而取消
```

控制方向相反：用户按钮/输入→正式POST controls或审批API→应用拥有者处理→结果通知。不能由前端投影自行运行工具，普通观察事件也不负责图下一跳。

## 3. astream就是这一次执行

ainvoke_with_message_observation先建_StreamState；可用checkpointer时先读baseline并seed hashes，不把旧历史重发。正常调用`agent.astream(input,context,config,stream_mode=['messages','updates','values','custom'],version='v2',output_keys=agent.output_channels,...)`，async for不断消费即驱动同一次图执行；最后返回latest values及收集的interrupt，不再额外ainvoke。

_StreamState.part忽略非空ns（子实例已独立驱动并附source）；values保存latest并观察完整messages，updates收集中断，messages投影分片，custom接工具进度。输入context/config沿当前session/run/thread，不由浏览器指定任意checkpoint驱动。

基线读取失败时，特定子checkpoint失败必须抛出；普通观察基线故障报告unavailable、禁用turn细节，然后在尚未开始astream前只执行一次原ainvoke。自定义/不兼容图调用接口也尊重原ainvoke。astream执行中抛错则保留原异常，不再调用ainvoke重跑；可能读当前checkpoint发布recovery_view观察，读取失败只诊断，不替代主异常。

执行适配必须收集result/interrupt，因此不能整段作为可丢弃观察删除。call_observation中的选模/响应门禁，以及tool_execution.observation中的工具截断/归属门禁，同样是必要执行职责；只有对应通知/投影才允许降级。

## 4. 草稿、完整消息与事件含义

delta只取model节点且排除summary/permission-review tag；正文和可见reasoning各有独立index。用(namespace,step)保存稳定stream message ID锚点，处理Responses空首chunk带最终响应ID、后续chunk带框架ID的情况。stream.part收到分片后立即投影，可能早于完整响应门禁接受。

MessageStateObserver保存ID→snapshot SHA256与有序ID集合；baseline只登记不发旧消息。后续完整状态的新ID发message_completed，同ID内容投影hash变化发message_revised。hash来自实际snapshot JSON；Web将content blocks变纯文本副本时重算hash，不修改原领域事件。前端按ID/顺序处理，当前没有逐项回算snapshot_sha256校验，不能讲成浏览器依靠哈希证明保存完成。

| 事件 | 发布时点/关键字段 | 当前消费者与限制 |
| --- | --- | --- |
| message_delta / message_reasoning_delta | 模型chunk已产生；message_id,text,index,reply_id | 服务端/前端草稿累积；未证明完整响应获准、图提交或保存 |
| message_completed | 实际完整图消息首次被观察到；message_id/type,visibility,snapshot_json/hash/bytes | 完整快照替换同ID草稿；适用于human/ai/tool等，不等于整run结束或应用归档完成 |
| message_revised | 同ID投影发生变化 | 替换修订，不追加第二份同ID消息 |
| message_snapshot_unavailable | 不能可靠读取/投影相应消息 | 标记incomplete并诊断，不伪造正文，不据此重跑 |
| context_messages_changed | 观察到上下文ID移除/变化 | 模型上下文变化，不删用户聊天展示原文 |
| tool_* / control_* / turn_* / model_* | 沿前面场景各自真实时点，附同run顺序 | 不是一律可选执行代码；当前两套模型事件语义沿旧源码，118尚未迁移 |
| run_finished | 沿场景11必要收尾后的终局通知 | 剩余provisional行标unconfirmed，不能把未确认半截文字升级为成功正文 |

visibility=graph_values表示从图状态观察，recovery_view表示异常后回读；都不能替代应用必要保存确认。一个AI消息complete也可能带tool_calls，后面仍有工具和下一次模型。

## 5. 发布与Web任务登记

RunEventPublisher核对payload精确类型，锁内生成run级sequence并入队，顺序同步调用handlers。重入发布先入队，不插到当前事件其他listener前面。普通Exception记录安全类型并在当前publisher停用该handler，其他handler继续；不能返回awaitable/非None。observe会标记故障observer并返回fallback，emit_event保护payload构造与publish；payload工厂在调用点立即求值，不是延迟执行。BaseException控制不当作普通观察异常吞掉。同步小回调仍有耗时，异常隔离不等于零耗时。

Service为run创建publisher时取订阅快照，所以_launch在实际生产者启动前订阅job.observe，避免遗漏开头。_launch内创建register闭包，但首次真实事件到observe时才取得实际R1并将_ready排到event loop；_ready调用register/on_started并设置started future，独立_registered保证排队回调与快速结束不重复登记。通常首事件run_started；若首个实际事件更晚，仍取它的真实run_id并标incomplete。

Web不预造运行ID：Q是前端request_id（正常路径也用作输入HumanMessage.id），R1由应用实际准入产生。HTTP等待者await shield(job.started)，取消这个等待不取消producer或共享future。所有通知缺失时没有R1可确认；producer结束后返回run_observation_unavailable，不编造run号。执行可能已完成并保存，同Q保持未确认回执，不自动重新执行。

_cached以(scope,request_id)定位，比较包含操作类型的body指纹；同Q/同内容返回已有receipt或等待同一pending job，不同内容冲突。该普通消息回执是当前进程有限窗口，不是持久Inbox或跨重启恰好一次保证；重新生成的持久动作账本沿场景9独立处理。

DeliveredRun.observe先检查S/R1/sequence，更新projection和工具/子状态，再保留wire帧。缓存同时受条数、UTF-8序列化字节数限制；单帧还受max_frame_bytes限制。先投影后淘汰使事件缓存可空而当前视图仍完整。超大帧省略/旧帧淘汰更新_evicted_through；缺真实序号或投影失败则incomplete=True，两者不同。view是有界最近窗口，允许预览/详情入口，过大无法投影则明确报错，不改执行结果。

producer完成/失败走finally取消订阅、置job.done、移除active_by_session并唤醒流。job.status是运行结果投影，done是Web生产者已退出，incomplete是观察完整性；这三项不能合成同一个成功位。终局通知缺失但应用正常返回，可用真实result补显示并标incomplete；有异常且缺终局则unconfirmed。缓存和job均非跨重启恢复源。

## 6. ID、前端投影与断线

| 标识 | 本例与实际校验 |
| --- | --- |
| session_id/run_id | S/R1；job与subscribeRun都拒绝另一会话/run；source子run另沿场景10 |
| event.sequence | 根/子共享R1的递增序号；after=N只请求>N，<=last忽略，跳号报gap |
| message_id | A1；用它定位并替换消息，不用正文相等判断 |
| delta index | A1正文1、2…；reasoning另计，要求下一项连续，不能当全局sequence |
| reply_id | G1；标记任务归属，不代替运行或消息身份 |
| archive sequence/revision | 归档正文/分页定位与修订，不等于事件序号；conversation_revision防重新生成旧分支混入 |

SSE帧形如`event: runtime\nid: 17\ndata: {version:1,...,sequence:17,...}\n\n`。服务端after预检或流中检查发现after>last、incomplete、after<_evicted_through时要求resync；建立连接前返回HTTP409，连接内发resync_required帧再结束。当前前端使用fetch手动decode，不靠浏览器EventSource自动重发Last-Event-ID；frame.id是帧标识，业务连续性实际检查data.sequence。

decodeSSE用流式UTF-8 decoder缓冲到空行，不把一次网络read当一个模型token/完整帧；不完整尾帧报stream_truncated。validateEvent检查version、sequence、S/R/source等，applyEvent检查外层顺序：重复旧帧忽略、跳号抛错；带source路由agents[path]，所有帧仍推进公共游标。没有专门UI处理的事件也推进last_sequence，不能先按类型过滤导致合法帧被误判丢失。

message_delta按A1/index累积草稿，完整snapshot按A1替换为provisional=False/state=complete。run_finished只把剩余草稿标unconfirmed。history.merge按消息身份和修订合并归档/live，不用旧预览覆盖已有完整正文；超大草稿预览标content_unavailable，不能把后续delta拼到缺中段的正文上。

subscribeRun首轮取得RunView并检查S/R，done则返回；否则events(after=view.last_sequence)。例：前端停在17，掉线期间服务端到31。重试先调用synchronize（实际refreshSession prepare，补录/读取历史，不执行图），再GET /runs/R1得当前窗口/last_sequence=31，再订阅after=31；快照与接流之间的新32+由缓存补交。

因此实际前端重连优先用新快照，服务端after重放补连接间隙，不承诺重放断线期间每个旧token。重试有界退避；授权/身份/不存在等永久错误不自动重试。只调用读/prepare同步，不调用start/approve/control。切会话abort当前fetch/等待并检查当前选择，防晚到数据画到其他会话，不代表请求停止Agent。

## 7. 正常与失败分支

| 分支 | 当前结果 |
| --- | --- |
| 正常分片→完整图消息→必要保存→终局 | 草稿校准，最终查询确认job状态，刷新会话/历史 |
| 收到半截文字后模型失败/停止 | 保留provisional、标unconfirmed，不作为保存的成功正文；原异常/停止沿原合同 |
| 旧帧被淘汰/超帧 | snapshot可能仍完整，游标不合法要求重同步；不停止producer |
| 真正观察缺失/投影失败 | 标incomplete；已保存历史可校准，缺失token不能凭空恢复；不能保证新view清掉诊断或一定重新建立流 |
| 完成且done后live仍有旧草稿 | session历史合并可用同ID已保存正文校准；保留incomplete诊断 |
| running/failed/stopped/interrupted或未done | 不用旧归档假装新草稿已完成，避免同ID旧消息误确认新半截输出 |
| SSE断线/切会话 | 解除该显示读取，producer继续；真正停止走正式控制入口 |
| 全通知缺失 | 执行/保存独立完成，无法确认run交付回执则报unavailable，不伪造/重放 |

归档校准在WebService.session的history_window执行：仅live.done且status=completed允许restore_saved_drafts；run GET本身仍是独立显示快照。完整可读正文来自必要归档/按需分块读取，原子checkpoint/应用保存合同沿场景11。截图/页面文字、完整消息、run终局与文件/业务效果是不同证据。

Pi固定73f8de80：底层stream→agent-loop的message_update/end→Agent.processEvents先改streamingMessage/messages再await core listeners→AgentSession扩展/公共通知及message_end追加会话记录→RPC序列化stdout，另有await stdout背压。它将同一次执行的底层流传递到不同消费者；不能据此把所有监听都当作无业务含义的可选通知，也不能据公共通知先到就声称磁盘保存完成。我们借用现有框架流驱动/投影即可，不为UI再造一次模型调用；慢Web客户端由有界缓存/重同步处理，和Pi RPC背压成本不同。
