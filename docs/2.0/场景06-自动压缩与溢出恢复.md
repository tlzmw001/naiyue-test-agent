# 场景6：自动压缩与溢出恢复

> 版本提示（2026-10-20整理）：正文保留本轮讲解时点的基线。并行开发已开始Spec118模型事件迁移；文中的旧32类目录、两套模型事件或“Spec118未实施”属于当时状态。当前事件名称及实际消费者见[事件功能总结](总结01-事件的实际功能.md)，开发验收以对应Spec/交接为准。

从[十二组场景总览](十二组场景总览.md)整理为独立文件；保留原讲解内容和当时的版本、验证边界。

- **问题**：上下文超过预算时需要安全压缩；供应商真实拒绝后还需局部恢复。
- **当前主动路径**：`compact_before_new_run.abefore_agent → _acompact_messages → _compaction_steps → arun_summary_steps → summary model`；检查切点、摘要有效性、压缩后预算，再返回RemoveMessage/summary/preserved更新。
- **当前溢出路径**：`recover_input_overflow.awrap_model_call`识别输入溢出→强制压缩→只重试当前handler一次→响应接受后ExtendedModelResponse/Command提交替换历史及响应。不是重跑此前工具。
- **失败**：某些临时/空/截断摘要且原请求仍安全时可回退；强制恢复不能回退已拒绝输入；重试失败不能把摘要当成功提交。
- **判断**：安全切点、局部重试和成功后提交是强项。主动压缩只挂在run开始；同run多轮工具/steering增长不等于每次都做主动压缩，后续有观测和溢出兜底。这是触发策略限制，不直接证明请求必定失败。
- **目标**：在实际每次模型请求前定义预算决策，不等于每次都摘要；与第5组请求事实一致。保留供应商拒绝后的单次局部恢复。当前摘要生成器只有arun_summary_steps一个生产驱动器，可改为直接async流程，纯切点/预算算法保持可测试。
- **保护**：原历史不被失败摘要破坏、配对不拆坏、既有工具不重放、响应门禁仍适用、原异常/失败阶段可见。
- **测试入口**：`tests/test_context_overflow_recovery.py::test_tools_before_overflow_are_not_replayed_and_checkpoint_continues`。

## 场景6补充：候选、局部重试与正式提交（2026-10-20）

本段按当前源码补齐场景6后半；检查时点、两条预算线、安全切点与单套模型事件目标已进入[Spec118](../specs/118-request-preparation-and-context-budget.md)，未实现，不在这里重记成当前行为。当前初始主动路径仍是abefore_agent，模型事件仍有逻辑call及框架invocation两组。

贯穿例子（示意，非实网记录）：图中原消息为`[H_old, A_old, H_task, A_tools(t1), T_result(t1)]`，下一模型请求被供应商明确判为输入溢出。合法压缩候选保留`[H_task, A_tools(t1), T_result(t1)]`，用摘要H_summary替换旧前缀；工具t1已经执行，不重放。

```text
recover_input_overflow.awrap_model_call
  → handler(request)首次请求
  → input_context_overflow_reason确认明确输入溢出
  → _begin_recovery：本次request的模型/系统提示词/工具/messages，force=True
  → _acompact_messages：安全计划、摘要、有效性/配对/预算及确实缩小校验
  → update = [RemoveMessage(REMOVE_ALL_MESSAGES), H_summary, *preserved]
  → _retry_request：移除状态控制标记，request.override(messages=update.messages[1:])
  → handler(retry)只执行当前模型请求一次
  → _recovery_returned：ExtendedModelResponse(响应, Command(替换消息+响应.result))
  → 外层_ModelSelectionMiddleware._accept响应门禁
  → 本机框架组合器返回、amodel_node._build_commands
  → LangGraph按messages reducer合入更新
  → ContextOperationObserver.observe确认替换与响应可读
```

`RemoveMessage(REMOVE_ALL_MESSAGES)`是图状态更新指令，不进入供应商输入。摘要本体是带`naiyue_compaction_summary=True`的HumanMessage；该类型不代表真实新用户授权。框架先生成响应状态Command，再附加middleware Command；恢复更新清空历史后须重新加入response.result，保留正常AI响应及可能的结构化结果消息。该Command在wrapper返回前只是候选；外层门禁抛错时amodel_node不会返回它，不能把生成包装视为提交。

主动与恢复的提交边界不同：当前abefore_agent主动压缩返回更新，图先合入，再进入正常模型调用；后续主请求失败不会据此声称主动摘要从未提交。overflow候选先用于局部重试，重试及外层门禁成功后才随模型节点结果提交。两者复用摘要算法，不承诺同一种回滚语义。

| 分支 | 当前结果与状态 |
|---|---|
| 普通超时/401/429，或只在RuntimeError文字里出现超限 | 不进入本恢复；原异常沿原路径传播 |
| 无需主动压缩/无安全前缀但原输入仍在发送预算 | 返回None，按原合同继续；不等于强制恢复成功 |
| 主动摘要临时失败、空或截断且满足既有fallback条件 | 原输入在发送预算且配对合法时可回退；不泛化为任意失败都可回退 |
| overflow无计划/摘要无效/不缩小/仍超预算 | 明确失败，不回退已被拒绝输入，不增加单条文本切割 |
| 第二次主请求失败 | 不做第三次请求；原第二次异常传播，候选摘要不提交 |
| 重试返回invalid_tool_calls等门禁拒绝 | 原ModelResponseRejected传播，工具不执行，候选不提交 |
| 用户停止/外部取消 | 沿既有控制与取消合同结算，不作为普通overflow触发重试；必要收尾仍被await_settled保护 |

事件身份与确认：逻辑C2对应当前主模型请求；恢复O_recovery和压缩O_compaction各由ContextOperationObserver生成operation_id，恢复的related_operation_id关联压缩，retry_attempts=1。假设保留ID为h_task/a_tools/t_result，移除ID为h_old/a_old；observe必须看到图消息以前缀`[h_summary,h_task,a_tools,t_result]`开头、旧ID均已移除，且ID有效，才报告compaction_finished(applied)。恢复另须外层门禁已接纳、替换已确认、重试AI响应ID已出现在可读消息中，才报告context_recovery_finished(recovered)。健康观察路径在门禁拒绝时为恢复failed/response_validation、压缩unconfirmed；普通观察故障不会反向提交或撤回图更新。

必要保存与busy仍沿SessionExecution的既有_afinish_run：结算子工作、清理、等待持久化，满足关闭窗口/无在属子实例等释放条件后release_run，不因摘要模型返回就释放。

优先阅读两个确定性用例：

- 正常：`tests/test_context_overflow_recovery.py::test_tools_before_overflow_are_not_replayed_and_checkpoint_continues`。fake依次返回工具调用、明确overflow异常、恢复回复、下一run回复；断言工具只执行一次、普通模型3次及摘要1次、工具配对与后续checkpoint延续。证明本机受控恢复合同，不证明供应商token估算或真实副作用。
- 失败：`tests/test_context_overflow_recovery.py::test_rejected_retry_response_does_not_commit_compaction`。fake先抛明确overflow，再返回invalid_tool_calls；断言ModelResponseRejected、图消息仍为原messages、普通请求2次及摘要1次。事件补充见`test_context_operation_events.py::test_retry_response_rejected_does_not_report_recovery_or_replacement_success`，不把模型返回误报为恢复成功。
