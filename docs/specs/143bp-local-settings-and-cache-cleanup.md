## 1. 已确认的方向

1. 页面侧栏左下角目前显示“本地工作台”，删除该文字入口，改为齿轮图标按钮。
2. 点击齿轮打开菜单。该菜单承载本机范围的设置和功能，首项为“清理缓存”。
3. 不把“清理缓存”放入输入区加号菜单，不以当前选中的项目或会话限定清理范围。
4. 点击“清理缓存”打开类别选择窗口，用户勾选需要清理的类别后，主动执行。
5. 本轮清理类别限定为“工具输出归档”和“云输入包缓存”；其余对象按已确认结论维持现状，不提前加入。
6. 工具输出归档默认保留最近 7 天，云输入包缓存默认保留最近 3 天，执行清理时用当前时间与文件最后修改时间（mtime）比较，不采用创建时间或最近使用时间。
7. 不新增定时后台清理，也不在启动、打开项目或会话运行结束时自动执行本项删除。
8. 删除失败须在界面暴露具体原因和可定位对象，便于用户处理；同时记录诊断，不静默吞错，不让清理故障导致应用退出、会话运行失败或其他无关副作用。

本机范围指当前本机服务下仍在项目登记表中的全部项目（包括未打开的项目），以及普通持久会话的对应受管数据。用户已明确排除移除登记后仍留在磁盘上的项目目录；不为发现这类目录扫描整个 workspaces，不扫描用户任意目录、其他数据根目录或云端 Runner。扫描后项目被移除或登记身份变化时跳过该项目并报告，不沿用旧候选继续删除。尚未打开与已经移除登记是不同状态。

## 4. 窗口与操作流程

```text
侧栏左下角齿轮
  → 本机设置菜单
    → 清理缓存
      → 勾选类别：工具输出归档（保留最近 7 天）／云输入包缓存（保留最近 3 天）
        → 清理所选
          → 展示实际完成、跳过与失败情况
```

窗口明确显示范围为“本机已登记项目与普通会话”。入口不依赖必须已选择项目或已创建会话；切换项目不改变它的本机范围。已移除登记的项目不参与本次扫描或删除。

交互合同（最终接口与状态见 00/S3）：

- 齿轮使用可访问名称“本机设置”，支持键盘打开、关闭及焦点返回；沿用项目现有菜单行为和样式。
- 打开菜单、打开窗口、勾选类别均不删除文件。
- 类别初始不勾选；未选择类别时不能执行清理。
- 首版打开窗口只读取策略，不做预览扫描；执行后展示实际删除数量与字节数。加载中、不可用和零删除分别显示，不填示例数字。
- 点击“清理所选”是删除动作的明确入口，不增加逐文件确认。
- 清理结果报告实际删除文件数和对应文件字节数，区分跳过和失败；不把逻辑文件字节数宣称为文件系统实际释放的块数。
- 失败不能只显示“清理失败”或只写日志：显示类别、项目/会话、可定位的受管路径、失败步骤与原因，提供匹配原因的处理提示。无法确定占用者时不猜测具体程序；操作系统错误码保留在详情中。
- 请求结果不确定时，界面只查询原 ID，不自动重发删除；实例变更后明确结果未知。具体合同见 00/S3。

## 5. 七天规则与文件保护

用户已确认的规则：执行本次清理时，以文件最后修改时间（mtime）计算，保留最近 7 天的工具输出归档。

实施采用的精确定义：

1. 服务端为本次删除操作固定时间 `T`，保留边界为 `T - 7 × 24 小时`，不使用浏览器时钟。
2. 同一调用的归档按文件名中的调用标识分组，以组内受管文件 `st_mtime_ns` 的最大值判断。只有严格早于保留边界的整组才符合时间条件，边界上的文件保留；不使用归档目录或所有权标记的 mtime 代表文件时间。
3. 读取归档不续期。后台任务仍在运行、写入未关闭或正在受保护读取时，即使符合时间条件也不删除。
4. 只处理应用明确拥有、现行目录布局下的归档；沿用固定文件类型、路径和所有权检查，不按任意路径递归删除。
5. 预览统计不构成放宽文件身份检查的理由。执行前复核归属、占用和文件身份；状态变化的范围跳过并提示重新检查。
6. 一个项目忙碌或不可清理时，不终止其任务；全局结果应区分该范围被跳过与其他范围已完成。
7. 删除失败保留尚未删除的文件并提供用户可读原因和日志，不能提前报告全部成功。按第 10 节隔离故障，其他可独立安全处理的范围继续；删除操作不承诺跨文件、跨项目事务回滚。

以上精确规则已在 00/S1 落实到接口与并发入口。清理时间语义不能倒退为启动、打开项目或会话结束时自动删除。

## 6. 云输入包缓存：保留最近三天

用户已确认：后续将退出旧代码交付路径；本机云输入包缓存加入本机手动清理窗口，保留最近 3 天。该决定不表示旧代码交付已经退出，也不在本轮执行代码迁移或删除数据。

- 范围：本机项目数据库旁 `cloud-input-cache/` 中应用拥有的冻结输入包及其专属缓存元数据。原项目文件、云端输入包、已接收成果均不在本项范围。
- 触发：只在用户勾选该类别并执行清理时处理，与工具输出归档共用本机入口，无后台任务。
- 时间：用户已确认采用最后修改时间。服务端固定本次时间 `T`，保留边界为 `T - 3 × 24 小时`，边界上的数据保留。包按一起回收的受管文件 `st_mtime_ns` 最大值判断，不能只看包目录；独立回执按其受管文件最后修改时间与实际引用判断。缓存根目录、锁和其他包的变动不影响本包时间。不新增访问续期，不因读取或复用主动触碰 mtime；活动依赖由占用保护负责。
- 保护：正在捕获、上传、续传或执行相关恢复的包跳过；清理不主动取消操作。共享同一输入内容的消费者需一起核对，不能因为一个操作结束就删除共享包。
- 旧代码交付：现存 apply/branch/基线验证路径仍可消费输入包。实施前核对旧路径退出状态；若尚未退出，仍被未完成交付及其恢复依赖的包保留并提示跳过，不假定未来迁移已经发生。其余旧任务输入引用的释放规则与退出合同一同收束。
- 暂存和来源回执：不按整个目录递归删除；固定输入包、导入回执和异常暂存各自明确归属与恢复依赖。保留缓存所有权标记和锁文件。
- 验证：覆盖 3 天边界、重复复用旧包、共享内容、上传/续传并发、异常暂存、旧交付尚未退出和原项目文件不受影响的场景。

本项已批准加入类别、三天保留期限及 mtime 时间来源。S2 已规定实际依赖释放、文件分组、跨进程读取保护与失败退役处理；旧路径依赖保守保留，不提前删除历史记录。

## 7. 正常与失败场景

正常场景：本机项目 P1/P2 和普通会话 S 各有受管归档；用户在 P1 页面打开本机齿轮菜单，选择工具输出归档。服务端按本次时间及真实归档状态筛选，删除超过 7 天且可以清理的归档组，保留最近 7 天的数据，返回各范围及总计结果。P2 未在前端打开不代表排除 P2。

占用场景：P1 正在执行命令或有尚未收尾的后台任务。清理不能终止它，不能绕过现有占用保护；P1 显示跳过，其他可安全清理的范围仍可处理。

文件变化场景：查询候选后，某归档发生写入或目录身份变化。执行复核后跳过受影响范围，不把旧预览当成当前删除授权。

登记变化场景：P2 仍登记但未打开时纳入清理；P3 已从项目登记移除，即使其受管目录仍在磁盘上也不扫描。扫描期间 P2 被移除时，执行前复核后跳过。

Windows 失败场景：一个候选文件删除返回共享冲突，界面显示该项目、文件及系统错误码，提示关闭可能占用它的程序后手动重新清理；剩余文件保留，其他安全范围继续。会话仍可发送消息，后台任务不被终止，清理中的锁与占用标记正常释放。只有访问被拒绝时，应说明可能是权限、只读属性或占用，不能断言某个杀毒软件是原因。

历史读取场景：超过保留期的归档被用户手动清理后，聊天正文仍在，但原路径可能已不可读取。类别说明须写明会移除较早的详细工具输出；读取失败不能用空内容冒充原结果。

- 保留当前手动清理实际消费者，实施时核对兼容范围；不借新入口擅自改变现有 CLI 合同。

## 9. 逐项讨论补充结论：云端共享输入回收

2026-11-18 用户确认以下方向；本节是云端独立变更的需求记录，不属于本机清理窗口的执行范围，尚未实施。

- 完整删除云端任务后，对该任务使用过的 Coordinator 共享输入包进行回收检查。释放环境、本机移除关联不等于完整删除任务。
- 仅回收已经没有其他任务、附件、在途上传提交、读取或必要恢复操作依赖的包；不按包年龄判断，也不因一个任务删除而无条件删除共享包。
- 上传成功但尚未完成任务/附件关联的间隙需要保护，不能仅以当前任务引用计数为零判断可删除。保护方式及终结条件在云端详细实施 Spec 中收束。
- 删除任务前需固定相关输入身份，避免删除完成后请求脱敏或关联移除导致候选集合丢失；详细设计核对墓碑、幂等重试和引用竞争。
- 回收失败应可观测且可恢复；任务删除成功与共享缓存回收成功分别表达，向用户展示失败包与原因，不把已成功删除的任务误报为仍存在，也不能把未删除字节提前核销。共享缓存回收异常不应导致 Coordinator 退出或改变其他任务结果。
- 回收只处理明确拥有的共享输入目录及其元数据，不删除其他任务的 workspace/state、已保存成果或全局历史。
- 验证覆盖共享输入仍被另一任务使用、最后一个引用解除、上传到关联的间隙、并发读取、删除中断和重复删除请求。

本轮同时确认维持现状：数据库升级备份与还原原库不加入缓存清理；结构化诊断沿用现有年龄/容量维护；Runner outbox 不新增独立裁剪，随完整删除任务清理。

## 10. Windows 兼容与失败可处置合同

2026-11-18 用户明确要求：按最后修改时间计算，排除已移除登记的项目，删除失败的原因须可供用户解决，不能静默或使应用崩溃。本节落实这些要求，不授权执行清理。

### 10.1 已有问题与复用边界

- [Spec143AT](143at-windows-input-publication-retry.md) 记录了 Windows 输入包发布曾返回 WinError 5、稍后恢复的现场；这证明访问拒绝可能是短暂占用，不能一律解释成永久权限不足或猜测占用进程。原发布操作的局部重试不自动扩展到删除。
- [storage/files.py](../../naiyue_test_agent/storage/files.py) 的 `changed_store_fields` 已区分句柄与路径的时间字段语义；[备份回归](../../tests/test_storage_backup_validation.py) 和 [云端兼容回归](../../tests/cloud/test_windows_cloud_compatibility.py) 覆盖了 Windows `fstat/lstat` 的 ctime 差异。保留期只使用 mtime；身份检查复用现有规则，不重新比较两种来源的完整 stat 元组。
- 路径操作复用 `windows_api_path`、受管路径校验及现有 Windows 目录保护方式，避免假定 POSIX 的 `dir_fd`、`O_NOFOLLOW` 或目录 fsync 在 Windows 可直接使用。不跟随 junction/symlink/reparse point，不通过先 resolve 掩盖重定向。
- [Spec143AC](143ac-windows-durability-and-cloud-ui.md) 已记录只读句柄 fsync 在 Windows 的失败。清理若有必要持久化元数据，应沿既有可写句柄及跨平台目录同步入口，不以忽略 IO 错误替代兼容处理。

### 10.2 时间与句柄

- 使用服务端同一时基的整数时间与 `st_mtime_ns` 比较，不转换成日期字符串，不按浏览器本地日期计算；保留精度较低的文件系统实际报告值，不假定物理精度一定达到纳秒。边界相等和未来 mtime 均保留，属性读取失败不得当作时间为零。
- 文件打开句柄可能阻止 Windows 删除。删除前关闭本次扫描/校验已不再需要的目标句柄；需要固定的父目录与活动预留仍按既有保护保持。删除子目录前释放阻止该子目录删除的自身句柄，不为解决占用而放弃路径身份复核。
- 不强制关闭用户程序、不自动提权或修改 ACL/只读属性、不以无限重试掩盖故障。用户根据原因处理后可再次主动发起清理，重新扫描与复核。

### 10.3 结果、异常隔离与诊断

- 每个失败至少包含类别、项目/会话或输入包身份、可定位的受管路径、步骤（枚举/属性读取/文件删除/目录删除）、稳定错误码、用户可读原因及适用的处理提示；详情保留 `errno/winerror`。日志记录对应诊断，禁止写文件内容、凭证或未经处理的敏感异常正文。
- 区分已删除、受保护或状态变化而跳过、删除失败、结果无法确认。统计只累计可确认的实际删除；已被外部删除的文件不冒充本次释放空间。部分成功必须如实展示，失败明细不能被总数覆盖。
- 普通单项 IO 失败停止该最小安全单元，保留剩余文件及必要恢复信息，继续其他独立安全单元；目录身份、所有权或登记失效时停止对应范围。全局枚举失败或无法保证隔离时终止本次清理并报告，不降级成“无缓存”或继续盲删。
- 错误在清理任务/请求边界转为明确结果；IO 继续使用既有后台执行方式，不能长时间阻塞应用事件循环。异常及取消路径均释放本次拥有的锁、句柄和清理预留；不吞正常取消信号，不改变正在执行的会话/云任务状态，不让 UI 永久停在清理中。
- 未预期异常须留下诊断并使本次清理明确失败，不能通过空 catch 伪装成功，也不能逃逸为服务退出。网络断开时只报告结果未知，不自动重发删除；确认最终结果的接口在实施合同中定义。

## 11. 拷贝优化：本轮全部暂缓

2026-11-18 用户明确“拷贝这些都可以先不改”。此前讨论的九项均维持现有实现：

1. 本机云端成果保存时，预览与执行中的临时副本。
2. 本机输入缓存命中前的重复捕获与打包。
3. 首次输入捕获中的冻结副本与归档。
4. Runner 不同附件身份之间的重复下载与缓存。
5. 接收、保存和发布等环节的重复整文件校验读取。
6. 历史与 checkpoint 的重复序列化及哈希计算。
7. 图片在消息与持久化状态中的重复存储。
8. 消息、审批与事件对象的内存深拷贝。
9. 旧基线、差异和代码交付路径中的拷贝。

这些项目包含磁盘写入、重复读取及内存复制，不宣称具有同一种成本或已测得收益。暂缓性能优化不撤销本机缓存手动清理和云端任务删除后回收无依赖输入包的已确认方向，也不授权退出旧代码交付路径。

## 12. 已确认保留：云端已提交但从未关联的输入包

当前源码：[LocalAttachments.launch](../../naiyue_test_agent/application/cloud_local/attachments.py) 先完成 `client.upload`，再检查取消状态，随后请求任务附件关联。[CloudInputs](../../naiyue_test_agent/application/cloud/inputs.py) 的上传暂存过期清理跳过 `committed`，提交后的输入包也不能由原上传取消接口删除。因此上传已提交、关联前取消或关联失败且未恢复时，可能留下从未被任何任务引用的云端共享输入包。此处是静态调用链分析，未执行故障注入或真实云端验证。

第 9 节已确认的回收仅检查被删除任务使用过的输入包；一个从未关联、且未被其他任务复用的包不在这个候选集合中。本机 3 天规则也不适用于 Coordinator 的这份数据。正在等待关联或必要恢复的包仍须保护，不能把当下零引用等同于可删除。

2026-11-18 用户确认：本轮对此类包继续保留，不新增独立过期扫描或删除入口，将其作为已知限制。未来若单独覆盖，需另定上传到关联的保护终结条件及回收触发点，不能直接套用本机 3 天期限。
