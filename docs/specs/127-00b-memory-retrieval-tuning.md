# Spec127-00b：检索精度实验与参数校准

2026-10-22。用户在00结果解释后确认需要继续实验检索算法与调参；本片实验已完成，[实际结果及限制](../research/memory00/检索调参与独立测试结果.md)。仍限离线研究，不接生产/真实配置/用户库、不增加依赖或供应商模型调用；保留00原始代码/协议/数据和结果。01 history暂不实施。

## 1. 问题与假设

00的字组OR扩大了召回，也允许仅含「测试」的环境/鉴权记忆进入「测试类」结果；仅按各库名次RRF不能识别弱匹配。此前81.25%是非空query精确率宏平均，全部条目合计仅16/28=57.14%；子串为14/16=87.5%。00实验完成，适配FTS只保留为待验证技术方向，不再将3/2/1＋RRF60视为产品最终策略。

本轮分别检验：查询字组覆盖门槛能否减少单泛词噪声；精确表达存在时停止补充弱匹配是否有价值；使用跨库可比的词项覆盖/命中字段重新排名，能否改善RRF第一名弱匹配。所有方法必须允许少返回，技术锚点/范围/状态/期限/权威版本约束保持。

## 2. 固定样本、协议与影响文件

新增明确标注的合成语料及144条查询，36个事实/意图组，每组4种表述；同组只进入一个split。18组72条校准、9组36条验证、9组36条最终测试，各split含2组无答案。每条保留intent、来源组、相关ID及禁止项；相似但不回答目标问题的条目作为难负例，另有失配/到期/停用/候选/遗忘条目。原00的24条已被观察，另作历史回归，不混入新独立测试。

本轮样本仍是小规模手工合成，不假装统计代表真实用户分布。改写由同一作者编写，有模板/用词相关性；按事实组隔离能减少同事实泄漏，不能消除人工样本偏差。查询intent用于标注解释，不输入算法，不增加用户侧参数。

范围仅docs/research/memory00/新增tuning数据/协议、tuning检索与benchmark、测试、结果报告及Spec/当前状态同步；复用00的ResearchIndex和可信过滤/版本重验，不改冻结实现或新造存储层。四类待比较实现均取同一前50候选池，返回最多8；新筛选在该池后执行，报告有限候选池带来的漏召回限制，不假装已实现全库无损筛选。

## 3. 候选方法与调参范围

| 方法 | 本轮区别 |
| --- | --- |
| substring / adapted_or | 保留原子串及字组OR＋RRF基线；权重按相同校准规则选择。 |
| coverage_rrf | 字组集合覆盖比例达到门槛才返回；保留原RRF顺序。 |
| cascade_rrf | 优先返回原query各词段都能完整字面命中的条目；若不存在，再按覆盖门槛回退；不为填满8条补弱匹配。 |
| cascade_quality | 同分层/门槛，使用原词段命中及字段覆盖的统一确定性分数重排；RRF仅作后续同分依据，不直接比较跨库BM25。 |

权重只比较(1,1,1)/(3,2,1)/(5,3,1)；覆盖门槛只比较1/2、2/3、3/4、1；每方法最多12组。索引、单词/数值/标识符边界沿00，不添加专用同义词表、停用词名单或按某条query ID的分支。RRF60、候选50/结果8冻结，不调无实际作用的常数凑参数。

覆盖按去重字组/英文词项计算，不强制所有中文字组AND；例如「用例生成」与「生成用例」共有2/3字组，可在2/3门槛保留。完整字面命中按原查询词段检查，不能把OR中的任一字组当完整表达。统一重排分数仅由原词段在标题/别名/正文的匹配比例及字组覆盖构成，具体固定公式在首次评分前随代码哈希冻结。

原query及显式expansions都参与筛选/重排，按完整命中、覆盖比例、质量分的顺序取最佳variant证据；锚点仍由原引擎逐variant强制校验。字段质量分固定为max(字段权重×该字段完整词段命中比例)＋sum(字段权重×该字段字组覆盖比例)/sum(权重)。各方法还在验证集以相同3/2/1和2/3门槛作消融对照，区分方法变化与调参收益；不增加测试后可调的规则。

## 4. 评分、选择与测试集边界

报告micro precision（全部相关返回/全部返回）、有答案query的macro recall、正例逐query F0.5（空结果按0）、Hit@1、MRR@8、无答案错误返回率、平均条数/字节、禁止项和逐query遗漏/额外项。非空query precision仅保留为旧口径对照。F0.5侧重精确率，不把空结果的精确率算100%；负例另外统计，不能藏进正例平均。

校准集为每方法选参数；选择键预定为禁止项更少、无答案误返回更少、正例F0.5更高、macro recall更高、Hit@1更高、返回更少，最后参数更简单。验证集用同一顺序选定一个方法并冻结；方法须先通过已知旧集合全部required/禁止项/无答案门禁，没有合格方法则停止，不消耗最终测试。正式测试只评一次冻结选择与各方法预先选定配置，不用测试结果换胜者/改参数；失败如实保留。选择键用于实验比较，不是新产品配置或已确认质量门槛。

协议修订说明：首次校准/验证冻结v1选择coverage_rrf的3/4门槛，但对已观察旧样本复跑确认h10「用例生成」required遗漏，最终测试尚未运行。v1选择遗漏了已知行为回归门禁；保留v1原结果/源码/协议证据，新增失败测试后在v2补上述选型资格检查。没有改变样本、标签、算法或参数网格；这次修订使用的是已观察开发样本，不声称v1结果独立，也没有查看最终测试成绩。

v3在首次最终测试前另修复每variant技术锚点的筛选证据回归，独立红灯后修复；protocol的revision_note只描述v1→v2门禁变更，不表示v3没有算法实现修复。最终测试首次使用frozen-v3，此后不改算法/数据/参数。

安全门禁必须禁止项0；若最终测试相对子串或旧OR出现精确率/召回/首条明显退步，不能仅因某个平均分好就定型。报告各方法取舍和最差案例，由用户确认后才进入产品检索。无方法满足需求可以是本轮有效结论。

## 5. 执行、失败与验证

流程：固定数据/协议哈希→失败行为测试→最小算法/评分实现→校准选参→验证选方法并冻结→最终测试→重复性/规模噪声探针→报告。新代码单文件≤500行；CLI沿00的显式证据目录、拒绝覆盖/冻结指纹校验和失败诊断，不读隐藏配置。数据/预定参数在首次评分前冻结。

正常链：benchmark读固定query→原ResearchIndex提供当前有权候选→确定性筛选/重排→实际返回ID→独立gold评分与结果；失败链：旧索引/技术近名/失配候选在原链拒绝，筛选全不满足返回真实空；数据或代码在冻结后变化则拒绝测试，不覆盖旧证据。

复用原研究57项，新测试覆盖整词优先/2/3改写/各库强弱匹配/不填满/无答案、micro与空结果指标、按组划分及冻结不使用测试标签。只跑本片研究回归、语法/导入/行数/哈希/链接/diff；并行产品修复不在本片范围，不重复宣称旧产品全量成绩是当前验证。

本轮没有新增工具API、DB schema或真实配置。数据/程序只被研究CLI及测试消费，可直接保留原00结果回退，不触碰用户状态。后续若基于测试结果改策略，当前测试集即转为已观察数据，须新增独立样本，不再称独立验证。

依据：SQLite FTS5的[布尔匹配](https://sqlite.org/fts5.html#fts5_boolean_operators)及[BM25列权重](https://sqlite.org/fts5.html#the_bm25_function)属于词项匹配/排序机制，不提供本项目语义正确性或跨库可比分数；本片的覆盖/分层是待实验的项目策略。

实际收尾：76项研究测试通过，42组配置评分、冻结后180条测试排名及重复性检查完成，过滤禁止项0；新正例28/28召回、精确率28/31，旧必命中20/20而相关召回92.08%。复杂统一重排无额外收益，不先采用；候选为分层＋RRF、同分权重1/1/1、回退覆盖1/2。残留主体/对照提及、含混查询和重复噪声需先评审，尚不固定产品参数。完整命令、实际结果及无产品构建/全量声明的边界见报告。
