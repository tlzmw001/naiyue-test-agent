# Spec127-08：精简记忆合同的真实模型对比

2026-10-22，用户在127-07交付后确认继续，推进上一轮已说明的真实模型对比。本片是验收实验，不新增记忆功能。新一轮最多24次真实HTTP发送，历史48次及13/24评分保留，不复用旧预算。

## 1. 范围与固定条件

读取用户已授权的`.env/models.json`现有默认模型；只使用该配置的语言模型，不访问passwd或调用embedding、评分、修复模型。当前默认为heiyu-gpt-5.5、OpenAI兼容Responses。实验持有两个独立catalog，仅在进程内设置所选模型的memory_output=text或json_schema；不修改实际配置、模型参数、SDK重试、项目/个人用户数据库或产品代码。

同一冻结12样本各运行一次，两协议合计24个逻辑调用上限；HTTP发送也共享24上限，每组最多12次，SDK重试计入。调用前校验源文件、提示和fixture哈希，实验中不调提示、schema、检索或评分。交替运行同一case的两协议，保留时间/顺序/实际输入以便核对相关记忆、覆盖和预算差异。每次调用沿既有run_case→MemoryJobs→生产worker→一次模型请求→严格解析→03保存，使用临时SQLite及独立data_dir，结束后关闭。

## 2. 预算、失败及保存

复用RequestBudget及probe_callback计量逻辑调用；在catalog自己持有的HTTP客户端request hook中预留发送额度，拒绝第13/25次发送，不修改SDK重试次数。生产HTTP观察记录尝试/状态和memory调用配对。callback只保留安全错误类型、HTTP状态及经有限字符校验的code/param，禁止供应商异常正文、鉴权、端点或配置正文进入报告。

确定返回400/404/422且无合法模型输出时，停止相应结构化协议组，记录不兼容/请求拒绝，不能据此直接断言模型本身不支持。同组连续三次HTTP/超时/顶层格式失败则停止实验并报告，不自动改用function_calling或新增请求。正常顶层下的语义不符合预期继续记录全组，不能因失败修改样本或门禁。每个case结束立即独立写JSON，避免后续失败丢失已有证据；停止/预算不足如实标incomplete。

## 3. 评估及解释

1. 协议层：HTTP状态、顶层可解析、逐条proposal有效、实际发送次数、SDK尝试、用量/耗时及事件配对。
2. 固定预期：沿既有check_case检查类型、状态、必须来源和候选同ID/版本；分母仍为原12段，未运行单独计数。
3. 助手逐项复核：实际保存正文/范围是否受来源支持，是否违反原forbidden、是否有噪声、是否把指定流程说成执行结果。代码结构通过不自动等于语义通过，助手复核不冒充用户验收。
4. e06缺具体命令/依赖/可复现目标与原active预期冲突，仍按原预期计失败并单独说明；不为分数放宽experience门禁或改分母。

这是旧冻结样本的开发回归，每协议每样本一次，没有独立泛化或统计显著性证据。与历史13/24只能描述观察差异；不能把样本量差异、模型随机性或schema额外开销当成协议因果效应。真实网关结果只约束本次配置及时间，不宣称所有Responses/OpenAI网关均兼容。
