原会话/工具原文仍在既有档案。项目记忆、版本、来源/抑制、FTS、概览和处理位置复用当前目录sessions.sqlite的独立业务表，不写入checkpoint或另存可双向编辑Markdown。个人记忆及同合同字段独立存data_dir/personal/memory.sqlite；相同data_dir共享，不同data_dir不自动合并。

## 4. 生效、转正与生命周期

明确持久用户约定或有直接来源支持的可复用有限观察，条件清楚且无已识别冲突，可首次active。价值明确但缺持久意图/验证/条件/冲突解决时candidate并写缺口；例行/无价值/敏感/来源不成立不保存。不因confidence、时间、使用次数晋升。

每次阈值同时提取新建议并有界检索相关旧候选，由同次现有模型结合新增原始依据提出更新/转正；不是固定第一轮建候选、第二轮转正，不增加评审模型或定期全库扫候选。主Agent显式补证走同一memory更新校验。

提交校验可信范围、来源角色/版本/引文、大小/类型/条件、已知冲突/敏感/抑制及expected_version；语义仍依赖模型，引用相等不是语义证明。更新同稳定ID及新版本，状态/正文/索引同库事务提交。另会话先更正/停用/遗忘则旧版本提交冲突，不能最后写入覆盖。

更正保留版本；替代须同主体/范围/条件并有明确新依据，不让时间戳决定。单次工具失败不推翻用户选定环境，不把过去成功当当前可用性保证。失效/到期退出默认集合但可历史追溯；遗忘清正文/引文/版本/索引，登记及提交均检查已知抑制。不承诺识别任意同义改写或删除原会话/全部备份。

| 主类 | 候选TTL初始默认 | active TTL初始默认 |
| --- | --- | --- |
| user/rule/decision | 各30天，可按类配 | 不适用类型TTL |
| context | 30天 | 30天 |
| procedure | 30天 | 180天 |
| experience | 30天 | 365天 |
| reference | 30天 | 90天 |

普通读取/注入/改写/旧证据重提不续期；实质新补证/确认使用真实新来源时间，不用导入/整理时间。明确来源截止时间与类型TTL取早，免TTL类型也遵守明确截止。TTL配置修改不追溯原截止时间，后续新建或实质补证/确认时采用新策略；到期不需要模型打分、闲置定时器或物理删库。不能把context改写成decision绕过TTL。

## 5. 工具合同

history操作：list_sessions、search、read。01参数为query/完整session_id/可选已登记agent_id及受控分页cursor、limit（默认10，最大50）；read按返回的sequence/revision/conversation_revision和offset分段读，不允许任意thread。程序核对该目录真实归属/父子身份，模型不能指定任意库路径。目录按真实活动时间，排除当前会话用于首次注入；无概览如实为空，保留真实标题/时间/运行状态。

memory操作：list、search、read、record、update、disable、forget、refresh_overview。查询scope为当前workspace或personal，默认active，用户明确查询候选/历史时才扩展状态；操作参数沿现有BaseModel做严格action判别校验，proposal/source独立强类型，禁止任意status=active绕过校验；03不为schema外形改通用工具构建层。update承担补证/转正，需memory_id和expected_version，写入建议附来源/条件/正文；记录可零条，不做填额。

返回包含status、真实ID/version/scope、短正文/标题/条件、来源/验证时间、匹配字段/详情入口，以及分页/截断。写入区分saved、still_candidate及缺口、conflict/failed；整理登记返回accepted/task_id，不能说已更新。无结果与IO故障分开；工具业务错误按现有工具反馈合同返回，许可/机制异常保持现有边界。

history无内部模型调用；memory显式完整内容不为复述另调模型。依赖完整本轮的概览/提取请求只登记，待本轮正常结束且必要保存后执行；不等待自己。明确已有条目的更正/停用/遗忘可在工具内短事务保存必要来源并提交；来源不足时不虚构保存成功。

parallel/read_only与parallel/may_mutate沿已有ToolSpec；同批有sequential工具仍整批顺序。依赖上一步ID/version的更新在后续调用。个人直接允许不等于跨项目历史读取许可，来源链接只给定位及不可用原因。

## 6. 整理输入、输出与调度

来源是已保存可见档案及真实reply/分支版本，不从压缩后图消息重建全部历史。输入含旧概览、新用户/助手可见正文、工具名/脱敏参数/退出事实/有限正文/归档入口，以及少量相关active/candidate。reasoning、system/恢复内部材料、凭证配置、二进制不进入；外部工具/子报告不冒充用户来源。图像只保留已有文字/引用，不加识图任务。

每批一次既有模型返回固定JSON的overview与proposals（可零条）；无独立提取/评分/格式修复循环，不强改模型temperature/思考。程序独立校验概览/每条记忆，来源信封/处理位置由程序提供。顶层截断/不可解析不抢救权威状态；一部分有效可独立保存并显示部分成功，不把概览成功说成记忆成功。

应用独立worker拥有模型调用及控制；同会话一个在途任务，重复目标合并；全应用并发1、等待目标32。只共用既有后台查看数据/停止入口，不把Shell的command/capture/process manager改名充当记忆服务。已结束root结果不等待普通整理；用量/失败独立记录。停止/进程关闭必须确认必要提交及资源终局，后台本身不保证重启接管。

自动触发仅在正常完整根用户轮必要保存成功后，新增8轮或20000用户/助手可见正文字符（OR）；不含思考/system/原始工具洪峰。成功登记/合并时推进触发基线，期间新增内容不丢；失败区间跳过、下次不自动补做，不因旧失败反复触发。队列满未接收则不推进基线，下个正常用户轮可重试登记，明确区别于已处理失败。

输入过大先分批，单轮按记录/原文区间分段；正常可处理分段在预算内前进。300秒/3批任一到达停止启动新批，保留独立成功，未处理/失败如实标注，之后新增材料继续，不自动回填。用户显式指定会话/区间可另行有界整理，同样校验范围/来源/抑制和额度。

首次启用不遍历全部旧会话调用模型。新会话从起点累计；旧会话在新增用户轮前记录保存上界为触发基线，首次触发可取预算内最近完整旧轮＋新增轮，明确早期未整理，之后增量。旧来源时间不续TTL，无概览仍能history读原文。停止/失败/审批等待本身不触发自动整理。
