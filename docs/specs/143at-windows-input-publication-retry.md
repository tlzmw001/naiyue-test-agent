# 143AT Windows 输入归档发布重试

Windows 实机用相同三个压缩包复现。原文件读取与打包完成，发布目录时 os.rename 抛 WinError 5。同一现场约 14 秒后改名成功。证据支持短暂的目录占用，进程归因以实机报告为准。

只在本机输入的两次目录发布边界重试。捕获已写入且刷新归档后，把 bundle 发布到暂存输入目录，再由缓存层发布到内容地址目录。对于 Windows 访问被拒绝或共享冲突，原地重试 rename，最多等待 30 秒。重试期间保留原归档和缓存锁。其他 IO 操作、非目标错误和传输不进入重试。耗尽时返回发布被占用，详细 Windows 错误码落本机日志，保留原清理语义。没有新配置项或云端协议变更。

通过假时钟与 WinError 注入验证两个发布点、14 秒恢复、原归档内容一致，以及耗尽后未发布。真实 Windows 安全扫描下的复验由用户完成。

验证：两个短暂占用回归在旧实现失败，修改后通过。定向后端 100 项、云端后端与安装烟测 1189 项、全量前端 639 项及构建通过。macOS 注入证据，Windows 三个压缩包原机复验待做。
