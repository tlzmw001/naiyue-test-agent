# Spec143BO-S6：完整接线、切换与评测验收

日期：2026-11-17。状态：默认 Wiki 切换与本轮工程验收完成；真实模型校准已记录，语义优化延期。依赖：[总规范](143bo-memory-wiki.md)、S0—S5。目标是从真实公开入口证实这套方案可用，清理被替代的内部路径，并区分工程正确与模型效果。

## 1. 接线完成的定义

以下链路都实际运行后才能称“Wiki 记忆已接入”：

1. 新会话 → 当前项目/个人 Wiki 导航与其他会话概览 → 模型按目录读页 → 最终回答。
2. memory 显式 record/update/disable/forget → permit → API → 必要来源保存 → 同库门禁 → 真实回执。
3. 正常保存满足旧轮数/字数阈值 → A → 概览独立保存 → B 读目录/页 → 整理/拆页事务。
4. organize → 已有合法页 → B 纯整理 → 来源/范围/期限保持。
5. 根会话必要保存成功 → checkpoint 维护＋新代记忆 GC → 统计与正确异常隔离。
6. 新格式打开 → 旧记忆不可用 → 历史/概览仍可用 → 新写入仅进入新代。

组件存在、单元返回正确和生产接线分别记录。未接线组件不靠文件名或测试 import 宣称完成。

## 2. 公开契约和兼容

memory 的工具名与 request 动作信封保持；kind 删除、destination/change/scope 来源和 Wiki 动作属于本次批准设计的参数迁移。许可绑定更新为 memory_actions_v2；旧待执行 v1 不执行、不猜参数、不重写历史审批。

历史 read 的 overview_only 与既有 cursor 配合，是 S4 的参数兼容扩展；原消息分页仍合法。权限、服务 DTO、工具 schema 和读取实现同步，不仅改工具描述；待执行调用仍必须通过实际参数的许可绑定，不能为旧审批静默补改字段。

真实 MemoryAPI/HistoryAPI 服务入口及 RunScope 身份保持；内部聚合 MemoryInput/编译器可按新合同迁移，不能因历史测试可 import 就保留废弃包装。

## 3. 配置与数据切换

准备新配置参考与字段级迁移说明，不自动改用户文件。若显式旧配置含已删除字段，启动报清晰迁移错误，发生在用户库迁移前；不得先升级库再因配置失败留半次启用。

停止旧 owner/排空已接受任务 → 校验格式与备份 → 开库事务执行 S1 新代隔离 → 校验完整新格式 → 构造新工具/仓储/后台/导航 → 接受运行。个人库保持原 DELETE/FULL 和并发初始化保护，不擅自切 WAL。

旧记忆从所有正向消费者消失；不是只不注入，search/read/后台比较/迁移回填也不能访问。旧忘记抑制保留。原历史与每会话最新概览保留，可用于 history，但不能被当成新发生的独立确认。

部分库升级、另一个库尚未打开是合法状态：每个库在自己 owner/事务内独立升级，无跨库数据搬移。个人格式不支持/繁忙时显式报告，不能退回旧个人记忆或切到当前项目库代存。

回退不声称可无损降级：新格式不能交给旧程序混写。必要时停止全部相关 owner，用验证过的迁移前备份恢复该库；新代切换后新增内容不会自动合并回旧格式。恢复是独立显式操作，不在失败时自动覆盖用户数据。

## 6. 性能验收

使用临时磁盘 SQLite 和固定合成数据，分别测试 2,000 与 20,000 条新代记忆；另加大量过期成员、旧版本和关联，不使用真实用户数据。

记录目录/正文/来源/GC 的 SQL 次数、查得行和字节、EXPLAIN QUERY PLAN、查询/渲染/序列化的 p50/p95、Python 峰值分配、并发等待。冷/热缓存分开，SQLite native 内存不能冒充已被 tracemalloc 完整测得。

必须满足：读取固定页不把整库正文取出；无逐条来源 N+1；游标无深 OFFSET；输出≤2,000 且可继续；组织提交后≤30；GC 依约有界并在续期竞态中不误删。耗时随总量变化和锁等待单独报告，不以一条极紧机器时间断言替代结构证据。

模型耗时、工具往返、网络、数据库查询和渲染拆开记录。只在实际数据表明目录/读取占主导时再考虑缓存或索引调整；不把本片扩展为检索算法比赛。

### S6 迁移回归补充：触发基线与当前协议

真实调用链仍为 `session_execution` 准备本轮 → `SessionPersistence.prepare_memory` → `MemoryJobs.prepare` 在非 preview 时调用 `storage.memory.ensure` 建立本轮之前的历史基线 → 根完成必要保存 → `MemoryJobs.after_finish` 的 `tick` 统计新增普通用户轮数/可见字符 → 达到任一阈值后登记并释放任务。目录导航改代不能删除该基线步骤；否则首次完成会被当成初始化时已有历史，轮数/字数阈值为 1 时都漏触发。只读 preview 不建立基线、不改数据库。

失败场景保持：受理保存失败不释放模型、不推进已接受基线；已经受理的模型失败范围跳过，不重试。目录的 seen 标记由 SessionPersistence 独立拥有，即使其失败，失败根运行也必须通知后台取消登记，后续普通运行不能复活该请求。

旧测试迁移使用当前 v2 action、Wiki A/read/finish、页面导航与真实 read，不保留旧 API 执行适配器。写入回执预算在 apply 之前检查；测试分别验证该阶段零写入、apply 后注入故障完整回滚，以及解锁后可再执行新的用户操作。项目/个人两库都检查页面、目录修订、记忆、版本、来源、搜索和抑制投影。重开读取须检查本轮最后一条工具结果，避免把上轮写入回执误当成读取成功。

候选页面必须返回 gaps/reason，存在明确 deadline 时返回期限；active 且无 gaps 不为这些空字段膨胀响应，原有分页预算仍须通过。公开 provider schema、许可信封串改、来源保存锁、关闭排空、子 Agent 独立许可和冷重开均使用当前主链继续验证。证据目录为 `build/spec143bo-s6/migration-r2` 与 `migration-r3`；完整后端未全绿前不标记 S6 完成。

### 生命周期测试迁移的合同对应

`test_memory_lifecycle*` 与 `test_memory_evidence_storage` 的当前产品行为改走 query_wiki/v2：旧 partial/unknown 确认对应 supplement，不提交新的正文；完整 replace 必须使用比旧 evidence_at 更新的真实来源，旧来源失败时版本和时钟不变。改变 default_ttl_days 不追溯修改已保存记录；supplement 保留旧 TTL，新的完整确认/替换才按新配置计时，明确 deadline 始终约束到期时间。active/candidate 共用统一 TTL，不再保留按 kind 或状态选择 TTL 的产品分支。

写入回执只返回 ID/版本等定位信息。沿用 S2 的预算合同：若后续读取连必要 metadata 和一个正文字符也装不下，明确返回 memory_budget_too_small，不截断必要条件/缺口来伪造可读性；原数据库正文与缺口保持完整。默认 read_page 仍不向普通召回暴露 candidate；显式 read 指定 candidate 可以读取，预算不足时如实失败。

并发和失败场景包括两个个人库 owner 的同版 CAS、来源 revision/conversation_revision 改变、版本表插入故障后双库释放与持久投影回滚。新的显式操作可以在修正来源或清除测试注入故障后执行，这不代表后台自动重试。个人必要跨项目来源被继承时，更新版本可以包含旧范围依据与新正文依据，来源条数按实际保存版本精确断言，不能为了匹配旧数量丢弃范围证据。

旧格式约束和 nullable 验证字段的测试直接针对历史 schema 和存储读取，仍服务备份/迁移；不再通过已退役的 MemoryAccess.query/_mutate 制造测试数据。旧内部 helpers 仍有未迁移消费者，清单保存在 build/spec143bo-s6/migration-r4/legacy-lifecycle-consumers.json；这些消费者全部迁移前不声称旧链清理完成。

显式词法与只读检查也迁至 query_wiki：对实际 content 解码后检查正文/条件/来源，不把只含定位字段的 items 当成旧完整记录。保留技术锚点、扩展不得替换原锚点、Top-K 后去重不补齐、条件/basis/代码空白差异、陈旧版本/索引、SQL 字面量和查询复杂度断言；读取不续期。中文/emoji/NUL 用真实 700 token 预算分页后逐字拼回，另查 byte 上限和跨范围 cursor。错误 owner 现在在 Wiki 写入时直接拒绝并检查零新增，而不是依赖读取时过滤结构错误的跨库行。保留旧 seed/query/add_source helpers 只为尚未迁移的明确测试消费者，不能因此恢复旧产品入口。

### 后台比较行为用例迁移

固定比较场景继续使用历史输入和旧协议哈希作为对照。测试改走归档来源 → A 绑定证据 → B 读目录/页 → 提交，而旧比较协议文件保留原样。旧协议的“完整补证续期”在 Wiki 通过明确的 confirm 表达，局部 supplement 保持正文和时钟。过期条目不能从当前目录发现，尝试读取或更新时不得写入或续期。测试核对版本、到期、原文、独立概览和失败计数；来源验证、版本冲突与事件配对继续由真实存储和后台执行链断言。

当旧来源已从会话归档清理，补证仍可使用新用户来源。B 只依赖已经完整读到的记忆页和当前快照。持久化保留已有来源指针，不补造已经丢失的原文；模型即使在 supplement 附带正文，程序也继续使用旧正文。拒绝 update 的分支保留原版本并记录失败，概览独立保存。SDK 测试保留四种适配器、两种结构化输出模式，记录 A、B 读目录、B 提交三次调用，并核对保存正文及真实来源。
