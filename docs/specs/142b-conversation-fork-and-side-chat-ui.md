# Spec142B：前端交互与参考模块复用

状态：2026-11-01 方案稿，未实施。持久分叉环境方向已确认采用当前工作区复制；具体范围及辅助按需准备随[主Spec](142-conversation-fork-and-side-chat.md)与[142A](142a-conversation-fork-and-side-chat-contracts.md)审阅。本文件是交互合同及结构示意，不是产品截图。

云端基础交互/任务状态/结果与连接器先按[Spec143D](143d-web-and-cli.md)实现；本稿旧A环境字段/方法仅为历史接线参考。分叉和辅助入口仍为后续独立功能，不并入B首版。

## 1. 设计取向与当前前端

以聊天正文为主，分叉是低频消息动作，辅助对话是可随手打开的侧面交流区。借鉴 ChatGPT 的动作层级与 ZCode 的窄边框、弱分隔和紧凑工具条；复用当前字号、主题和消息能力，不把本功能扩成全站重设计。

当前项目已经有 React 19、CSS Modules、浅/深/系统主题、Markdown/GFM/代码高亮、真实工具状态/差异、上下文面板、活动侧栏、图片输入与审批。它们是本次基础，不是需要从ZCode重建的模块。`useConversation(api, active)` 已接受独立WebApi；`WebApi.forScope`已有不同scope客户端入口。

当前 UI 的改进集中在三个真实问题：最后回复动作缺少分叉；加号缺少辅助入口；现有侧栏需要清楚表达当前显示的是运行活动、子Agent还是独立辅助对话，避免消息、审批和停止指向错误对象。

## 2. 分叉入口与来源显示

在**主会话最后完整成功回复**的现有动作行加入分支图标，tooltip和可访问名称均为“分叉为新会话”。按服务端 `conversation_actions.fork` 显示可用性，不通过前端“反向找最后ai文本”独立决定。流式文本、摘要、旧分页消息、工具结果、子Agent和辅助面板不出现可点击分叉入口。

鼠标悬停/键盘focus时显现，触屏保持可发现的更多操作入口；不增加每条消息常驻的大按钮。保留复制与重生成原顺序，分叉相邻但图标和说明不同。无可操作回复时不渲染虚假按钮；状态变化时以可见说明解释当前动作暂不可用。

正常交互：点击后显示“正在复制上下文/捕获工作区/校验文件/创建会话”等真实阶段，同request_id禁重入；成功刷新侧栏并打开新会话，聚焦空输入框。当前源会话准备期间发送/重生成/压缩暂不可用，提供取消创建，不伪装成模型任务运行。创建不自动发送文字、不复制未发草稿、不触发模型，原草稿保留。

新会话临时本地标题为“分叉 · 原标题”，原标题为空则为“分叉会话”，使用现有长度限制和本地标题策略；名称不承担身份与幂等用途。侧栏是普通会话行，增加轻量来源标识，不新增树形层级、计数徽章或版本轮播。

新会话正文顶部显示一行“从《原标题》的回复分叉”，可点击回到源会话的对应回复。源不存在或无访问权限时显示“来源会话不可访问”，不展示内部路径，也不阻止新会话继续。来源历史中的费用和附件限制按142A标注，不冒充新发生的执行。

409后在动作附近提示“会话内容已变化，请同步后再分叉”，保留原草稿，不自动重试另一回复。响应丢失只用同request_id查结果；未确认前不在侧栏插入乐观假会话。已创建但打开失败提示“已创建，打开失败”，仍可由侧栏进入，不能再创建第二份。

## 3. 辅助对话入口与布局

主输入框加号菜单增加“辅助对话”，副文案“参考当前上下文，关闭后丢弃”。与附件、压缩、Skills等现有菜单项统一高度/焦点/禁用样式。本期不新增斜杠别名或新的全局快捷键，避免扩大指令系统范围。

无稳定上下文时禁用并显示“完成一轮对话后可打开”；主会话运行时允许打开，说明“参考上一轮完整对话，不含正在生成的内容”。菜单动作使用当前服务端snapshot_token，创建冲突时刷新状态并提示，不悄悄选一个新上下文。

每个浏览器页面最多一个辅助实例，服务端另有全局数量与RAM准入；不提供辅助标签组或嵌套。已经打开时菜单显示“显示辅助对话”，点击恢复同实例；折叠后不是新建。切换主会话/项目视为关闭当前辅助实例，先按其收尾合同处理，成功后完成切换；有未发草稿时复用丢弃确认。

桌面结构示意：

```text
┌──────────┬───────────────────────────┬──────────────────────┐
│ 项目/会话 │ 主会话 A                  │ 辅助对话       ─  ×   │
│          │                           │ 参考：上一轮完整上下文 │
│          │ 正文、工具卡片             │ 关闭后丢弃             │
│          │                           │                      │
│          │ 最新回复 [复制][重生成][分叉]│ 仅显示本实例新消息     │
│          │                           │ 真实工具事件/本实例审批 │
│          │                           │                      │
│          │ 主输入框                  │ 辅助输入框             │
│          │ [+] … [主任务发送/停止]    │ [+] … [辅助发送/停止]  │
└──────────┴───────────────────────────┴──────────────────────┘
```

主区与辅助区有独立滚动和输入。辅助右上角分别为“折叠辅助对话”和“关闭并丢弃辅助对话”；用tooltip和aria-label区分，不能都叫关闭。折叠后在右侧保留窄恢复入口及当前运行/待审批标记，组件、lease及事件订阅保持挂载。

使用现有右侧面板容器；辅助、子Agent和活动面板占用同一展示槽，一次只显示一个面板。切到活动/子Agent只折叠辅助，不销毁实例；辅助审批到达时出现明确的辅助待审批标记，用户可点击切回，不把审批弹到主会话面板。

推荐布局常量属于本期设计值：窗口宽度至少1200px时侧面板默认420px、最小360px，主聊天可用宽度至少560px；不足时先沿现有侧栏折叠策略，仍不满足则使用覆盖面板。375px窄屏使用全屏辅助面板，保留“返回主会话（折叠）”和“关闭并丢弃”两个动作，不能把返回当销毁。

不增加拖拽调宽器或布局偏好持久化。所有布局值集中在组件CSS/现有uiSettings中，颜色与字号消费theme tokens；URL、端口和执行环境仍从API获得。

## 4. 辅助内容、工具与输入

初始面板只显示标题、上下文来源与简短提示：“可以继续问刚才的话题。这里的对话不会加入主会话，关闭后丢弃。”不复制一屏历史、不生成虚构欢迎回答、不放示例聊天冒充已有内容。

参考上下文包括实际snapshot时点说明；主会话继续回答后不改标签指向的快照。继承消息不在面板时间线中展示，也不算未读消息。模型仍能读取它们；上下文查看若开放，须明确“继承参考”和“本次消息”两种真实来源。

复用 `Conversation`、`ToolCall`、`MessageImages`、`Composer`、`ApprovalPanel`、模型选择与现有发送/停止控件；面板传入自己的scope/sid/run。不得复用父chat对象的send/stop/approval回调。工具错误、未知结果、Write/Edit差异、图片加载失败沿原投影，不为了视觉紧凑隐藏关键状态。

辅助输入支持当前图文和模型/工具选择；实际禁用能力如子Agent、记忆或环境管理不展示为可启用项。加号菜单只显示本实例有用的附件/现有上下文动作，不提供再开辅助/分叉、重命名/置顶或历史导出。长输入、代码块、审批和图片不撑破面板。

修改工具的审批区显示“辅助对话请求”及真实目标和影响范围。父会话同时待审批时，两者各显示自己的批准/拒绝/取消结果；焦点与键盘提交不能跨区。辅助面板停止按钮只终止辅助任务。

Sandbox分叉输入区显示“独立沙箱 · 复制当前工作区”，来源详情展示文件捕获时间、真实commit/树/排除清单。说明“带上已有文件改动，之后两边独立；不复制后台进程或工作区外软件，Git暂存分组不承诺保留”。不要让用户误以为只复制了最初仓库，也不能说已克隆整个容器。

辅助打开时只有文字快照；首次发送前按需复制工作区。源忙时显示“主任务运行中，辅助工作区尚未复制，可先询问已有上下文”，工具列表标注文件/Shell暂不可用；允许的联网仍可用。源闲后下一次发送可准备，成功显示“独立临时沙箱 · 文件快照于…”，同时保留文字快照自己的时点；关闭将清理临时沙箱。准备失败保留输入与真实错误，不能自动从初始输入或Host重做。

Host项目按真实事实显示当前工作区名称；帮助说明“两个对话使用同一工作区，已批准的文件修改会保留”。不能用“独立对话”暗示文件隔离。联网/环境不可用时显示真实错误，不显示虚构ready状态。

## 5. 生命周期与异常交互

| UI状态 | 展示及允许动作 | 数据合同 |
| --- | --- | --- |
| creating | 加载状态，可取消；输入禁用 | RAM文字未ready前不发送；迟到创建成功须关闭旧实例；文字ready不代表文件环境ready |
| active | 正常时间线/输入/自己的审批 | 只消费当前scope/sid/实例generation事件 |
| collapsed | 恢复入口、运行/审批提示 | 不abort lease、不丢草稿、不重seed |
| closing | “正在停止并清理…”；禁止新发送/审批放行 | 幂等收尾；不创建同源第二实例 |
| closed | 移除正文/草稿/图片和恢复入口 | 下次创建全新身份和快照 |
| cleanup_unconfirmed | “收尾未确认”及重试收尾 | 不宣称已停止或已清理，不恢复发送 |
| lease断开/刷新 | 提示本次辅助已结束，可重新打开 | 不自动恢复旧聊天，旧响应不得进新实例 |

主输入框有草稿时打开/关闭辅助不影响主草稿。关闭仅在辅助存在未发送文字/图片时询问是否丢弃，运行中的对话直接停止收尾。页面/应用退出可能无法展示收尾结果，服务端仍根据lease与操作拥有权处理；文案不能承诺远端即时终止。

创建失败把失败提示放在辅助入口附近，主任务不中断。发送失败保留本实例未发输入，沿当前重试语义；关闭身份失败不能用重新POST创建来恢复旧对话。导航过程中收尾失败保持原主会话，显示原因并允许重试；不把用户意图悄悄切换到其他源。

## 6. 视觉、无障碍和状态管理

沿用现有 `--surface/--surface-soft/--sidebar/--line/--text/--muted/--danger`；正文16px、控件14px、元信息13px、caption12px，消费已有字号变量。圆角消费6/8/12/16/24/full序列中的已有用途，不新建一套design system，不引入ZCode字体资源或硬编码它的色值。

ZCode值得借鉴的是弱化大面积卡片边框、将常用控件靠近输入、工具过程紧凑折叠、把辅助内容留在侧面；本项目只对新面板/动作行应用这些规则。浅/深模式要分别检查文字、分隔线、hover、disabled和审批状态，不以主题能切换代替可读性验收。

加号菜单沿用现有键盘↑↓/Enter/Escape及focus返回。打开面板后聚焦辅助输入；关闭后返回触发加号按钮；折叠恢复后保留光标位置。覆盖面板按现有对话框模式管理焦点，桌面并列面板不困住主输入框。Escape先关内层菜单/弹层，再折叠辅助，不直接丢弃对话。运行状态用有文字标签的aria-live，不以颜色作为唯一信号。

拟新增 `useSideChat`只管理create/lease/close、实例generation与临时WebApi；消息流、历史及发送继续用现有 `useConversation`。`SideChatPane`只做布局与装配，不再实现一遍工具卡片或网络重连。当前useConversation为474行，不继续把整套side生命周期塞进去；新增职责放独立模块，改动后各生产文件不超过500行。

实例key必须包含scope_id与sid。取消/迟到HTTP、旧SSE、旧图片加载、关闭后的审批ACK均检查实例generation；不以标题或selected parent id作为实例key。当前 `browserConnection`的sessionStorage保存只是主连接信息，辅助不得调用它把temp scope覆盖主连接；使用 `api.forScope(tempScope)`。

## 7. ZCode 可借鉴与可复用范围

源码版本固定为 `a60ba6a7e5a06742270ca605f5d2cc2766afa7e1`。本项目React+CSS Modules与ZCode内部UI包的依赖/样式方式不同，不能因两边都用React就整块复制。

| 对象 | 真实耦合 | 本期结论 |
| --- | --- | --- |
| `useComposerToolbarFit.ts` | 约132行，React/DOM测量，按data属性和优先级收起控件；依赖特定toolbar DOM/CSS | 可局部移植的候选；先用现有换行/溢出策略，只有窄面板实测溢出且现有办法不足时才移植 |
| 通用button/tooltip/popover | Radix、class-variance-authority、cn、Tailwind等 | 借鉴交互和状态，不为几个按钮引入整套依赖；复用项目现有菜单/tooltip |
| `SelectionSideChatPane` | 复用巨型SessionPane及内部session/project/协议状态 | 借鉴“同一消息组件装进侧栏”的组织，不直接复制文件 |

## 8. 可见验收

至少检查1440px和375px、浅/深主题、鼠标/触屏/键盘、空/长文/代码/图片/审批/工具失败。所有截图使用明确测试夹具或真实已授权运行结果，不将示意数据标成业务运行。正常、折叠、关闭、待审批、收尾未确认各有可检查状态。

前端通过条件包括：主副草稿和流不串；最后回复才有正确分叉动作；分叉后原会话可继续；辅助不入侧栏；折叠恢复同实例；关闭再开新实例；刷新不复活；任一停止/批准不会控制另一run；窄屏无横向溢出、可触达关闭和发送。对应自动及手动证据见[142C](142c-conversation-fork-and-side-chat-acceptance.md)。
