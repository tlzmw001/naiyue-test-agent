# Spec143BP-S4：整体与 Windows 验收

日期：2026-11-18。状态：待执行。前置 S1—S3。此片负责证明产品主链和失败保护成立，不追加清理类别、不做拷贝优化、不部署云端。

## 1. 证据分层

1. 单元/故障注入：期限、身份、依赖、锁、结果与释放的确定性断言。
2. 集成：真实本机服务、实际临时目录和 SQLite、认证 HTTP、并发消费者与断线查询。
3. 原生 Windows：真实共享句柄、长路径、Unicode、只读/权限与父目录操作。macOS 上 monkeypatch `os.name` 不能代替这一层。
4. UI：真实后端删除结果进入窗口，不以 mock 成功当作产品验收。

不需要模型调用或云端 HTTP；验证过程中应断言/记录这两者均为零。若 Windows 执行环境缺失，只报告对应证据未完成，不改写为全部验收通过。

## 2. 隔离夹具与安全范围

每次验收在专用临时 data_dir 创建 registry、P1/P2/P3 和 chats 库，创建真实格式 marker/包/回执。使用 `os.utime(ns=...)` 设定时间，业务时钟可注入；不用 sleep 构造日期边界。

- P1：已打开且有活动运行/后台进程。
- P2：仍登记、未打开，含过期与未过期归档/包。
- P3：先登记再移除，受管目录留下但本次不可扫描。
- chats：两个持久会话，其中一个不加载 actor；附加一份无会话行孤立目录，证明不扫描。
- 外部诱饵目录：放置普通项目文件、下载成果、日志和图片样本，建立可识别的链接/路径替换测试；预先保存哈希。
- 至少一份旧 receive/交付依赖和一份已 ready 的新附件，验证保护与可释放区别。

只删除该夹具明确列出的受管数据，测试收尾沿 TemporaryDirectory；不触碰真实 data_dir、工作区资产、Docker 容器和云端包。无法安全建立某 Windows 边界夹具时报告未验证，不偷换为简单路径测试。

## 3. 必过矩阵

| 组 | 场景 | 必须观察到 |
| --- | --- | --- |
| 时间 | 7/3 天前一纳秒、相等、后一纳秒；future；低精度文件系统 | 只删严格早于边界且无依赖的单元 |
| 分组 | raw 旧/text 新；archive 旧/upload journal 新 | 整组保留，目录 mtime 不影响 |
| 范围 | 已打开、未打开、移除、普通会话、孤立目录 | 前两者及仍存在普通会话参与；其余不扫描 |
| 冷读 | 缺模型配置、未加载模型、历史 DB 旧格式/恢复标记 | 清理不初始化模型、不迁库；无法验证则保留并说明 |
| 并发 | 已运行/后台 writer未关闭/上传/CLI读/恢复 | 原工作不中断；清理明确跳过 |
| 竞争 | 枚举后移除/改名/目录交换；新运行与清理同时准入 | 单一明确先后关系，不能穿透预留 |
| 锁 | 两上传并行；捕获与上传并行；清理获取失败 | 读者并发保持，清理不等待读者网络；失败释放已取锁 |
| 历史 | 旧代码交付、已完成可继续使用的基线 | 必需包和来源回执保留，真实消费者可继续读取 |
| 失败 | 枚举/stat/JSON/权限/unlink/rmdir/同步/控制记录故障 | 明确对象、步骤、原因；计数准确；安全范围继续 |
| 退役 | rename前/后中断；archive删后剩元数据；重新捕获同 ID | 无半包进入复用，旧残留不删新包，无自动启动删除 |
| 服务 | 重复 POST、错 ID、断线、GET、换实例、正常关闭 | 一次执行；可查询；未知不重发；资源最终释放 |
| 资源 | 扫描/时间/结果容量边界 | 显式未完成，后续单元不执行，已发生失败无静默截断 |
| UI | 折叠、375px、空会话、部分失败、项目切换、刷新 | 入口可达，结果与后端相同，无第二次 POST |
| 资产 | 会话/图片/项目/保存成果/日志/备份/云目录 | 对应哈希/DB 记录不变，临时测试业务状态按预期 |

故障检查在测试末显式断言，不能把断言放进被业务异常隔离吞掉的回调。并发使用 Event/barrier 或状态查询，验证锁竞争的先后，不依赖 50ms 时间窗。

## 4. Windows 原生专项

最少覆盖 Windows x64 原生 Python；专用工作目录含中文、空格和非 BMP 字符。

1. 真实超过 MAX_PATH 的受管路径，通过当前 windows_api_path 操作；盘符根边界、UNC 路径转换。UNC 真实文件操作需有可用测试共享，否则分别报告转换已测/真实共享未测。
2. 用 CreateFileW 打开候选且不共享 DELETE，触发真实 WinError 32；窗口显示原文件与原因，其他项目继续；关闭句柄后再次主动清理成功。
3. 为夹具设置只读属性，删除明确失败且不自动清属性；用户模拟手动解除后新请求成功。ACL 拒绝只在隔离夹具且可恢复时测试。
4. junction/symlink/reparse point 不跟随；外部诱饵哈希不变。目录替换竞争在父句柄保护下被拒绝或变成明确跳过。
5. 验证目标文件/子目录自身句柄关闭顺序，父目录保护仍在；退役后输入新捕获可用，旧 payload 可下次清理。
6. 共享 readers.lock 的两个独立进程可同时读；第三个独占清理立即失败。读者退出后显式新请求成功，文件锁句柄无继承泄漏。
7. 保留旧 `changed_store_fields` 的 fstat/lstat ctime 差异回归；必要同步不重现只读 fsync/EBADF，不忽略注入的真实 IO 错误。

不通过自动重试、清除权限或关闭用户进程让测试“通过”。记录 OS/Python 版本、文件系统、完整命令、退出码及所用夹具范围。

## 6. 对照 Spec 收尾

- 每条外部接口、配置字段、占用入口、错误明细和 UI 动作均能指出真实生产调用者。
- 复查 cold path 没有 ProjectStore 初始化、模型准备、迁移/备份等隐含副作用；只读扫描不是用户历史重写。
- 复查任务/附件读取保护覆盖 CLI 与旧交付，不把 memory-only busy 当跨进程保护。
- 确认现有 CLI 清理、云端结果轮换、接收材料、日志、备份、诊断、Runner 行为未被改变。
- 缓存失败记录与 readers.lock 的新增文件均有明确所有权和保留规则；没有新增无限增长的成功清理日志。
- 更新当前用户说明和 handoff，明确手动触发、7/3 天、历史详细输出可能不可读、失败处置与重启未知边界。
- 回退 UI/服务功能不会触发任何恢复性删除；已经删除的缓存不承诺找回。旧业务事实不迁移，必要依赖事前保护。已退役残留由当前支持该格式的显式清理处理，旧版本不得猜测它的含义。

验收退出条件：确定性测试、认证服务集成、前端构建及要求的 Windows 原生矩阵都有记录；缺证据的项明确未完成。云端回收由用户后续云端优化完成，不阻塞本机切片，也不作为本片验收通过项。
