## 1. 先用一个例子理解要实现什么

旧记忆 M17 写着“本项目本地回归使用系统 Python”。用户现在说：“以后本地回归统一用 `.venv`，CI 保持原样。今天先试试关代理。”

1. 程序先把真实用户消息、助手动作和配对工具结果整理成有关系的输入，为可引用的原文片段编号。
2. A 提出“本项目本地回归使用 `.venv`”，引用程序提供的编号；“今天试试”不应被概括成永久规则。
3. 程序按“本项目的本地回归环境”查旧记忆，不强制旧记忆也必须含新值 `.venv`。
4. B 同时看新证据和 M17 正文，判断是否更正同一事实、是否受 CI 条件限制、结论是否得到原文支持。
5. 程序再次检查引用、权限、来源版本、遗忘状态和 M17 版本，满足条件才保存 M17 的下一版本。

如果 B 超时，本批记忆直接跳过；如果 M17 在提交前被别的操作改过，也直接跳过。不会重做 B，不会另存一条新记忆绕开冲突，不会用 candidate 保存失败材料。A 已独立保存的合法概览可以保留。

用户下一次同时问“跑本地回归，另外检查 TC-99 页面”时，前台分别查询两件事，再在原条数与 token 预算内合并。这里不调用额外模型。

## 2. 分片入口和实施顺序

| S1 | 原文如何保持关系并准确引用 | [对话输入与证据编号](143bm-01-conversation-evidence-input.md) | 完整交互优先、自然边界、工具配对、证据编号和唯一 binder |
| S2 | 同一消息的多段证据如何保存，删除和到期后如何处理 | [证据身份与生命周期](143bm-02-evidence-lifecycle.md) | 来源属性迁移、消息/片段身份、部分确认不整体续期、公开读取边界 |
| S3 | 新信息如何找到应比较的旧记忆并安全落库 | [事项检索与批量比较](143bm-03-proposal-comparison.md) | A→查询→B→硬门禁；无重试；概览与记忆独立成功 |
| S4 | 一条长问题中的多件事如何分别召回 | [问题拆分与整体验收](143bm-04-query-recall.md) | 有限查询、版本一致性、预算内合并、联合质量与成本验收 |

```text
S0：固定数据、旧源码指纹、calibration/validation 基线
 ├─→ S1：输入/编号 ─→ S2：证据/迁移 ─→ S3：查询/B/提交
 └─→ S4：前台查询/合并
                      ↓
        候选冻结 → 隔离旧版 holdout 基线 → 候选 holdout
                      ↓
            全量工程验证 + 真实语义/成本报告
```

S4 的工程实现可在 S0 后独立进行；它的整体验收要等 S1–S3 接好。首轮按 S0→S1→S2→S3→S4 执行最易审阅，不要求同时推进多条实现分支。

S1 可以先在既有单阶段 runner 中接入新输入/引用协议，验证输入收益；S2 前不能宣称同消息多 span 已完整持久化。S2 的后台 confirmation_scope 参数在 S3 才有正式消费者，单独写出参数不算该能力 L3 接线完成。
S3 切换为最终两阶段链时同步删除旧单阶段模型 schema、批次级查旧项和直接提交分支；不长期保留双算法开关。旧测试、探针与适配器迁到真实新链，保留原异常/顺序/来源断言。

## 3. 已确定的共同边界

| 事项 | 本轮实施规格 |
| --- | --- |
| 失败处理 | 保留原设计：失败跳过、无后台业务重试；没有恢复队列、持久提议包、提交回执或继续入口 |
| 两阶段 | A 负责概览和事实提议；有有效、可完整装入的提议组就做一次 B，无旧项也复核支持关系 |
| 零有效提议 | 可以保存合法概览，B=0；不是调用 B 来判断是否还要继续调用 |
| 自动生效 | 充分新证据继续允许自动生效；推断/未解决冲突可按既有规则成为 candidate，不新增逐条人工审批 |
| 模型与程序 | 模型判断语义；程序核查来源、身份、版本、权限和保存。精确引用不证明概括一定正确 |
| 删除会话 | 记忆正文按原规则留存，原会话引文不可展开；不能用保存 quote 绕过源数据删除 |
| 遗忘记忆 | 删除该记忆全部版本/来源/索引并保留消息级抑制；在途旧来源不能重新生成它 |
| 旧证据不可用 | 不强行删除有效正文；新证据独立足够时可更正旧项，旧正文不能冒充新证据 |
| 适用条件 | 沿现有 machine/module/target 与正文限定；不新建条件推理引擎 |
| 前台检索 | 最多少量完整查询，默认4；不新增模型、向量库、词性服务或全局阈值放宽 |
| 配置/运行框架 | 延续现有 MemorySettings、SQLite、Python＋LangChain create_agent 及模型适配，不增加供应商/依赖 |

“不同条件可以并存”不等于两条都一定自动 active。若本地/CI 只在正文中区分，当前结构化 known_conflict 仍可能让新项保持 candidate；首版保留这条保守门禁并记录在评测中，不让 B 绕过或伪造 subject 来避开检查。

scope 表示记忆归属与可访问空间（workspace/personal），不是“这条事实到处适用”。personal 正文可沿原权限跨项目召回，其原始引文仍受来源项目限制；其他项目 workspace 记忆不能因此被读取。字段未知也不代表适用条件已被证明通用。

## 4. 正式调用链和数据交接

当前后台仍沿 `MemoryJobs.request/after_finish → worker → memory_job_runner.drive` 接纳和执行；主 Agent 必要保存成功后才能释放真实归档范围。登记目标不是全部处理成功的凭据。

```text
真实聊天归档
  → S1 build_batch / model_batch
  → A：overview + proposals
  → S1 bind_proposal_evidence
  → S3 comparison_candidates / 分组装包
  → B：证据支持 + 新旧关系 + confirmation_scope
  → S3 严格校验并编译 MemoryInput
  → MemoryAccess.commit_comparison
  → S2 commit / 来源重验 / 单库事务 / MemoryWriter.save
```

| 交接数据 | 生产者 | 消费者 | 唯一责任与持久性 |
| --- | --- | --- | --- |
| EvidenceUnit / E 编号 | S1，基于可见归档事实 | A、binder | 原文、角色、真实位置、关系由程序建立；编号仅本批有效 |
| MemoryBatch / coverage | S1 | runner、概览保存 | 新读范围、重叠及遗漏分开；真实推进位置不是模型自报 |
| BoundProposal | S1 binder | S3 | sources、evidence、context_units/context_complete 唯一从程序映射产生 |
| P 编号 | S3，按 A 原数组位置 | 查询分组、B、决定编译 | 只在任务内存存在，不是数据库 candidate |
| O 引用/旧项版本 | S3，受权限保护的真实查询 | B、提交校验 | 只有本次给过的目标才可写；版本冲突直接失败 |
| confirmation_scope | B 提议、S3校验枚举 | S2内部提交 | whole/partial/unknown；不是用户可填的公开字段 |
| 已保存来源 | S2 | 生命周期、source_reference | 消息级身份用于新确认/遗忘，span身份用于保留不同片段 |
| 前台 query plan | S4 | MemoryAccess.query、装配器 | 无持久状态；query offset不是证据偏移 |

必需的限定若只出现在辅助 context，却未成为正式引用，跳过依赖它的提议；B 不自动补来源。辅助前文不能给旧事实续期，也不能独自触发一批新整理。

公开 `MemoryInput/MemorySource`、`MemoryAPI.query` 与前台 `prepare_memory_parts` 的签名/响应合同保持。内部更改集中在 S1 的批次绑定、S3 的受控比较入口、S2 的 keyword-only 确认策略；不要把可 import 的旧内部函数升级为兼容承诺。

## 5. 成功、失败与候选如何区分

| 情况 | 处理结果 | 不能发生的替代行为 |
| --- | --- | --- |
| A 整体响应损坏/拒绝/超时 | 本批无新概览或记忆，记录失败范围 | 从残缺文本拼概览、增加修复调用 |
| A 概览有效，一条提议无效 | 概览和其他独立有效项继续 | 把无效提议存成 candidate |
| 旧项查询失败/截断/必要材料装不下 | 跳过相关提议组 | 将失败当“没有旧项”后新增 |
| B 输出支持充分但有未解冲突 | 按既有状态规则保守处理 | 宣称 candidate 已自动可用 |
| B 整体失败 | 本批相关记忆全部跳过，已保存概览保留 | 退回 A 直接保存 |
| 一组提交 CAS/来源/权限失败 | 相关决定跳过，保留独立已确认成功 | 重读再比较、改存新 ID、跨库补偿重放 |
| 后续来源批次可独立理解 | 在原任务剩余预算内处理新范围 | 下一批重复前一失败范围 |
| 全局超时、停止、进程重启 | 结束内存任务；可观察遗漏 | 恢复旧提议或后台补跑 |
| 前台一条查询失败 | 省略该查询，其余计划查询独立执行 | 全量 list 兜底、追加查询/模型调用 |

合法 duplicate/unsupported 是已完成判断；failed/skipped 是未取得该项成功结果，统计不能混为“原文没有记忆”。必要保存须等 settled 再计数，观察故障不得改变已提交结果或覆盖主异常。
既有用户显式重新整理历史是一项新的请求，仍重新读取当前合法来源、重新受预算限制，不承接失败任务的内存状态。
SDK 既有传输重试配置不在本片改动范围；业务逻辑调用和实际 SDK attempts 分别统计，受原任务期限限制。

## 6. 预算和配置总表

现有默认保留：每任务最多3批、总时限300秒（含等待）、单次输入16000/输出4096 tokens、每批最多8提议、related_limit=8、注入2000 tokens。模型自身更小的上限优先。
最终每批 A≤1、B≤1，任务最多 `2 × max_batches` 次逻辑调用，默认3批即最多6次；查询失败不会新增逻辑调用。预算先算 schema/system/概览/关系元数据；不以只数正文证明请求一定装得下。

以下是待实施的可选配置初值，旧配置省略时采用默认，不是已测量的最佳值，也不是本轮对用户真实配置的修改：

| 字段 | 默认与合法范围 | 责任片 |
| --- | --- | --- |
| batch_max_messages | 128，严格整数1..1024 | S1 |
| batch_read_chars | 65536，1024..262144 | S1 |
| batch_overlap_chars | 600，0..8192，且≤batch_read_chars//4 | S1 |
| comparison_queries | 2，1..2 | S3 |
| comparison_query_chars | 256，32..512，且不超过公共上限 | S3 |
| comparison_query_terms | 64，8..128，且不超过公共上限 | S3 |
| comparison_material_bytes | 65536，4096..262144 | S3 |

所有新整数拒绝 bool；非法配置沿现有 memory_settings_invalid 禁用记忆并记录诊断。配置必须沿 load_settings→冻结任务/注入设置→实际消费者接线，同步现有简版/完整示例及工具说明；不能只声明字段。

另会话 Spec143BL 的 token 校准尚未实施，本规范使用当前估算/输出适配合同，不私自依赖它的拟议算法。

## 7. 数据迁移和回退边界

S2 当前规划项目 schema 23→24、个人库 user_version 2→3、记忆格式2→3；实施前重新核对最新迁移版本，若被别片占用，先同步本片编号再编码。

升级前停止共享这些库的所有旧写入进程，使用已有备份机制取得每个库内部一致的备份，并记录同一暂停窗口的库身份/版本/备份路径。不新建跨库事务、备份平台或自动成组恢复服务。

## 8. 实施文件范围与收尾责任

必要行为依赖现有锁/事务顺序。首版不新增锁；实现若改变锁作用域、间接嵌套或新预留标记，先同步 [lock-hierarchy](../lock-hierarchy.md) 并补确定性并发测试，不能以“内部接口”绕过评审。
每片收尾扫描生产代码、测试、探针、序列化/DB映射及当前文档消费者；列出删除的旧入口和真正保留的调用者。历史 Spec 可保留，当前入口与 handoff 必须反映实际状态。
实现不得改真实 settings/.env、依赖版本或无关 MCP/课堂/前端工作。只在明确需要时同步原消费字段，不借机增加 Memory 管理 UI。

## 9. 工程与业务验收

先按各片的行为矩阵写失败测试并观察正确红灯，再实现；不能把文档检查称为 TDD。迁移同时覆盖新库、旧库、坏数据、重复打开和备份读取。失败测试必须断言真实写入状态、来源/版本以及调用次数，不能仅检查异常字符串。

源码完成后，除各片专项测试，使用当前仓库已有全量测试与标准构建入口。以下示例以本机支持的 macos-arm64 为目标；在新输出目录运行，不覆盖他人资产，不把本机结果当作其他平台结果：

```bash
.venv/bin/python -m scripts.native_assets --target macos-arm64 --output build/spec143bm/test-assets
PATH="$PWD/build/spec143bm/test-assets/bin:$PATH" .venv/bin/python -m scripts.ci_shards --index 0 --count 2 --output build/spec143bm/backend-0.xml
PATH="$PWD/build/spec143bm/test-assets/bin:$PATH" .venv/bin/python -m scripts.ci_shards --index 1 --count 2 --output build/spec143bm/backend-1.xml
npm --prefix frontend test -- --run
npm --prefix frontend run build
.venv/bin/python -m scripts.build_release --target macos-arm64 --output build/spec143bm/dist
.venv/bin/python -m twine check build/spec143bm/dist/*.whl
.venv/bin/python -m scripts.verify_wheel_install --wheel-dir build/spec143bm/dist --output build/spec143bm/install.json
git diff --check
```

标准脚本负责原生资产、前端与 wheel，不能用裸 python -m build 绕开它。上述本地构建/安装检查不是发布；未授权上传、部署或改真实运行环境。

S0 分三类证据分别报告：

1. **工程正确性**：硬边界、故障隔离、无重试、真实接线和迁移回归。
2. **真实模型行为**：A 提议、B 关系和证据支持的固定样本人工评价，不以另一模型自评作答案。
3. **最终效果与成本**：有效事实召回、误覆盖/误注入、candidate、跳过、token/时延及实际样本量；未过门槛如实记录。

首版96个合成场景，四套各24，按家族隔离校准/验证/留出。真实语义24条两次完整独立重复，单模型/profile 的旧基线最多48次、候选最多96次逻辑调用；单次探针≤24次，先检查最坏预算，旧12条回归另计。这里定义后续采样范围，不表示本轮已发请求或取得质量结果。
无模型或缺少人工审阅时，报告 semantic_pending/needs_human_review；不能因单元测试通过宣称错误记忆已消除。
