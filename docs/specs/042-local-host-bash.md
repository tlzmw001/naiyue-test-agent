# Spec 042：显式开启的本地宿主机 Bash

状态：2026-10-02，已实现显式开启的本地宿主机首片，并通过假模型、临时目录和 CLI 的确定性测试；真实模型/pytest 质量及 Pi 输出链等价尚未验证。用户确认工作区外读写不作为这一片的拦截条件。Spec 041 的 OS 隔离探针保留为将来隔离执行模式的验收，不能用本片替代。新发现的结果链差距见 [Pi Bash 对照](../research/pi-bash-result-chain-2026-10-02.md)。

## 当前链路与设计取舍

当前 CLI 的工具是工作区文件工具；运行层的 LangChain `create_agent` 把模型工具调用交给 ToolNode，`HumanInTheLoopMiddleware` 暂停需审批调用，应用层展示并恢复，工具收到可信会话工作区。本机 Pi `a69bef789` 的 Bash 用 `spawn` 在 cwd 运行本机 shell，cwd 不限制工作区外文件访问；AIAutoTest 的 Pi 权限扩展在 approval 模式对 Bash 设 ask，在 full_trust 模式设 allow。我们在本地单用户 CLI 采用同类宿主机执行，但不声称已有 OS 沙箱或多用户授权。

## 本片契约

- 只有 CLI 明确传 `--host-bash` 且指定 `--workspace` 时注册 `bash`；未开启保持现有工具集合。启动时提示此工具按当前登录用户权限访问宿主机文件和网络，cwd 不构成限制。
- 模型参数为 `command` 非空字符串和可选正整数 `timeout` 秒；会话工作区从可信运行上下文取得，用作 cwd，模型不能覆盖。单次命令默认 60 秒，最长 300 秒，命令和输出有输入/输出预算。每次 Bash 都经 HITL 审批，CLI 展示完整、转义控制字符后的命令及工作区；批准绑定原工具调用 ID、命令全文和会话工作区；拒绝不启动进程，重复或变化的授权不放行。
- 直接在宿主机执行 Bash；不做路径/命令白名单和工作区外限制。子进程只收到最小 PATH、HOME/TMPDIR 等必要环境，不继承模型 API 密钥或代理环境。环境清理降低误泄漏，不妨碍命令主动读取当前用户可访问的文件或访问网络。用户在审批前必须能看到完整命令。
- 同轮工具批次将 Bash 标记为 sequential。命令 stdout/stderr 分别有界采集，超过预算继续排空但不写无限缓存；成功或非零退出都以原 ID 回填包含退出码、截断标志和有界输出的 ToolMessage。参数错误、后端启动失败提供可行动错误。超时杀进程组并把会话标成结果待人工核对，禁止自动重放；运行中 `:stop` 沿用当前“本 turn 后停止”，不表示立即杀命令。
- 日志只记录调用 ID、run ID、退出类别、时长和截断状态，不记录命令、输出、路径或完整子进程环境。CLI 审批屏幕展示命令是有意给当前本地用户审查，不进入普通日志。

## 涉及文件与验证

新增 `agent_runtime/tools/bash.py`；工具导出与运行层审批规则、运行上下文、应用层待审批展示和恢复、CLI 开关与失败展示接线；相应新增工具与应用/CLI 测试；更新 README、future-work、handoff、project-plan。保持现有 `build_local_application` 公共签名、Read/Write/Edit 工具行为和默认 CLI 行为。

先写失败测试确认：未开启不注册、缺工作区拒绝开启；批准前及拒绝后没有副作用；批准后在可信 cwd 运行并把结果回填模型；工作区外临时文件可读写（这是本片刻意允许的能力）；授权无法跨调用或改变命令；参数/退出码/超时/超量输出正确处理；假凭证不会自动出现在子进程环境；日志不含命令/输出。然后实现最小能力，跑定向和全量 pytest、compileall、pip check。真实模型能否正确使用 Bash 与生成 pytest 的质量另测，不能由假模型测试推出。

本片仅用于用户明确开启的本地单用户开发。未来 Web/SaaS、无人在场的 Auto、执行不可信生成测试，以及跨用户场景仍需 Spec 041 的隔离、身份和权限验证；没有这些证据不得暴露同一个宿主机 Bash 入口。
