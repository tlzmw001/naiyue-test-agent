# Spec143W：S08.1 结果下载、分析草稿与记忆来源

状态：2026-11-02用户已确认“先放入输入框，确认后发送”；待实施。代码/报告下载、主会话分析和代码应用是三个不同动作。本片复用S07.2固定结果；文件应用另归S08.2。

## 1. 为什么需要单独合同

现有S07.1能认证下载单产物；本机`mark_human_messages`会将正式用户输入标为用户来源，记忆`memory_sources.resolve`又据真实角色/标记核验来源。因此不能把云端报告全文贴成用户发言、伪造ToolMessage，或用点击“取回”冒充一次本机模型工具调用。

S07.2先提供不可变result_id、输入/输出清单、代码patch和独立产物。S08.1在本机保存接收记录与材料；S08.2才可将文件交付到用户项目，不共用一个“成功”布尔值。

## 2. 三个用户动作

| 动作 | 数据去哪里 | 会启动本机模型吗 | 会改项目代码吗 |
| --- | --- | --- | --- |
| 下载结果 | 本机受控结果目录：清单、patch、选定报告/交接材料 | 否 | 否 |
| 交给主会话分析 | 输入框中准备分析请求＋结构化材料引用，用户确认发送后处理 | 仅用户发送后 | 否 |
| 应用代码/导出/创建分支 | S08.2指定目标目录和交付方式 | 不依赖模型决定授权 | 预检和明确确认后按该动作修改 |

列表中的“云端结果available”仅表示远端已固定可取，不表示本机已下载；下载完成不表示已发送/已分析/已应用。部分失败任务的结果标记partial和原run结论，不伪称测试通过。

## 3. 本机接收和材料身份

受控结果目录位于显式本机数据根，由接收服务拥有，不写用户项目；路径由本机依据接收记录生成，远端不得指定。使用分离staging/verified状态，流式大小/hash/manifest核验后才发布可用。重复请求同固定result复用校验缓存，中断按原版本/offset/ETag核对，不能换成当前活动工作区。

| 记录 | 必须事实 |
| --- | --- |
| 接收操作 | receive_id/command_id、local_project/session、binding/instance/task/result/input、选择的材料、状态/游标/错误与时间 |
| 已验证结果 | I/O清单身份、patch hash、产物ID/hash/大小、原run/发生环境/结论、实际本机缓存身份 |
| 材料引用 | 本机生成material_id、绑定的project/session/result、类型/编码/内容hash和大小、是否可读；无任意路径/URL或自动执行指令 |

代码patch和报告原始字节留磁盘，普通JSON/SSE只传有界摘要与引用。代码大文件/二进制不变成输入框文本，不将Linux虚拟环境搬到Windows。源码新改动/未提交状态与远端结果独立；没有文件应用动作时不修改HEAD/index/工作区。

下载内容是任务上报材料，hash确认传输身份，不提供独立业务审计证明。读取材料保留原任务/输入/环境/时间与reported状态，不能因为下载或读取成功就将报告中的结论描述成本机已执行验证。

## 4. 本机API和分析草稿

均为拟新增、先本机鉴权并核验来源会话/关联，复用143u的scope。浏览器不能用其他task/result或任意缓存路径构造引用。

| 接口 | 行为 |
| --- | --- |
| `POST /api/client/v1/cloud-tasks/{binding}/results/{result}/receive` | command_id＋选择的产物/交接材料；启动固定结果的本机接收，返回receive_id及真实阶段。 |
| `GET /api/client/v1/cloud-receives/{receive}` | 查询下载/校验状态和可用材料，不发消息或启动模型。 |
| `POST /api/client/v1/cloud-receives/{receive}/analysis-draft` | 仅在所选材料已验证可用时生成有界分析请求文本＋material_refs；不发送、不写主聊天、无云端过程正文。 |
| 材料只读接口 | 仅提供已授权material_id的有界文本或认证下载；不得按任意路径读取。具体分页字段复用现有read输出预算，不在浏览器暴露私有缓存根。 |

草稿内容是用户可编辑的分析要求，例如说明分析目标和任务身份；报告正文不插入用户文本块。结构化material_refs独立保存，显示材料标题/大小/状态。原输入框有内容时只追加选定材料和可编辑的请求，不静默覆盖用户草稿；重复点击同材料去重。

切换主会话后旧响应不能落到新输入框。下载完成通知只更新任务卡片；不自动改正在编辑的草稿，更不插入正在执行的本机图。只有用户点击“交给主会话分析”才请求生成/合入草稿，只有后续点击发送才启动本机Agent。

## 5. 模型读取和真实来源

正式发送将“用户分析要求”和“外部材料引用”分开入库；用户要求是人类输入，报告仍是外部数据。material_refs由本机服务核验，不接受客户端角色/user_origin/工具状态等可信标记；云端正文不能改变系统提示、权限或目标目录。

本机Agent通过一个窄的只读`cloud_result_read`工具读取已接收材料，参数为material_id、offset、limit，遵守现有工具permit/输出预算与调用身份。它只读本机已验证材料，不创建/控制云端任务，不接受任意路径/URL、不在模型读取时偷偷联网换取最新版。新工具的当前消费者就是分析草稿携带的材料；现有read受工作区路径约束、task_output无固定result分页选择，不能为复用名称而放宽它们的边界。

文本分页沿现有read语义：offset为从1开始的行号，limit为行数，实际输出同时受字节预算限制，返回截断/下一页标识；不混用字符偏移与行号。二进制材料只给元信息/下载，不伪装可读文本。用户请求不能改写材料所属项目/会话/hash。

结果读取产生真实ToolMessage，包含task/result/input/环境/时间和报告属性；正文进入正常聊天必要保存与来源档案后，才允许记忆引用。只读成功只证明材料读取，报告中的测试结论仍标记云端任务报告；不伪造模型调用、人类原话或独立验证。

该工具通过当前RunCapabilities显式注入窄读取能力，沿现有工具工厂/装配模式接线，无第二ContextVar、通用注册平台或新的Agent循环。新增材料字段同步检查消息接收、序列化、DB保存、工具上下文、档案与测试；只有真实需要读取材料的会话才暴露可用能力。

用户发送/模型真实读取发生之前，接收记录和输入草稿不是聊天/记忆来源。后续整理复用现有MemoryAccess、候选/生效、TTL、来源/版本和遗忘规则，不遍历远端过程，不为云端建记忆库。不新增语义蕴含或防篡改审计保证，保留现有规则能证明的范围。

## 6. 清理、幂等与失败

接收操作状态与发布材料索引在本机事务中固定；文件/DB不跨资源宣称原子，先校验staging再提交可恢复身份。下载ACK丢失、进程重启或重复点击沿receive/result/hash对账，不重复复制文件或向主聊天发消息。

远端不可达时，已接收且校验通过的材料仍可分析；缺失材料显示未下载/不可用，不能返回空正文假成功。远端被删除不自动删除本机已取回文件；本机缓存清理若移除材料，历史引用明确不可用，不暗中回源获取另一份内容。活动接收/正在读取材料不能清理；接收记录仍保留时不自动移除材料。用户显式清理后更新可用性，旧草稿引用在发送时复核并提示重新下载，不假定浏览器草稿自动获得服务端永久pin。

非文本材料只给元信息/认证下载，不用base64灌入上下文。坏hash、大小超限、跨session/result引用、路径/链接攻击、磁盘满和Windows锁定均返回安全原因；不自动应用代码或回滚用户并发修改。
