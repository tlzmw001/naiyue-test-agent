# Spec143D：Web、Windows 连接器与 CLI

2026-11-01用户确认的任务自动授权、外部网络开关与项目依赖合同见[143p](143p-s042a-task-capabilities.md)；该合同替代此前B逐工具审批计划，本机普通模式审批保留。

状态：2026-11-02按[143s](143s-local-session-cloud-delegation.md)修订为加号菜单手动管理云端任务、侧栏查看/续聊，暂不实现本机Agent自然语言提交，尚未实施；本期不实现Spec142分叉、辅助对话或主会话迁移。

## 1. 本机会话为主，云端任务独立执行

保留本机`nyt`、Agent、项目Host、主聊天与长期记忆。云端连接模块建立SSH和实例/协议握手，嵌入本机应用提供文件/任务API适配；不创建第二个主Agent或把主会话代理到云端。`nyt cloud`仍可提供同API的操作入口。

用户从主输入区加号菜单点击“云端任务”打开侧栏，不调用模型或创建容器；侧栏顶部“新增任务”，列表运行中优先且可找回已停止/完成任务。选择任务进入详情查看过程，底部输入框只发给该云端任务；主聊天继续本机执行。首版不注册模型创建任务工具，不以自然语言关键词自动路由。任务侧栏明确标记云端实例/任务和来源会话，不要求另开云端聊天窗口，不在主输入区切换执行位置。不同实例的任务/事件缓存以instance_id＋task_id分区，本机会话持久保存关联，不能凭同名项目/session或客户端传入ID取得控制权限。

云端project是逻辑分组；本地路径属于文件导入来源，不能用项目同名推断同一目录。首次显示真实空态与“新增任务”入口，不展示未接线能力。主聊天和任务侧栏复用本机同一份Web资源，Coordinator提供过程/控制/结果API，不另部署云端主聊天UI。

## 2. 连接器的安全与文件职责

沿用当前 bearer、X-Service-Instance、X-Request-ID和 Host/Origin 校验方式，不新建 cookie/session体系。连接器先校验浏览器本机身份/Host/Origin，再转发到唯一配置的云端实例；上游认证由连接器附加，不将云端所有者 token 送入任务容器或浏览器存储。

当前 `web/auth.py` 要求精确 Host/Origin；代理不能简单原样转发后放宽远端检查。连接器在本地验证通过后构造固定上游 Host/Origin，过滤不应透传的转发/认证头；远端按真实绑定入口验证。连接目标来自 profile，不接受浏览器任意 URL，禁止把连接器变成通用代理或本地文件服务。

拟新增本地路由`/api/client/v1/`负责输入捕获、目录句柄、持久委派/过程/控制适配、结果接收和本地交付。现有本机会话API继续本机执行；仅目标任务请求通过固定上游适配到`/api/cloud/v1/`，不把主消息请求透明代理过去。二进制独立流处理；OpenSSH沿已配置alias/key/agent，不保存密码或自动改写SSH文件。

source_handle/destination_handle 绑定当前本机用户、实例、规范目录和用途；远端只见 input_id/result_id，不得指定本机路径。Windows 目录选择/授权后再捕获，路径重解析点与文件变化由连接器检查。

## 3. 导入与准备流程

```text
加号菜单“云端任务” → 侧栏顶部“新增任务”
  → 复用已配置连接/模板/当前授权项目；缺必要配置时引导补齐
  → 选本地来源 → 看纳入与排除摘要 → 确认导入
  → 捕获/哈希 → 上传或缓存命中 → 云端校验 → 输入已就绪
  → 创建独立任务/环境、安装输入/Runner预检 → 任务详情可发送
  → 用户在底部发送首条消息 → 云端持久受理执行 → 可关闭本机
  → 云端独立执行/必要保存/自主保存结果
```

同 input_id＋模板新建多个任务会显示“复用输入”，并创建独立工作区；继续旧任务只显示启动/核对状态，不再次显示完整上传流程。输入冻结后展示简短标识、文件数、大小、捕获时间与来源摘要；不暴露真实密钥文件内容。

导入新本地状态首版创建新输入/新任务，默认全量归档；已有任务没有自动同步/覆盖按钮。同输入缓存命中才显示无需上传。项目依赖准备与容器/输入/Runner阶段分别显示，CRLF脚本或依赖预检失败给出明确文件/阶段，不伪报ready即所有测试已可运行。

准备阶段使用服务端真实阶段/字节和时间，不根据定时器伪造百分比。取消捕获/上传只取消所属操作；取消任务准备在服务端按 command_id 收束，对已经确认创建的专属资源做受控清理，失败/未知时显示需要核对。不能因为UI取消就无条件销毁既有环境或输入。

打开/关闭侧栏、选择已有任务不分配新环境；新增/重试沿原command_id去重。任务新建不自动复制全部聊天/记忆或调用模型，用户填写任务要求和必要背景。已有任务发送新消息复用原task/workspace/state；若环境已释放，先启动同任务环境，界面显示恢复准备，不另建任务。

主输入区继续服务本机聊天，不受云端准备/断线禁用；任务侧栏的补充输入按对应任务ready/恢复边界启用，断线保留任务草稿。上传未完成不能显示已接管；持久受理后本机退出不取消任务，依赖Windows中转的业务调用仍可能断开。模板依赖失败显示实际Linux阶段，不提示修改Windows Bash路径。

## 4. 会话、任务与连接状态

| 状态维度 | UI位置与动作 |
| --- | --- |
| 连接：在线/重连/不可达/协议不兼容 | 实例区域；重连不创建新任务，协议不符提示升级 |
| 环境：creating/ready/stopped/reconciling/lost/failed | 云端任务侧栏；启动/停止/检查对应明确命令，不改变主会话执行位置 |
| 运行：空闲/执行/停止中/终局 | 云端任务详情；本机停止本轮、云端停止本轮与停止环境分别标明对象 |
| 业务中转：已验证/未验证/不可达 | 任务依赖提示；不将API在线等同预发布可达 |
| 结果：捕获/校验/可取回/失败 | ResultReview；固定 result_id，不用当前变化目录冒充已冻结结果 |

`reconciling/unknown` 显示“正在核对原操作”，客户端查原 command_id，不提供会复制执行的“再发一次”快捷动作。结果保存失败保留错误与已完成聊天，不能显示交付成功。根/子任务和显式权限拒绝保留；B普通容器工具不逐次审批，不提供审批扩权按钮。网络由开发机部署策略约束，结果应用等所有者操作独立确认。

停止环境后可直接读已有聊天，不为展开历史启动 Runner。聊天分页、流式正文、思考/工具事件、用量、附件沿用现有组件/DTO，不让 B 迁移变成重写聊天产品。

历史来自Coordinator持久投影，任务尚未确认的保存/事件缺口单独显示；不以容器在线代替历史保存成功。自动空闲停止被运行、未收齐输出、必要保存或unknown阻止时展示具体原因，不能建议强制停止来清掉红色状态。任务上报的测试成功/退出码不是防篡改审计；所有者命令状态与任务执行观察分别呈现，显式deny仍生效。

侧栏详情必须显示云端Agent消息、工具调用/结果/错误、根子归属及可用日志/产物。工具失败但Agent仍运行时保持运行态；completed/stopped且保存确认后可向同任务补充指令；failed/blocked先按143q显式核对恢复；Runner崩溃/unknown先对账和确认旧写入者终止。不将所有错误映射成“重试”，不自动重放未知操作。修复仍在原沙箱权限/网络边界内，无宿主Shell或扩权入口，具体合同见143s第4–5节。

展开/关闭过程面板、状态轮询和SSE只观察，不复制过程到本机主聊天/长期记忆。下载仅保存本机结果目录；“交给主会话分析”只准备文本要求＋material_refs，用户确认发送后才启动本机模型并真实读取材料，不给旧工具调用追加返回。下载通知不修改主Agent输入或用户草稿。侧栏向云端发出的补充指令也不冒充本机主输入。手动创建/发送关联使用来源session、instance/task与用户操作ID，不要求或伪造本机模型run/tool_call。运行中可编辑任务草稿，首版等待本轮结束或停止/保存确认后再发，不新增并发根运行；切换任务和迟到回包不得串草稿/消息目标。

## 5. 结果与交付

候选侧栏在S06.4提前验收，S07.2/S08各片补接真实结果动作，S09.1仅正式切换和A退出，不承担首次UI接线。ResultReview 默认展示 I→O 文件变化、捕获时间、校验状态和独立产物列表。先看摘要，按需取差异正文/预览；大二进制显示大小/hash和下载，不强行把base64放进消息。下载结果和代码交付可独立操作。按143w，“下载结果”把清单/patch/选定报告存入本机受控目录；“交给主会话分析”把分析要求和材料引用合入输入草稿，保留已有内容，由用户点击发送；代码/报告字节不放输入框。窄的只读材料工具在真实调用后产生工具来源，下载/观察/未发送草稿不触发模型或记忆。

ResultDelivery 提供“导出到新目录 / 创建本地分支 / 应用到当前目录”。选择目标后显示将新增/修改/删除的文件数与冲突；应用必须显式确认。旧“merge远端提交”字段和操作从云端UI移除。无 Git/无原HEAD时分支动作不出现；连接器不在线时只保留云端审查/普通下载。

失败例子：捕获后用户在 Windows 改了将覆盖的文件，应用预检返回冲突列表，不做副作用；UI保留当前结果，可导出到新目录或调整后重新预检。中途磁盘失败显示 partial/unknown及本地操作号，不显示“失败所以没有改动”。

容器停止/释放后已验证结果仍可查看下载；删除结果/持久数据是独立显式动作，详见143v。用户已确认：仍有关联未删除任务（包括已停止/完成）时阻止删除本机会话/项目，先取回所需结果并处理关联任务；不自动取消远端或转移到全局列表。

## 7. CLI 对等与手机边界

云端CLI复用相同认证、命令ID与会话API，提供连接、输入导入、创建/列举/停止任务、消息、结果下载与三个本地交付动作；CLI和Web不分别装配两个Agent。具体子命令解析沿现有CLI模式在对应切片实现，不为未接线能力预留空命令。

S04.2b已接内部`cloud control stop|recover`及owner `POST /tasks/{task_id}/control`，复用command show；请求原ID/CAS/run/checkpoint与环境强停/换代顺序见[143q第6节](143q-s042b-run-control.md#6-内部cli与核对顺序)。UI接线在S09：普通stopped可发新输入，失败/unknown展示Runner恢复描述并显式核对；根本轮完成但后台尚在时分别显示，不能把completed渲染成可回收或建议重放旧run。

SSH私有首版允许本机会话侧栏与CLI查看/控制同一云端任务，本机退出不停止已接管任务。未来手机复用云端任务API/鉴权查看或控制；本期不公开公网，不新增移动应用或手机代码合并。Windows关闭时本机主Agent不响应；手机无本地文件连接模块时不能显示已应用到Windows。
