# Spec 056：软触发阈值下无安全切点时继续运行

状态：2026-10-07，已按 TDD 接入；与 Spec 057 的轮次中途切分组合使用。

## 当前链路与问题

本地 `before_agent` 用 `窗口 − max(预留量, 最大输出)` 触发压缩，`_cut_at_complete_turn` 只从 `HumanMessage` 开始保留。若最近保留目标跨过同一轮的工具结果，可能得到切点 0 并报 `no_safe_cut`，即使完整请求仍低于 `窗口 − 最大输出` 的估算发送上界。2026-10-03 本地只读探针：窗口 350、最大输出 20、预留 60、最近保留目标 30，含完整工具调用/结果的五条消息估算 314，超过软阈值 290、低于发送上界 330，却会因切点 0 失败。

Pi 可在消息边界拆轮次，但本片只修正软阈值不应造成无谓硬失败；拆轮次见下一独立 Spec。窗口数值与近似计数不是供应商真实能力保证。

## 本片契约

- 原有压缩触发条件不变。若唯一阻碍是 `_cut_at_complete_turn` 返回 0，且原始完整请求估算 `<= 窗口 − 最大输出`，本次跳过压缩，记录不含消息内容的 `context_compaction_skipped` 事件及固定原因 `no_safe_cut_within_send_budget`，由原 `create_agent` 正常模型循环继续。等于发送上界也允许继续。
- 原请求估算超过发送上界时，本片本身不允许直接发送正常模型请求；随后由 Spec 057 尝试安全的消息边界切分。仍无可行切点（例如单条超大用户消息）时才报 `no_safe_cut`，不改 checkpoint 内容、不把失败变成回答。
- 摘要请求超预算、摘要模型失败、压缩后仍超预算等其他失败不在本片回退。无安全切点的消息既不删除也不截断。公开 API、配置与模型重试策略不变。

## 影响与验证

- `agent_runtime/context_compaction.py`：只在切点 0 分支按已有估算和发送上界做一次判断，安全记录跳过原因。
- `tests/test_context_compaction.py`：先增加完整应用链路红灯：软阈值被跨越、切点为 0、原请求低于发送上界时正常模型被调用且摘要模型未调用；超过发送上界时仍失败。现有压缩、checkpoint 与门禁测试回归。
- 本 Spec、交接、后续清单与总体决策同步实际证据；不修改私有 `.env`、依赖或 `docs/关键知识点.md`。
- 定向及全量 pytest、`compileall`、`pip check`。真实供应商接受边界附近请求需另行验证。

## 实施与证据（2026-10-07）

先写软阈值反例，红灯为 `1 failed, 1 passed`：估算 314 处于软阈值 290 和发送上界 330 之间，却报 `no_safe_cut`。最小实现按原估算跳过并记录固定原因；定向压缩测试一度为 `14 passed`。Spec 057 接入后，原来“超过发送上界必失败”的旧断言已不符合新契约，改为验证存在安全消息边界时会压缩；单条超大用户消息的 `no_safe_cut` 断言仍保留。最终合并验证见 Spec 057 与 `docs/handoff.md`。
