# 独立 Agent 评测首个切片

从仓库根目录运行 `python -m evals run`。Inspect AI 安装在独立评测环境，产品包维持现有依赖和入口。评测进程关闭 Inspect telemetry 与 LangSmith tracing，真实模型由显式模型配置读取。数据集用 JSONL，工作目录 fixture 与评分目标分别传递。

## 执行与证据

- 单步组件执行读取真实模型目录，拼接现有基础提示词并调用一次模型，保留工具调用。术语题检查零工具调用，并可选用独立模型按固定细则评分。
- 系统执行为每次尝试复制 fixture，设置临时 data_dir，调用产品应用装配、项目登记、建会话和 RunAPI。通过现有订阅从本次运行采集工具消息和首字时间。对比两份报告同时评必要读取与最终答案。
- 多轮题在同一会话内按固定用户脚本澄清，独立执行四次。保留每次结果与 pass^4。固定脚本先验证会话和重复执行，动态模拟用户属于下个切片。
- 单调时钟记录每轮 Agent 执行，整题耗时为各轮之和。以任务尝试为样本计算平均、P95、P99，单列组件与系统。Inspect 逐条日志与 HTML 输出置于本次评测的独立目录。
- 业务失败仍生成证据和报告。执行或评分异常标为评测错误，报告显示有效样本数；四次业务结果齐全后才算 pass^4。

## 代码范围与验收

`evals/` 含命令、数据校验、执行、评分、报告和三个用例。用固定模型在进程内替换产品模型目录，驱动真实运行链并核对报告；真实模型凭显式配置另行运行。检查评测临时工作区与产品数据独立、运行结束后清理、负向结果正确归因。评测主体在仓库中，产品安装包不包含此目录。真实运行回收、会话诊断和 LangSmith 接入独立推进。

## 子 Agent 介绍词与路由数据

单步用例通过 `roles` 声明父模型可见的角色名和介绍词，通过 `tools` 开启真实 `subagent` 工具定义。沿用产品的提示词组装函数。评分从本次 AI 消息中读取结构化工具调用，核对角色集合与次数、合法委派参数以及创建新实例的约束，无需裁判。首次收录独立排查、编写测试设计、双角色分工、禁止委派和无需委派五个场景。样本只触发模型决策，子 Agent 协作执行与产物留给系统评测。

用固定调用验证选错角色、漏委派、重复委派及无效参数的扣分。随后用已配置模型跑该组，记录真实调用与判分。

## 工具选择和参数数据

单步题通过产品工具定义约束模型输出，仅记录工具请求。每题提供任务相关的工具与容易混淆的选项。预期调用以 `checks.tool_call` 记录工具名和必须匹配的参数。单次调用的工具名和次数单独判分，参数须通过原工具契约并满足预期值。嵌套对象按预期字段匹配，数组比较长度与顺序。未指定的可选参数按工具契约校验。无调用题沿用 `no_tools`。

覆盖通用内置工具与 Runner 交付目录工具。edit 单步题从已取得原文开始，先读后改纳入多步规划。现有系统执行路径继续只接受已接入的读取工具。验证包括覆盖率、错选、错值、无效参数及重复调用。模型输出的命令和任务控制操作仅作为评测证据保存。

## 受控多步规划

`mode: planning` 在同一个模型对话中执行工具请求并回填模拟结果。每个样本声明按依赖顺序排列的预期调用与工具结果。只有一批模型请求中第一个匹配当前步骤的调用能推进状态。其他调用收到错误，保留证据。参数验证沿用产品工具契约。循环按模型轮数封顶，任何路径都不会调用真实工具或写文件。

第一组验证四个场景：读后局部编辑再核验、编辑返回过期资料后重读并重试、文件缺失时如实停止、只读检查时遵守禁止修改。用例要求终态第一行使用约定文本，代码分别判步骤缺失、约束违规、提前宣告完成和可继续时误判无法完成，并保存已到达步骤和终态。固定模型验证反馈确实进入下一次请求。真实模型评测使用同一组受控响应。

## 组件场景扩展

四组保持独立入口。系统提示词用真实 Skill 目录与空目录对照，裁判核对可见能力。路由使用中性角色名，交换介绍后复用同一任务。工具加入历史中更正目标后的取值、单行分页边界以及等价分页请求中的无关上下文。规划保留脚本化故障，给只读题增加精确答案行，并用相同目标对照待修改和已达标的初态。

规划的 file_goal 用例在临时目录内准备一个指定文件，模型只看到用户目标和可用工具；评测循环把已校验请求限制到该文件，复用产品的读、写、编辑实现，记录真实结果。最后比较文件全部字节，对已经满足目标且要求保持原样的题检查读到目标行和零写入请求。成功路径接受有效的局部编辑或完整保留其余内容的写入；误改其他行、越界请求、未检查就宣告完成分项判失败。脚本题保留原有顺序判定。涉及 cases、execution、planning、scoring 和四组数据，验证反例、独立 CLI 与同批真实模型报告。

## 系统轨迹 v1

独立 CLI → 临时项目和真实 Session/Run → AI 消息与同 ID 工具回执 → 校验最终答复、工作区改动或交付文件 → 匹配参考路径 → HTML 和 JSON。评分只读证据，不调用模型。成功读取、预期缺文件错误、无回执和参数错误分别保留。一次模型决策中的调用共享批次，不能据列表位置推断它已看过同批另一个结果。

每题声明等价类、边界和一个或多个参考路径。一个路径由若干阶段组成，同阶段动作可以并发或互换，跨阶段需先取得前阶段反馈。每个动作含工具名、关键参数、预期状态及可选结果片段。按一对一最大匹配计算精确率 P=M/A、召回率 R=M/E。A=E=0 时均为 1；只有一边为空时，该边的空分母取 1，另一边取 0。按完成验收且完全有序、完成且有序但有额外动作、完成且全覆盖但顺序有偏差、未完成但有命中、未完成且零命中依次分五档。完成却未覆盖任何一条完整参考的路径留待复核，保留任务成功。多参考优先选最高可解释档，然后按 F1 择优。总分精确 100，有序 60+20F1，任序 40+20F1，部分 20+20F1，偏离 0。分值是首版约定。

输入覆盖文件和代码问答、搜索 0/1/多个命中、均可先读的两份报告、需前次结果才能确定路径、修改 Python、书写文本用例和自动化测试脚本、术语及无关请求。结果独立核对，写入在临时项目中执行，验收核对写操作目标和工作区前后差异。Python 修改按语法树核对，文本用例按 CSV 表头与行多重集核对。自动化脚本使用题目约定的无参 pytest 函数和独立布尔断言，以受限语法解释每个断言，逐一翻转 99、100、101 的正确返回值并验证测试能检出变化。还覆盖清单→两份报告→CSV 的分阶段交付，以及主文件缺失后读取备份。缺文件时按用户约定如实反馈也算完成。完整评分、匹配详情、待复核及耗时写入原报告。用合成证据确定性覆盖五档、重复动作、并发、合法替代和零分母，再用同一 CLI 跑真实基线。范围为 evals、专用 fixture、测试及评测文档。

## 系统多 Agent 协作

复用独立 CLI、临时项目和真实 Session/Run。组件集中的角色描述注册为测试用角色，父 Agent 可读文件和委派，子 Agent 只读文件，沿用被测模型。数据声明预期角色、交接必含项、子 Agent 应读的材料、子报告应返回的标识，以及父 Agent 最终答复。测试目录与真实运行配置隔离。

父工具请求先按公开参数契约判选角、次数和新建实例，再核对交接字段。用父工具调用 ID、子实例 ID 和子 Run 终态关联内置事件及父工具回执，通过 HistoryAPI 查子会话并核对实际读文件与状态。成功路径有材料、子报告及根最终交付。缺文件路径必须真实尝试读取并准确回报不可用。禁止委派的对照题检查零委派。最终交付继续进入端到端成功率，协作通过另要求全部协作断言。报告列出各维度，评分只用代码。

实现影响 evals 参数、运行和报告，增加固定模型正反例及真实模型单次基线。

### 开放式协作交付

新增两条真实系统题，分别评审边界测试设计和整合排障与验收结论。数据仍声明角色及必读材料，开放式子报告省略精确文本。父请求、子执行和父回执的关系仍由代码验证。材料可由子 Agent 读取，也可由父 Agent 在委派前先读取，此时裁判核对父读取回执中的必要事实已准确转交。运行同一 CLI 时显式提供裁判模型，评分器将题目、细则、实际交接、子轨迹与报告、父最终答复作为证据，一次调用分别输出交接语义、子报告质量及最终整合三个 0–2 分和理由。每维 2 分且代码全部通过才算协作通过。端到端结果使用最终交付维度及运行是否完成，保留与协作评分的区分。裁判缺失直接报配置错误，裁判响应无效记评分错误。固定文本用例继续用原评分协议。

## 动态多轮交互

同一个用例固定首条用户消息、模拟用户私有目标、回合上限及代码验收。评测以不同临时项目、会话和数据库各跑四次。独立指定 `--user-model`，模拟器按私有目标与实际已公开对话输出下一条用户消息，第二次 Agent 回复后才允许结束。评分规则和标准答案留在评测进程。反馈退出、回合上限、审批中断和模拟器故障均留证。最终答复、材料读取及适用的首轮约束用现有规则核验。模拟器的结束判断仅用于控制对话。报告显示逐次对话、每题四次通过情况和已完成题目的 pass^4 比例。模拟器调用独立计时。已有固定脚本继续走原入口。
