# Spec143S：本机会话委派云端任务、侧栏观察与介入

状态：2026-11-02确认的手动入口已完成S06.1a/b、S06.2a/b、S06.3a/b及S06.4本机验证，候选UI见[143x](143x-s064-cloud-sidebar.md)。共15单元完成7项、剩余8项，唯一下一片S07.2完整结果；结果接收/分析草稿仍归S08，正式切换仍归S09。产品合同仍为加号菜单→侧栏列表→新增/选择→详情追加消息；不做本机Agent自然语言创建、主聊天迁移或云端长期记忆。既有S01–S05/S07.1与原实机证据保留各自边界。专题合同为[143t历史/观察](143t-s061-history-and-observation.md)、[143u手动任务](143u-s062-manual-tasks.md)、[143v资源收敛](143v-s063-resource-lifecycle.md)、[143w结果接收](143w-s081-result-receive-and-analysis.md)。

## 1. 用户路径与所有权

用户在同一本机会话完成前置分析，通过加号菜单打开“云端任务”侧栏，手动新增独立任务，或选中已有任务查看/续聊。详情底部消息只发给当前选中的云端任务；主聊天输入仍交给本机Agent。Coordinator持久接管已受理的执行，Runner在独立容器内完成Agent循环；本机可继续聊天，不要求切换主会话或迁移本机checkpoint。首版不注册本机模型创建云端任务或自动发起远端运行的工具，不做主聊天自然语言自动路由。

```text
本机主会话/Agent/长期记忆
  → 加号菜单/云端任务侧栏 → 本机关联记录、固定输入与用户操作命令
  → Coordinator持久受理与编排
  → 独立容器中的Runner/Agent/工具/workspace/state
  → Coordinator已确认过程历史、固定结果及产物
  → 本机任务侧栏观察；显式取回结果后由本机Agent分析和整理记忆
```

本机拥有主会话、任务来源关联与结果接收记录；Coordinator拥有任务目录、所有者命令、委派编排、过程投影和结果；Runner拥有该任务checkpoint、必要保存与执行。云端project仅为授权/任务分组，不提供跨任务长期记忆。

这是完整任务委派，不恢复A的本机Agent逐次代理远端文件/Shell工具。任务内仍可按既有配置调用子Agent；本机主轮次与被委派任务的存活、停止和保存各自独立。

### 1.1 用户决定新建与复用

1. 主输入区加号菜单增加“云端任务”；点击直接打开ActivitySidebar的云端任务视图，不调用模型、不创建任务/容器。
2. 列表顶部固定“新增任务”。列出当前本机会话关联的云端任务，运行中优先；已停止/完成且仍保留的任务可继续找到，用于续跑、取回或清理。状态、实例与选中项真实显示，无伪造示例。
3. 只有点击“新增任务”进入独立任务/环境创建流程；复用已配置的连接/模板与当前已授权项目来源，缺必要配置/授权时再引导补齐。创建/准备失败、额度不足明确显示，不静默复用另一个任务。重复点击/网络重试使用原操作ID去重。
4. 点击已有任务进入详情：上方可返回列表，中间为Agent/工具过程，底部为该任务专属对话框。打开/切换任务或向已有任务发送消息均不新建另一项独立任务或并存环境，不重新导入本机当前文件；已释放环境的任务显式重启原任务环境，仍使用原持久目录。
5. 新任务准备就绪后首条消息启动第一轮；已有任务消息沿第4节的ready/停止/恢复边界启动新轮。任务运行中允许编辑草稿，首版需先停止并确认保存再发送，或等待本轮结束；不暗中并发启动第二个根运行。
6. 新建任务不自动复制本机全部聊天或长期记忆。用户在任务消息中写目标和必要背景，代码/proto按明确输入来源导入；主聊天后续消息不自动同步到云端。

## 2. 持久受理与离线合同

本机操作前持久登记来源project/session、云端instance、任务ID/输入ID、用户操作command_id与状态。创建任务、发送消息和控制分别留回执；首版没有本机Agent提交调用，不能捏造origin_run_id/tool_call_id或空的ToolMessage来满足关联。实际结果查询工具发生时才记录真实工具身份。用户任务消息携带目标、必要背景、验收条件与预期产物；输入只在已授权来源内捕获，复用143b清单/缓存/续传。

新建与发送分开：新建准备输入和环境，不自动编造任务消息或调用云端模型。仅当输入校验就绪、用户发送的运行命令在云端持久受理后，显示“云端已接管执行，可关闭本机”。准备/上传阶段仍依赖本机；不能把本地记录或HTTP已发出视为已接管。运行受理后云端独立执行并跟踪必要保存；完整文件结果完成S07.2后，由云端在静止边界自主捕获，无需Windows在线补发capture。

每个有副作用步骤沿既有command_id/摘要/CAS及持久阶段对账；重启或ACK丢失查询原操作，不另造任务/运行。编排只处理这个固定工作流，不建设通用工作流平台。本机关闭、当前聊天本轮停止、观察连接断开均不取消已接管任务；显式停止云端任务另发所有者命令。

本机重启从本地持久关联查询原instance/task/命令和结果。自动对账只更新任务状态，不启动本机模型、不重放工具、不自动应用文件。连接失败显示不可达，不把云端运行改成停止。结果与交接材料在云端保留至显式清理或已公布的保留策略；停止/回收计算容器不删除持久结果。

**网络前提**：Windows反向SSH中转是业务依赖。Windows休眠/关机后，云端Agent仍可运行，但依赖该中转的预发布HTTP/RPC可能失败；不承诺这类测试离线完成，也不自动重放结果未知的请求。完全脱机调用预发布需公司允许的常在线访问路径，部署另行确认。手机后续可查看/控制云端任务；不能在Windows关闭时让本机主Agent继续响应。

### 2.1 资源管理与停止继续保留

本机会话数量不触发容器分配；新增独立云端任务才进入环境准入。Coordinator沿既有活动/保留数量、CPU/内存和容量配置限制创建/启动，原子预留额度，未知资源继续占额度；达到上限明确拒绝，不以反复重试扩容。空闲停止仍须Runner静止、输出收齐、必要历史/结果保存确认且无unknown，周期调度由Coordinator承担，不能依赖Windows在线。查看过程不刷新执行活动。

本机“停止本轮”只停止本机执行；云端详情的“停止本轮”收束该任务根子/后台并保存。“释放环境”再移除运行容器，保留workspace/state/历史/结果，续跑重新启动；“删除任务数据”另确认清理范围，不隐含删除本机主聊天或已取回文件。停止容器不释放持久数据的磁盘占用，保留任务/输入缓存/结果容量和清理分别管理。现有空闲算法/额度代码不等于周期调度与完整数据删除已接线，正式入口和验收仍须实施。

## 3. 侧栏必须可观察，而非仅显示百分比

在现有ActivitySidebar/BackgroundTasks位置扩展云端任务列表与详情，复用现有消息、工具和子Agent呈现能力。每个任务至少显示：

- 来源会话、任务要求、云端实例、输入基线和环境准备阶段；不暴露凭证/宿主绝对路径。
- Agent消息、可展示的思考摘要、工具调用/结果、根子归属、有限输出与按需完整正文/产物入口。只展示实际收到的数据，不要求模型提供未公开的内部推理。
- 最近已确认历史水位、运行/环境/连接/结果状态，以及错误发生的阶段和安全原因码。
- 继续/停止/核对恢复/结果取回入口，按第4节真实状态启用；查询失败保留已有内容并标明过期或断档。

展开过程读取Coordinator投影，不启动Runner、打开任务SQLite或将过程复制进本机主聊天。快照/增量按epoch/seq衔接，断档重新同步；SSE不持有长读事务，慢客户端不阻塞执行。实时草稿与正式档案分开，观察故障不能改变执行成功或覆盖原异常。

容器停止后仍可查看已确认过程。过程存在不能证明checkpoint可恢复；未保存内容/用量缺失/日志缺口分别标明。主聊天可继续发送本机消息，云端不在线只禁用对应云端动作，不禁用本机输入框。

## 4. 错误、退出与修复必须区分

| 实际状态 | 侧栏行为与修复合同 |
| --- | --- |
| 单次工具失败，Agent仍运行 | 展示调用、错误结果和后续分析。工具失败不自动把整项任务标failed；Runner可在原授权范围内继续分析/修正。需要人工介入时先停止本轮并确认保存，再发补充指令，不并发写同一任务。 |
| 根运行completed/stopped，状态与必要历史已确认 | 允许向同一云端任务发送新指令，沿既有runs入口生成新run，继续使用原工作区/checkpoint；不必创建另一个本机主会话。 |
| 模型/应用失败，Runner保持blocked但可提供恢复描述 | 展示原错误、checkpoint/原命令归属和可用动作。沿143q显式recover核对并完成必要保存后，才接受修复指令；可选择任务已允许的可用模型，不把恢复误作业务重试。 |
| Runner崩溃、失联或副作用/保存unknown | 展示“需核对”，只读原命令/历史。物理换代先确认旧容器不能再写，再恢复持久state；不凭连接断开或令牌吊销认定旧执行停止，不自动重放Shell/RPC。 |
| 缺依赖、配置或网络不可达 | 补充指令可让Agent在原容器内修项目依赖/代码；基础模板或部署网络问题走既定管理流程。侧栏不提供宿主Shell、临时扩权或跳过deny。 |
| checkpoint丢失或不可校验 | 已确认历史和产物仍可查看/取回；明确不能原地续跑。若用户另建任务，使用显式输入/交接材料，不伪造无损恢复。 |

首版介入是“查看错误→必要时停止/核对→详情底部向同一任务补充指令→新一轮”，不由本机Agent根据主聊天自然语言自动发送。侧栏输入是发给目标任务的所有者操作，不冒充本机主聊天用户消息，也不自动触发本机记忆。任务详情明确显示当前输入目标；切换任务隔离草稿，旧请求回包不能落到新选中任务。

复用已有owner runs/control/环境命令，不复制第二恢复算法。发送/停止/恢复/取回均核对本机会话关联、目标实例和task、command_id以及当前revision/generation；任务令牌不获得所有者接口。原本机“停止本轮”只控制本机Agent，云端停止按钮明确标明对象。首版不新增交互终端或任意宿主命令入口。

## 5. 沙箱隔离保持

- 一个云端任务仍对应独立容器、workspace/state和固定输入；任务间不共享可写目录，任务不能操作本机目录或其他任务。
- Agent循环、Shell、测试和项目依赖均在任务容器。修复和续跑不降级成本机/宿主执行，不共享本机项目可写挂载；结果应用仍按143b/143d预检与确认。
- 沿143p使用任务NoAsk＋显式deny/准备执行复核，管理员部署的受控外网/关闭外网两种策略保持；关闭外网仍保留控制、必要历史/结果和受限模型入口。
- 真实模型密钥留Coordinator；容器不获得Docker/OpenSandbox管理权限、全局记忆库或本机凭证。取回的文件/日志是数据，不构成新授权。
- 保留143a第8节已验证/待验证边界。同任务同UID命令可影响本任务state，不能声称新增任务侧栏提供了任务内防篡改或强于现有容器边界的保证。

## 6. 主会话、结果与长期记忆

取消云端个人/项目记忆库、memory API和后台记忆整理；Runner保留本任务checkpoint、上下文压缩和过程档案。本机MemoryAccess/来源/TTL/候选/生效/禁用/遗忘规则保持，不将云端报告当作用户声明或独立业务验证。

用户已确认143w的三个动作：下载到本机结果目录；点击“交给主会话分析”只准备带任务/材料引用的输入草稿，由用户确认发送；代码应用另走S08.2预检/确认。代码和报告字节不塞输入框、不自动覆盖项目、不自动调用本机模型，也不覆盖已有草稿。

手动新增/发送保存为用户操作和任务关联，不构造本机run/tool_call。正式发送区分用户分析要求与外部材料引用；本机Agent通过窄的只读材料工具真实读取后，沿既有ToolMessage/必要档案保存产生可引用来源，不伪造角色。已确认材料在本机可离线分析；过程查看、自动对账、下载与未发送草稿都不参与本机记忆整理。

云端可将交接知识写入显式选择的文件随固定结果交付。取回/材料身份、幂等、缓存清理、旧回包和来源详见143w；单纯文件下载不等于主聊天已接收、模型已分析或代码已应用。
