# Spec143BO：按主题组织的长期记忆 Wiki

日期：2026-11-17；实施更新：2026-11-18。状态：**S0 固定样本/离线合同、S1 存储/隔离迁移及 S2 Wiki 工具组件已实现并验证；S3后台提出/按页整理已实现并通过本机验收，S4上下文/历史预算与S5到期维护已实现，S6 默认入口已切换并完成本轮工程验收，真实模型语义优化延期。** S1/S2 在隔离临时库验证。S6 已进行真实模型校准，已知范围误判保留原结果；不加用户确认，后续优化见 [S6](143bo-06-acceptance-and-cutover.md)。旧 Spec143BM 的实现与历史评测保留查证，其未完成校准不再是下一步。

## 1. 目标与已确认决定

历史工具负责找回当前项目的对话、阶段进展及会话概览；memory 只整理值得以后复用的长期记忆。数据库是唯一权威数据源，Markdown Wiki 是按需生成的视图，不另维护一份可写文件副本。

| 项目 | 本次固定合同 |
| --- | --- |
| 范围 | personal 与当前 workspace；both 仅为读取选择器 |
| 内容类别 | 不再区分 convention/context 等时间类型；只提取长期价值明确的内容 |
| 大主题 | collaboration＝协作方式；working_agreements＝工作约定；stable_knowledge＝稳定知识 |
| 层级 | 大主题 → 具体主题页 → 多条记忆；同级页面可关联，不增加任意深度分类树 |
| 范围与主题 | 相互独立；每个具体页属于一个范围，项目页还绑定程序确定的项目身份 |
| 默认有效期 | 30 天，可配置；真实确认时间加 TTL，不以整理/读取时间刷新 |
| 清理缓冲 | 到期立即退出普通召回；默认再保留 7 天，可配置，之后由代码分批清理 |
| 自动 Wiki 导航 | 独立上限 2,000 个估算 token |
| 自动其他会话目录/概览 | 独立上限 2,000 个估算 token，沿首次符合条件时提供的语义 |
| 按需读取 | 小主题目录、主题页正文、历史工具结果均每次最多 2,000 个估算 token，显式分页 |
| 一个小主题容量 | 默认 30 条未退休且未过期的记忆；超过须整合或拆成新的同级主题 |
| 后台 | 一个任务内 A 提出、B 整理；B 可按需阅读；失败跳过，不重试、不保存失败提议 |
| 显式写入 | 保留直接写入，共用来源/范围/容量/版本门禁；复杂整理走后台 |
| 旧记忆 | **全部退出使用，不迁入 Wiki，不参与检索、比较、导航或自动回填** |

两个 2,000 自动预算相加的上界为 4,000，不再受旧 injection_tokens=2,000 的合并上限二次裁切。按需返回是工具结果，累积计入整条模型请求；不是在 4,000 之外拥有无限空间。

**30 条是逻辑主题容量，2,000 token 是一次读取容量。** 一个有 30 条记忆的主题可以读取多页。用户已替换此前“整主题正文最多 1,500 token / 20 条”的建议；不得把这两个旧限制继续带入实现。

## 2. 人能检查的例子

用户说“我平时学习技术时习惯先看例子，再看原理”。A 引用真实用户证据 E12，提出 personal/协作方式。B 浏览该范围的大主题目录，完整读取选中的“方案讲解方式”页，判断是新增还是补证。程序绑定来源、检查范围和版本，保存一条记忆。新会话先看到主题入口，需要时读取该页。

若原话是“只在这个项目先举例”，则应存 workspace。A/B 的自然语言判断可能出错；代码能保证身份、来源、权限及结构，不能证明一段真实引文必然蕴含跨项目适用。

“测试约定”已有 30 条，新增一条会达到 31：B 可以提议将其拆成“本地测试环境”“回归执行要求”。程序一次提交成员移动和新条目，检查所有结果页均不超过 30。若拆分方案无效，相关组零写入，旧 30 条保持，不删一条来腾位，也不让分页掩盖超额。

## 4. 主链与权威状态

~~~text
真实用户/工具消息 → 已保存聊天归档 → E 证据单元
                                      ↓
                         A：概览与长期记忆提议
                          ↓                ↓
                   概览独立保存       程序绑定证据/范围身份
                                           ↓
                B：目录 → 按需读完整相关页 → 整理提案
                                           ↓
                  同库连通组校验＋CAS＋事务提交
                                           ↓
               当前记忆/主题成员/页面关联/证据快照
                                           ↓
              代码生成导航或分页 Markdown → 模型上下文

显式 memory 写入 → 同一个提交门禁 → 当前记忆/页面
必要会话保存成功 → 可选维护协调 → checkpoint 裁剪；记忆 GC
~~~

模型拥有语义建议；程序拥有 ID、范围路由、来源真实性标记、版本、时钟、容量和提交结果。所有记忆、概览、网页或工具资料均为数据，不成为执行授权。按需读取不会调用额外检索模型，不保存记忆或续期。

## 5. 范围合同

- personal 的依据必须是用户自己表达的通用要求或一般偏好；不要求字面出现“所有项目”，但需结合完整限定语判断。
- 项目事实、项目约定、项目语境中只有“以后/记住”的表达默认 workspace。无项目身份时不伪造 workspace，也不自动升为 personal。
- 引用材料、AI 总结、工具观测、多个项目重复出现，不能独自提供个人范围依据。
- 每个 personal 提议指出支持范围的已有 E 引用；程序保存该来源关联，不要求重抄原句，不接受模型提供 user_origin/verified_at。
- 原范围不能因改名、补证、移动、拆页、合并而扩大。项目约定升级为个人约定须有新的用户范围依据，创建独立个人记录，不做跨库搬移事务。
- personal 页仅链接 personal 页；workspace 页可链接同项目或 personal 页。目录标题/简介、链接和正文都在过滤权限后输出。
- 新个人内容不能借旧个人条目的“通用授权”任意扩写。新正文和适用条件仍需语义审核及真实来源。
- 同一事项同时存在个人默认与当前项目例外时，两者分别保留；提示模型在该项目应用证据支持的具体例外，不以项目例外覆盖个人默认。是否正确识别例外属于语义验收。
- 个人正文可跨项目读，原项目会话全文不可因此跨项目展开。旧来源原文清理后，已保存的必要片段与核验记录继续服务已有记忆至其到期。

## 6. 配置合同

以下为新字段；数值为首版默认，不是已测得最优值。真实配置不自动改写。

| 配置 | 默认 | 合法范围/含义 |
| --- | ---: | --- |
| memory.default_ttl_days | 30 | 整数 1..36500，新记忆及充分重新确认采用 |
| memory.expiry_grace_days | 7 | 整数 0..36500，0 表示到期后即有资格物理清理 |
| memory.wiki_navigation_tokens | 2000 | 整数 0..8000，0 关闭自动 Wiki 导航，不关闭显式工具 |
| memory.session_directory_tokens | 2000 | 整数 0..8000，0 关闭自动历史目录 |
| memory.wiki_read_tokens | 2000 | 整数 256..16000，单次完整工具返回预算 |
| memory.wiki_topic_max_memories | 30 | 整数 1..200，active＋candidate 中未过期条目的总数 |
| memory.cleanup_batch_size | 100 | 整数 1..1000，每次维护中旧版本、主条目、关联/空页各类工作单位的单批上限；不循环清空全库 |
| memory.cleanup_interval_seconds | 3600 | 整数 0..86400，每个已打开库的维护触发节流；非后台定时器 |
| tools.history.max_output_tokens | 2000 | 整数 256..16000，与现有字符/字节上限取先到者 |

不改后台触发默认 8 轮/20,000 字符、输入 16,000/输出 4,096 token、3 批和 300 秒期限；不改工具原结果裁剪。B 合法翻页会增加逻辑请求，已不再承诺旧 A≤1/B≤1；依赖现有期限与累计材料上限，不添加人工评测调用次数配额。

30 条不保证最坏长度的整页一定装进后台 16,000 token。前台仍可完整分页读取；B 若无法在已有预算内取得完整整理材料，则报告预算不足并跳过该组。评测单列这一失败率，再判断是否调整后台预算，不先增加另一套压缩/检索机制。

旧 active_ttl_days/candidate_ttl_days、personal_convention_tokens、injection_tokens、自动召回专属参数在最终切换时移除；出现于显式旧配置时给字段级迁移错误，不静默折算、不改文件。仍有显式 search 消费的词法参数保留。

TTL 采用值保存到条目；修改默认 TTL 不追溯续期/缩短既有条目。清理缓冲按维护时配置计算，减少缓冲会使更多已过期数据具备删除资格，配置说明须明确这一点。降小主题容量不会删旧有效条目；该页允许读取/减量/整合，禁止继续增加未过期成员，直至满足新上限。

## 8. 清理重构的引子

首版只统一本机根会话收尾处的可选维护调用，继续由 checkpoint_retention 和记忆仓储分别决定能删什么。没有全局注册表、插件式清理器、跨项目扫描器或新常驻清理任务。

诊断保留还承担写入时容量准入；云端输入/结果清理由独立 Coordinator、租约和 IO 预留约束；应用 close 是资源释放。它们不因函数名含 cleanup 就合并。本次建立返回计数/原因/耗时及明确所有者的维护边界，供后续整体重构接入，详见 S5。

## 9. 保留与退出

保留：history 的完整归档、最新概览及版本/覆盖范围、现有压缩、E 编号、来源精确绑定、忘记抑制、权限许可、CAS、任务进度与成本观测、显式词法 search。

退出：新写入 kind、按类型 TTL、个人长期约定预加载、用户整句/拆查询自动召回、后台词法找旧项、要求模型重写旧正文或抄旧来源的门禁、旧代记忆的全部产品读取。

旧记忆“不再使用”不等于本轮获准清空真实数据库。迁移隔离旧内容供备份/取证，产品无读取入口；后续总体清理重构可另定其物理保留政策。本次默认 GC 只处理新代记忆。原显式忘记的最小来源抑制标记继续生效，不把它当作可召回记忆迁入。

不新增向量服务、全库模型扫描、Markdown 双写、记忆管理 UI、重要性打分或按总条数淘汰有效记忆。30 天约束留存时间而非绝对条数；记录实际库/页/条目规模，不能宣传绝对容量上限。

## 10. 依据与证明边界

本轮本机源码核对：Pi a69bef789 的 resource-loader.loadProjectContextFiles → AgentSession._rebuildSystemPrompt，按位置加载全局/项目上下文；AgentX 3fcfa0e 的 AbstractMessageHandler → MemoryExtractorService.extractAndPersistAsync → MemoryDomainService.saveMemories/searchRelevant，按用户身份保存/查询。二者并不证明本项目能靠真实引用自动保证范围语义。

项目当前安装 langchain 1.4.2 / langgraph 1.2.12；继续使用现有模型适配和运行时。参考 [LangChain 长期记忆](https://docs.langchain.com/oss/python/langchain/long-term-memory)、[Claude Code 记忆](https://code.claude.com/docs/en/memory)、[Claude dreaming 示例](https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow)、[SQLite 查询规划](https://www.sqlite.org/queryplanner.html)。Claude 的 MEMORY.md 启动读取限制不是所有主题文件的统一容量规则。

先前 2,000/20,000 条内存 SQLite 探针只说明有限页面读取/拼接的局部成本；未覆盖磁盘、全门禁、并发和模型时间，不作为本方案性能验收。旧 143BM 真实报告保留，不重贴新标签宣称 Wiki 已通过。
