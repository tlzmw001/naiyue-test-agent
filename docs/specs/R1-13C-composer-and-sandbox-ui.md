状态：2026-10-25，用户授权在远端 SSH 验收前增加前端优化；本片已完成本机测试、构建和浏览器验收，等待用户视觉反馈；未提交/push/发布，R1-14按用户要求暂缓。

## 1. 已确认的问题与范围

当前链为 ProjectWorkspace → App.header → 项目入口 / ExecutionSelector；Composer 只接消息和权限工具。项目与执行位置在右上角，与用户提供的桌面端截图不符。沙箱结果入口藏在执行位置菜单；模型菜单内再套两层原生 select，视觉与其他选项不一致。执行菜单原来向下展开，直接搬到输入框会被底部裁切。

沿用现有 CSS Modules、系统字体、明暗主题和中性色，不更换品牌或新增 UI 依赖。只调整前端布局、组件交互和对应当前说明；HTTP、领域 API、权限、输入/结果选择及必要保存合同不变。R1-14 SSH 和 R2 不在本片。

## 2. 用户路径与边界

正常路径：进入项目或新建会话 → 输入框上沿显示项目和执行位置 → 选择此计算机或确认沙箱输入 → 使用原创建请求准备会话 → 输入任务 → 在同一输入框上沿直接打开“查看改动” → 取回固定结果、检查差异 → 单独确认合入当前本地分支 / 创建本机分支 / 丢弃任务引用。

失败路径：执行位置检查或准备失败 → 在原位置显示错误并保留原请求 → 只允许核对原创建请求，参数冻结；不会换到本机。环境不可用仍显示实际沙箱绑定，已取回的结果可以打开，捕获仍受后端条件限制。切换项目离开当前范围，不改变旧会话归属；更换执行位置新建会话，不换绑旧会话。忙碌时不创建或管理环境，但已保存结果仍可审查，不允许趁 run 执行交付。

参照：[用户的桌面端截图]为控件位置依据；[官方云端任务说明](https://learn.chatgpt.com/docs/cloud)确认“选择环境 → 发送任务 → 审查改动 → 明确处理结果”的总体顺序。官方可在电脑休眠后继续任务，我们当前 R1 仍依赖本机 Agent，不能用“云端持续运行”文案暗示已具备该能力。推送 / PR 已取消，保持三种本机动作。

## 3. 改动合同与实际消费者

- App 把已有 projectEntry / WorkspaceLabel 和 ExecutionSelector 传入 Composer 的可选 contextEntry 旁的独立上下文插槽（命名 workspaceEntry），顶部只保留既有模型、辅助栏、主题控件。ProjectWorkspace 的范围、草稿和客户端隔离保持原实现。
- Composer 在消息编辑器上方呈现语义区域“项目与执行位置”，项目和执行位置同一行同高度；长项目名截断并保留完整 title，窄屏允许换行，不挤压发送按钮。
- ExecutionSelector 沿用原 create/refresh 回调、请求冻结和错误显示；执行菜单从输入框向上展开，窄屏使用有边界的浮层。图标复用 Icons。沙箱会话直接显示“查看改动”按钮和实际准备状态；原菜单中的重复结果入口移除。环境管理与新建的层次分开，销毁仍二次确认。
- ResultReview 继续调用原 results/resultOptions/capture/diff/delivery API；打开后优先呈现最新已就绪的已保存结果。取回动作仍必须显式点击，不自动捕获。审查与本机处理的标题、按钮层级更清晰，取回记录和对象标识收为次级信息；本机处理区独立于差异滚动区并固定在窗口底部，展开确认时自身有高度上限和滚动，保证三个动作不被长差异挤出视口。错误、unknown 核对和丢弃后的差异保持。
- ModelMenu 使用带标题的原生 radio 分组显示模型和推理强度，替换嵌套 select。保留现有模型选中、支持档位、未配置时禁用、切换模型恢复默认、/model 入口、Esc/外点关闭和焦点返回。
- 修整相关浮层、图标、关闭按钮、底部动作、文件选择和长路径的对齐；明暗主题使用原 tokens。发送方式等无已确认问题的其他控件不改行为。
