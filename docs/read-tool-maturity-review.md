# Read 工具成熟度核对（2026-10-02）

本记录只对照本机 Pi 源码 `a69bef789` 的 `packages/coding-agent/src/core/tools/read.ts`、当前项目 `agent_runtime/tools/read_file.py` 和本地探针。2026-10-02 的 [Spec 031](specs/031-read-text-hardening.md)已完成其中的文本加固，以下本项目列反映加固后的状态。AgentX `3fcfa0e` 已核对的内置工具链没有可直接比较的任意本地文件 Read；不由其推断文件编码行为。生产级是目标，本机测试不构成生产成熟度证明。

| 维度 | Pi 当前本地源码 | 本项目当前实现与证据 |
| --- | --- | --- |
| 非法 UTF-8 | 文本分支 `buffer.toString('utf-8')`；Node [Buffer 文档](https://nodejs.org/api/buffer.html)规定无效序列以 `U+FFFD` 替换。没有看到替换检测或告警。 | 严格解码；当前回填固定的 UTF-8 限制及选择其他文本的指引，不反射原字节、路径或异常正文。加固前临时探针返回通用错误；加固后 `b'\xff'` 的确定性工具测试覆盖新契约。 |
| 非图片二进制 | 非受支持图片走文本分支；无通用二进制拒绝校验，非法字节可能变为替换字符。 | 返回正文中若含 NUL、其他不受支持的 C0 控制字节或 DEL，回填固定非文本错误；tab/LF/CR 保留。加固前 `b'abc\x00xyz'` 被原样返回；加固后工具测试覆盖拒绝。仅检查所读正文页，不宣称全文件格式识别。 |
| 图片及其他格式 | 对受支持图片有 MIME 检测、处理与模型附件分支；普通文本之外不支持自动识别任意文档格式。 | 只声明 UTF-8 文本；没有图片分支。PDF/网页解析仍属独立 RAG 模块，不能称为 Read 已支持。 |
| 分页与内存 | 先 `readFile` 整文件为 Buffer，再按 2000 行或 50 KiB 截断并提示续读；支持 `offset/limit`。 | 单页文件正文最多 2000 行或 64 KiB，按块/行读取；输出有 `next_offset`。深 `offset` 每次从头扫描；跨页没有文件快照。不能由峰值内存受限推断累计 I/O 或延迟更优。 |
| 路径与权限 | 基础 Read 用 cwd/绝对路径解析，不做本项目的工作区包含检查；额外权限扩展另论。 | 会话工作区 `allow`、无效/敏感路径 `deny`、工作区外普通文件 `ask`，执行时重验目标。工作区内部有限允许 `.gitignore` 文件和 `.github` 目录组件，其他隐藏路径仍拒绝；工作区外隐藏路径仍拒绝。路径解析到打开文件之间仍有竞态窗口。 |
| 错误与取消 | 路径/读取错误抛出；长单行提示 Bash 截取；执行接收 `AbortSignal`，但底层读操作已发起后的实际中止不能仅从 Promise 拒绝推断。 | 编码、非文本、长单行有白名单安全错误；缺失、权限及其他异常仍为通用错误。同步工具没有活动取消，CLI `:stop` 只在 turn 边界生效。 |

## 建议顺序

1. `ls` Spec 要沿用 [Spec 031](specs/031-read-text-hardening.md) 的点文件可见性边界；目录名可见与文件正文可读是两个不同动作，必须分别测试。
2. 图片 Read 与其他编码 Read 已由用户明确列为通用 Agent 后续能力，各自有完成判据，见 [future-work](future-work.md)；不能因为计划 RAG 就删除。当前文本错误分类只证明局部文件样本与假模型链路。
3. 深页索引、跨页快照、token 预算、活动取消与 OS 级路径绑定分别留给有样本和明确场景的切片。首次有副作用工具前须先处理独立的并发/权限契约。

原调研阶段没有修改工具；后续 Spec 031 已修改共享 Read 和测试，验证命令及实测结果见该 Spec。原始探针仅验证两个字节样本；其它维度是源码事实或明确的设计限制。
