# 在输入框中使用图片

当前开发分支支持截图粘贴、拖入图片文件及输入框右侧的图片选择按钮。可以只发图片，也可以同时输入文字；发送前可逐张预览或移除。运行中的图片消息沿原有“引导本轮／结束后跟进”进入同一个 Agent，不启动额外推理。

新图片要求当前模型明确声明 `image_inputs=True`；未知或不支持时保留草稿并阻止发送。服务端也会检查，不能绕过浏览器改成纯文字发送。切为文字模型后，早期历史图仍可查看，但模型只收到明确的像素省略说明，界面同时提示。能力声明并不能证明某个网关确实理解了图片，本轮验证使用离线模型，没有真实供应商视觉评测。

图片草稿只保存在当前页面内存，切换项目／会话可保留；刷新、关闭页面或重启应用后不承诺恢复。文字与图片由同一个会话草稿对象持有。截图粘贴包含图片时，不再插入同次剪贴板附带的来源文字；普通文字粘贴保持浏览器原行为。

发送结果不确定时，原图片请求会冻结。可以明确重试原请求，使用同一请求 ID，已经接受的任务不会重复执行；如果原请求尚未到达服务，此操作可能开始执行。修改后的新草稿不会覆盖原请求。用户也可以人工核对原会话后解除发送锁，再决定如何处理新草稿。未确认的请求保存在当前页面，不承诺跨刷新恢复。

停止后的未选中图片输入会出现在“保留的图片输入”中；已选中但送达未确认时显示“不确定”，不会自动重发。应用持有这些记录，可从另一浏览器打开同一会话读取，保留到应用关闭。列表只显示有界文字预览，恢复时会分块取回完整文字并和图片一起放入原会话输入框。恢复到输入框后仍需明确发送；显式移除或成功重新提交会释放对应记录。CLI 仍接收文字投影，并提示图片需要在 Web 待发送列表查看。

已发送图片只保存实际交给模型的处理后版本，包含缩放、方向修正及必要格式转换；不另存原图，也不会写进项目或沙箱目录。PNG/JPEG/WebP/GIF/BMP 可用，GIF 仅发送首帧并提示；SVG、PDF、HEIC 和伪装格式不作为图片接受。EXIF/GPS 不复制进输出。需要更多细节时，请重新附上原图。

历史列表和 SSE 只传元数据；点击图片后，通过原认证链读取字节，以临时 Blob URL 预览和下载。旧版本或不存在的图片会明确报错。图片随现有数据库聊天记录/checkpoint 保存，数据库快照包含已保存图片；删除会话后不能再从应用读取。普通 Shell 的 artifacts 仍是独立的临时输出归档。

集中设置为 `[image_inputs]`，完整示例见[设置文件](examples/settings.example.toml)，实际默认值见[ImageInputSettings](../naiyue_test_agent/image_input_settings.py)。前端读取服务下发的额度，不维护另一组默认值；修改启动时配置后需重启服务，本功能未增加图片配置热刷新。

| 设置组 | 配置项 | 默认值 |
| --- | --- | --- |
| 原始输入 | max_images_per_message / max_input_bytes / max_total_input_bytes / max_pixels | 4 张 / 单张 10 MiB / 合计 20 MiB / 单张 4000 万像素 |
| 处理后内容 | max_dimension / max_base64_bytes / max_total_base64_bytes | 最长边 4096 / 单张 base64 4.5 MiB / 合计 base64 12 MiB |
| 服务入口 | max_request_bytes / max_in_flight_requests | 图片请求 28 MiB / 同时处理 2 个请求，额度满立即拒绝 |
| 会话待处理 | max_pending_image_messages / max_pending_image_bytes | 图片输入 16 条 / base64 合计 32 MiB；队列与保留记录合计 |

图片处理使用 worker，名额覆盖正文读取到处理结束；HTTP caller 断线不会提前释放正在处理的名额。只有指定图片路由可使用图片请求额度，认证先于读取正文。普通文字命令、响应和 SSE 的既有上限保持原值。
