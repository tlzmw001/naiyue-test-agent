# 第八课 · 停止、插话与收尾

对应场景08。四段已讲解，用户已提交章末复述；下表保留复述与助手纠正。纠正后的再次复述、本人单步调试和故障预测尚未评估，不将已讲内容记为独立掌握。

## 用户复述与对应纠正

| 用户复述 | 核对与补准 |
| --- | --- |
| 停止涉及请求标志和 control 对象，后者有唤醒机制 | AR.stop_requested 供应用层边界读取；RC（RunControl）保存信号及登记的模型任务。RC.request 设置信号，并向任务所属事件循环安排取消回调，不只是设置标志或等待唤醒。用户停止、失败和应用关闭有不同 reason。 |
| 模型调用被包装成 Task，停止通过它的事件循环传入取消 | 主线正确；条件是 control 非空且模型被识别为原生异步。正常未停止时也先经 RC.await_model 创建并登记 Task。request → call_soon_threadsafe → _cancel → task.cancel；await_model 确认取消来源后将 CancelledError 转成 UserStop，由 StopModelMiddleware 转为无新回答的停止结果。外部取消调用者继续传播，结束时移除任务登记。 |
| 模型结束而工具未开始时，停止中间件补用户停止的工具消息 | StopBoundaryMiddleware.after_model 优先处理，找出最近 AI 消息中尚缺结果的调用，补明确未执行的 ToolMessage，再结束图；已有真实结果保留。 |
| 串行工具只能停掉后面尚未执行的调用 | 已进入执行的当前工具不一定已经完成，要按自身机制收束并保留真实结果；通用停止不强杀任意工具线程。后续调用取得串行位置或并发名额后，guarded 再读 RC，停止时不进入下游。已开始的并行调用同样不能被当作未执行。 |
| 插话分立即执行和结束后执行，前者每次模型调用后全部取出 | steering 在下一次模型调用前的 before_model 整批取出，不能修改已经发出的请求；自然结束边界也检查插话。follow_up 只在自然结束边界按入队顺序取一条。此时当前运行尚未释放，仍复用原 AR/run_id/thread_id。 |
| 收尾关闭标志，持久化后把 busy 变 False，最后释放本轮 | 正常路径是收束子执行 → 关闭控制窗口、整理队列 → 必要保存 → release_run 清空 SR.run → 发布 run_finished → 调用真正返回。busy 是 SR.run is not None 的派生值，变 False 与释放占用是同一个关键动作。保存失败不是成功停止；清理满足条件仍可释放 AR，但持久化阻断继续保留。 |

## 核心对象与生效位置

```text
AS：AgentSession
├─ _runtime → SR：SessionRuntime
│               └─ run → AR：ActiveRun
│                         ├─ stop_requested / 两个输入队列 / reply_id
│                         └─ observation → RO：RunObservation
│                                           └─ stop_control → RC：RunControl
├─ controls → CQ：ControlQueue(runtime=同一个 SR)
└─ lifecycle → RL：RunLifecycle(runtime=同一个 SR,
                               controls=同一个 CQ, persistence=已有持久化对象)

图调用的 RuntimeContext.scope.control → 同一个 RC
```

- 控制入口找到 AS.controls，向当前 AR 入队或请求停止；accepted 不等于运行已结束。
- before_model：停止优先；否则取出全部 steering，转换为 HumanMessage 后交给框架合入图状态，再准备请求。
- 模型包装：StopModelMiddleware 在外；_ModelSelectionMiddleware 使用 RC.await_model 管理原生异步模型任务。信号设定与异步任务取消是两项动作。
- after_model：停止边界优先于权限、批次审批和批次计划；补缺少的未执行结果后跳向结束。
- 工具派发：批次计划取得位置后调用 guarded；未停止才进入下游工具包装器和工具函数。
- after_agent：停止 → 全部 steering → 一条 follow_up → 无输入则关闭接收窗口。新消息通过 jump_to='model' 回到模型循环入口，仍执行 before_model。
- QueuedInput 是队列项，prepare_control_messages 才新建 HumanMessage。插话沿用当前 reply_id；后续消息创建新的 reply_id，但 run_id 不变。

## 收尾与状态边界

```text
图结果 → RO.result 记录 completed / stopped / interrupted
       → RL.arun 的 finally 等待 RL._afinish_run
       → 收束子执行 → CQ.close_control_window
       → SessionPersistence.afinish → RunUnitOfWork.finish_run 必要事务
       → RL.release_run：SR.run=None，busy=False
       → RO.finish 发布 run_finished → 向调用者返回结果或异常
```

- 自然结束先关闭 steering_open；控制清理再关闭 controls_open。保存期间 AR 仍在，因此输入已关闭而 busy=True 是正常状态。
- 关闭控制窗口会清空未消费队列及本轮临时引用，并重置 AR.stop_requested；图结果与 RO.status 已保留停止结论，不会因此改为 completed。
- await_settled 等待已启动的必要收尾收束，再传播外部取消；return result 也必须先执行 finally。
- 成功停止且无需复核时，可保存 state=ready、last_run_status=stopped；ready 仍需有效 checkpoint、无 next、无任务中断/错误。
- 必要保存失败阻断普通继续，可能留下数据库 running；不发布成功 stopped。busy=False 只表示运行占用已释放，不证明会话具备全部准入条件。已有主异常不被次要清理故障覆盖。
