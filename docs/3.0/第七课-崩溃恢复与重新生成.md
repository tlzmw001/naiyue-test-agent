# 第七课 · 崩溃恢复与重新生成

对应场景07。四段已讲解；用户先复述主要机制，助手补准并重建对象地图后，用户明确同意按引导后的整理作为本课总结。保留原理解、对应纠正和能力边界，不将认可整理视为独立掌握。

## 用户原理解与对应纠正

| 用户复述 | 核对与补准 |
| --- | --- |
| 重启时对比图状态和保存状态，先合并再更新，复用原线程 | 对比的是持久化会话元数据中的确认位置与当前图快照；正常ready且位置一致时走普通restore。异常continue才执行三阶段更新，第一次合入的是框架已保存任务输出，不是任意合并两份完整会话。沿用原thread_id。 |
| 恢复审批要核对工具、审批权限策略有无变化，保证同一批工具 | 先确认原AI调用、保存批次和interrupt对应且确在执行前；再按当前工具、参数、目标、执行环境和权限复核。重建pending并安装会话后仍等待用户决定，不生成批准结果。 |
| 替换要造一个尚无新用户消息的新线程，再切换会话继续 | 新线程先保存任务前缀，但切换前还必须持久化待重跑的人类输入。准备通过后事务激活新线程及会话版本，同步内存，再由已有会话的RunLifecycle重新运行。session_id不变，thread_id变化；文件副作用不回滚。 |

## 已核对并获用户认可的三条主线

- continue：持久化对象整理原线程，保存后由会话服务创建会话对象；只有新用户消息到来才开始新的Agent运行。
- restore_approval：持久化对象复核原审批点，保存后由会话服务创建带pending的会话；批准或拒绝后进入已有审批续跑链。
- regenerate：使用已有会话，先准备新线程的前缀与输入，再切换该会话的线程和版本，最后由其lifecycle重跑最后一个任务。

## 固定对象地图

```text
Host
├─ SessionAPI / RunAPI → 共享 S、P、G 等引用
├─ S：SessionService → _sessions[S1] → C：AgentSession
│                                      ├─ _runtime：会话状态、当前运行
│                                      └─ lifecycle：RunLifecycle
├─ P：SessionPersistence → sessions=S，storage=D
├─ D：ProjectStore → 会话/归档/回复边界仓储及运行事务
└─ G：图 → checkpointer → 保存的图状态

异常恢复起点：S中尚无C → P读取、判断和处理 → 必要保存 → S创建C
重新生成起点：C已存在 → 编排函数借用S/P/G/D/C → 激活T2 → C.lifecycle.arun
```

C不是所有恢复动作的起点：continue和restore_approval成功后才安装它。正常审批期间服务不退出时，原C与pending仍在；提交审批决定时创建新的ActiveRun，进程和会话对象无需重建。

## 关键边界

- 数据库state有ready、running、failed、interrupted、review_required。新建写ready，运行开始写running；收尾按人工核对优先、审批暂停、失败、其余正常结束选择保存状态。崩溃或事务失败可能留下running，不会自动变成failed。ready不等同任务成功，还需结合last_run_status及当前运行准入条件。
- recovery.kind是读出元数据和图快照后重新分类，分ready、interrupted_execution、pending_approval、unavailable。分类先描述事实，持久化层再结合配置、执行根和当前进程状态补充actions。缺少工具结果只证明未确认，不能断定未执行。
- continue依次cleared（合入已保存任务输出、清旧任务）、paired（仅补缺失结果说明并清工具执行状态）、finished（清后续路由）。as_node='tools'选择状态写入方式，不执行工具节点。每阶段追加checkpoint并保存恢复身份；重试核对最新checkpoint和阶段，不重放旧工具。
- 已有真实结果及artifact保留；未确认调用补status=error、reason=result_unconfirmed的ToolMessage，不将真实副作用判为失败。严格审批前选择continue则补cancelled_before_approval。最终必要事务保存ready/recovered及归档，再安装会话，run=None。
- restore_approval保留原图interrupt，不做continue的三次更新。旧allow必须被当前本地规则重新证明；旧临时session_allow和MCP调用身份等有恢复限制。项目执行版本变化可只恢复过期待审事实供取消，批准续跑仍拒绝。恢复卡片与一次性批准凭证是两个时点。
- regenerate按reply_id及conversation_revision校验最后任务。任务前缀从保存的source checkpoint读取，原人类输入从归档读取并更换消息/任务身份；新线程先保存前缀，再保存输入，之后才激活。激活事务替换旧任务归档尾部、更新线程和版本，再同步内存。准备/事务失败保留原状态；激活后失败不能假装未切换。同request_id返回保存的操作状态，不再次执行。已有文件和外部副作用不回滚。
