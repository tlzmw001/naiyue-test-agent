# 第五课 · 压缩预算与溢出恢复

2026-11-10，对应场景 05。本页保留用户章末总结与对应纠正；本轮讲解与核对收束，纠正后的独立复述和本人调试待检验。

## 用户总结

以下是用户原理解的要点，精确边界见下一节。

- 主要学习预算、首选切点与后续候选切点，以及溢出恢复、手动压缩。
- 触发压缩时兼顾预留量和模型最大输出；摘要完成后，输入只需满足窗口减去最大输出的预算。
- 从最新消息向前累计 token，达到保留量后寻找 HumanMessage，尽量保留完整用户轮次。
- 首选切点不合适时向后寻找 HumanMessage 或 AIMessage；切在 AIMessage 时检查工具配对，并记录所属用户消息的位置。
- 摘要请求区分更早历史和被切开的当前轮次前缀；成功后用摘要与保留消息替换当前图消息。
- 溢出和手动压缩使用强制模式，因此原先理解为切点为零也一定会压缩。

## 对应纠正

| 需要补准的位置 | 当前代码的精确行为 |
| --- | --- |
| “窗口减去触发阈值” | 被减去的是配置的 reserve（预留量），阈值是计算结果。触发线 T = max(0, W − max(O, reserve))；正常发送预算 B = W − O。W 是上下文窗口，O 是最大输出。 |
| “保留量至少始终达到” | keep_recent 是首选切点的保留目标：先向前累计，再退到不晚于累计位置的 HumanMessage。为满足预算，后续候选可能向较新消息推进，最终保留量可能少于该目标。 |
| “首选切点满足就压缩完成” | 此时只确定待摘要前缀和保留后缀。还要检查摘要请求预算、生成并校验摘要、检查真实摘要加入后的估算输入，最后由调用方应用更新。 |
| “AI 切点额外检查工具配对” | 候选搜索对 HumanMessage 和 AIMessage 边界都检查两侧工具配对。AI 边界还需找到所属轮次的非摘要 HumanMessage，供摘要描述当前轮次前缀；它不是另选一个最终切点。手动模式的候选只接受 HumanMessage。 |
| “用户消息前后两部分” | 若 cut = 5、turn_start = 2，则 removed = messages[:5]、preserved = messages[5:]；摘要中的 conversation 是 messages[:2]，turn-prefix 是 messages[2:5]，包含用户消息 2，不包含保留的 AI 消息 5。已有摘要会另外作为 previous-summary 更新。 |
| “做过主动压缩后才可能溢出恢复” | 无论前面是否压缩，只要实际请求返回可识别的上下文溢出错误，都可能进入恢复。恢复只重试一次当前内层模型请求，不重跑整次 Agent 循环和已经执行过的工具。 |
| “force 保证做一次压缩” | force 跳过普通的低于触发线判断，并要求成功结果确实减少估算输入；它不创造安全切点，也不取消预算和内容校验。手动模式找不到合适用户边界可 skipped；溢出恢复无安全方案会失败。 |
| “压缩后满足窗口就绝对不会溢出” | 检查的是近似估算；配置窗口和本地计数不能保证与供应商完全一致，所以仍需要实际拒绝后的恢复。摘要调用自身也需满足“摘要输入 + 摘要输出上限 ≤ W”。 |

## 主链与分支

```text
普通请求准备：未超过 T → 不主动压缩
              超过 T → 尝试切分；允许特定跳过/失败回退
实际模型拒绝：识别上下文溢出 → force → 成功后仅重试当前模型请求一次
用户手动发起：读取已完成 checkpoint → force + manual → 应用并确认写入
                                │
                                ▼
       找首选切点 → 必要时向较新消息搜索候选
                                ↓
       检查摘要请求预算 → 生成摘要 → 校验摘要和压缩后预算
                                ↓
       产出 messages 更新 → 对应调用方应用 → 后续执行或保存
```

普通模式下，首选切点为 0 且原请求仍在 B 内，可跳过压缩；某些摘要失败仅在原输入仍可安全发送且历史校验通过时允许回退。强制模式不能用这条失败回退继续发送原请求。手动模式仍有明确的 skipped 分支。

正常示意：W = 350、O = 20、reserve = 60，则 T = 290、B = 330；估算输入超过 290 会尝试主动压缩，成功后的输入不要求降到 290 以下，但要不超过 330。寻找候选时用摘要输出上限预估，拿到摘要后再以实际摘要重新估算。

手动压缩的 applied 还需要 checkpoint 写入及回读确认；摘要生成成功不等于保存成功。必要写入结果不明确时限制继续运行，不能当作普通 skipped。压缩更新当前模型上下文，不因此删除用户可查看的原始聊天记录。
