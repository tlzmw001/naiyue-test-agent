## 贯穿例子与数据链

课堂示意：会话A声明项目测试使用 .venv；旧候选可能缺持久选择，工具结果可能提供有限观察。会话B以后询问测试方式。示意值不是真实供应商请求或已保存业务记录。

```text
会话A的输入/工具结果 → 聊天归档
    ↓ 根运行正常结束、必要保存成功后放行
MemoryJobs → MemoryJob → 按归档顺序和预算构造当前 batch
    ├─ 程序保留：消息ID、版本、线程、偏移等
    └─ 模型阅读：来源编号、可见文本等
旧概览/覆盖信息 + 本批资料 + 相关旧记忆 → 整理模型
    ├─ overview → 检查历史版本/范围 → 更新会话当前概览
    └─ proposals → 编号/唯一引文匹配 → 正式请求与权限检查
         → 事务内重新核验归档 → 激活门禁/版本检查
         → 当前记忆、版本快照与来源引用

会话B正常根用户轮准备
    → active 用户类记忆 + 最新合格用户问题搜索的 active 记忆
    → 符合首次条件时的其他会话目录/有效短概览
    → 有限索引和详情入口 → ActiveRun.prompt_parts → 系统消息
    → 模型按需调用 memory/history → 身份、权限及实际读取
```

checkpoint 供原图线程继续执行；聊天归档保存可查询原文；压缩摘要用于控制图消息长度，可进入 checkpoint；会话概览记录该会话进展；独立记忆支持后续复用。它们不是同一种数据，也不共享同一套有效性结论。

## 补读后的关键边界

- 对象：ProjectHost 的 MemoryAPI、MemoryJobs 和 SessionPersistence 共享已有依赖；同项目会话使用项目记忆范围，不同 Host 借用应用级 PersonalMemory。owner/_owner 在相关 API 中指 ApplicationLifetime，协调使用与收尾，不代替业务授权。普通聊天个人记忆与项目后台整理的装配不同。
- 批次：按归档顺序、位置与预算构造，human/ai/tool 可混合，长消息可分段；不按角色分批，不保证执行上下文那样的工具配对边界。只投影允许的可见正文，不把原始 tool_calls、隐藏推理或 artifact 全量送入。
- 两种查询：后台 _related 优先拼接当前初步 batch 的 human 文本，无则用第一段来源，截取前部；读取阶段 _query_text 取本轮最新合格 HumanMessage，排除摘要/委派/插话，并过滤弱查询。两者不能混用。
- 旧记忆更新：查询并按版本读完整记录；模型看旧ID、正文和缺口，程序保留版本。模型选旧ID，proposal_request 只接受本次实际提供的唯一完整记录，并回填 expected_version；库中已变化则 memory_conflict。自动索引仅供应 active，候选由显式读取或整理使用。
- 概览连续性：previous_overview 是旧进展，previous_coverage 是来源范围与遗漏；模型生成新的完整正文，程序合并范围/缺口。新增消息可令 has_newer_messages=True 而不使旧概览 stale；历史修订/分支变化使其失效，准备及提交再次核对版本。失效不代表自动重建全部旧历史。
- 保存与反馈：引文不匹配、来源变化、权限失败均拒绝相应条目；已成功概览/记忆保留，任务可 partial，来源改写也可令两者均失败。来源不可用不自动清除已保存记忆，使用方须看 source_status、条件与当前事实。

## 词法检索：已观察到的限制，未实施优化

查询及记忆标题/别名/正文均使用确定性词项规则，无额外模型挑关键词。技术锚点是硬条件；全文索引/BM25及排序后，优先完整词段覆盖，否则按配置覆盖率回退。连续中文完整片段与二字词项是不同粒度，完整覆盖不等于整句相等。

用户主动指出长 batch 用户原文拼接后难以完整覆盖、部分主题会被长查询稀释；助手纯函数探针核对：示意长查询与旧正文重合6/14，增加另一话题后为6/23；另一示例原始重合3/4，但缺 .venv 技术锚点，feature 提前返回(False,0.0)。0不能解释为没有重合词项。这里只验证词项与筛选函数，未验证完整召回质量。用户决定先继续学习，后续独立写优化方案；没有批准或实施检索改动。
