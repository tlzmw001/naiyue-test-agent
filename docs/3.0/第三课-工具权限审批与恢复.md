# 第三课 · 工具权限、审批与恢复

2026-11-09，对应场景 03。讲解与本轮总结核对收束，按用户要求进入下一场景；本页保留复述、纠正与后续复习点。

## 用户总结

以下保留用户原理解的要点，精度问题见下一节。

- 模型请求工具后，进入权限中间件的 after_model；工具的权限策略和相关参数事先准备好。
- 创建临时审批中间件对象，设置允许的决定、判断函数和描述，再通过中断请求触发框架可识别的异常，得到审批请求。
- 校对审批请求与工具调用，经 RunLifecycle 中持有的审批对象，把待审批请求存入共用的 runtime。
- 结束本次运行，等待用户决定；同意后通过 RunAPI 的恢复入口找到会话、核对批次并读取之前保存的信息。
- 恢复原来的执行，并把新的运行写入 RunLifecycle。
- 补充辨认：一次性凭证刚消费时运行没有结束，后面仍要执行工具；能说出 L 发起待审批记录更新、A 修改共用 R 的关系，但一度将该动作提前到凭证消费时点，已反馈纠正，用户自述理解。

## 对应纠正

| 需要补准的位置 | 当前代码的精确行为 |
| --- | --- |
| 权限中间件负责整个审批功能 | PermissionMiddleware 准备目标并判定 allow/deny/ask；BatchApprovalMiddleware 为需要询问的调用组织框架审批；ExecutionAuthorizationMiddleware 在执行前检查凭证并附上许可。 |
| 权限策略和参数都事先准备好 | 工具声明、参数 schema 和配置规则提前装配；本次调用参数来自模型响应，目标信息和权限决定在处理本批调用时生成。恢复时可复用图状态中已准备的同一批次。 |
| 临时观察中间件 | 实际是 ObservedHumanInTheLoopMiddleware，继承框架审批中间件并增加观察和停止处理。allowed_decisions 是用户可选项，when 筛选具体调用；它们不是用户已经提交的决定。 |
| 针对描述发起中断 | description 是说明。框架收集需要审批的 action_requests 和 review_configs，再调用 interrupt(hitl_request)；首次没有恢复值时抛出 GraphInterrupt，由图处理并提供中断结果。 |
| 校对后再找到 RunLifecycle | RunLifecycle 本来就在等待图调用的结果。返回后调用 pending_tool_approval(result) 校对，再让已有的 ApprovalBook 写入同一个 SessionRuntime.state.pending_tool_approval。 |
| runtime 保存恢复所需的一切 | 会话中的待审批记录与图的 checkpoint 分工不同：前者支持展示、门禁和审批校验，后者保存图状态及中断恢复位置。恢复沿同一 thread_id 传入 Command(resume=...)，中断节点从头重跑，并在 interrupt 处取得决定。 |
| 批次核对都在恢复方法里 | 真实 Web 提交经 RunAPI.prepare_approval → ApprovalBook 校验批次 ID 和来源运行 ID；随后恢复入口再执行运行准入与决定校验。课堂直接 resume_approval(session, ['approve']) 绕过 Web 提交转换。 |
| 新的运行写进 RunLifecycle | 复用同一个 AgentSession、R、A、L；L.admit_run 创建新的 ActiveRun U2，保存到 R.run。旧 U1 已结束；恢复的是同一图线程中待完成的调用。 |

## 对象和状态小地图

```text
AgentSession 创建 R=SessionRuntime(session_id, state)
├─ _runtime → R
├─ approvals → A=ApprovalBook(R)，A._runtime → R
└─ lifecycle → L=RunLifecycle(R, approvals=A, ...)
               L._runtime → R，L._approvals → A

审批暂停收尾后：R.state.pending_tool_approval=记录，R.run=None
审批恢复准入后：R.state.pending_tool_approval=原记录，R.run=新 ActiveRun U2
正常完成收尾后：R.state.pending_tool_approval=None，R.run=None
```

执行前授权补充：prepare_resume 根据待审批记录和用户决定生成 OneUseApprovalGrants G，经 RuntimeContext.inputs.approval_grants 传给图。授权中间件核对会话、批次、调用、参数和目标后消费 G 中的对应凭证，为当前工具请求附上 ToolAuthorization.permit；文件工具再核对许可和当前目标。G 的凭证消费与 A 清空会话待审批记录发生在不同阶段。
