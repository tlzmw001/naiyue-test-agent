## 用户复述与对应纠正

| 用户复述 | 核对与补准 |
| --- | --- |
| 后台任务放进新的类，再被 AgentSession 引用；新 AgentSession 也能查询 | 托管对象是 SessionService 创建并持有的 BPM（BackgroundProcessManager），其中 _entries 保存 _Operation，后者持有 worker/capture。AS 的 RL 和图上下文借用同一个 BPM。普通下一轮复用同一个 AS/SR，新建的是 AR/run_id；后台任务跨 AR 保留。服务重启新建 BPM、登记表为空，不会恢复原 worker。 |
| 前后台都创建异步任务；前台循环观察，转后台返回任务 ID | 主线正确。受管路径一开始都由 BPM 创建 worker 驱动 Runner；前台循环等待最终结果、报告进度、转发本轮停止，符合条件才切换采集策略并返回回执。转换保持同一任务记录、worker、命令进程和原执行期限；不是重新启动或重新托管进程。 |
| 返回后，Agent 用任务工具查询后台输出 | 正确。task_output 从本轮上下文取 TaskQueries 和会话/目录范围，分发到 BPM，读取原 capture 的有限快照，不重启命令。应用 TaskAPI 也能进入查询链，不必调用模型。 |
| 查询和通知是后台任务类提供的新方法 | 查询主线已复述；通知还需区分终态待交付记录、轮初冻结快照、实际提示词片段和响应接受后的版本确认，不能等同一次查询。此细链由助手补充，用户尚未独立复述。 |
| 前台依靠 RC 停止，后台 RC 变成 item | RC 不会变成 item。两者一直是独立对象；受管路径的 Runner 从一开始收到的 control 就是 _Operation。前台等待循环读 RC.requested，再调用 _request_stop 设置 item.requested；显式后台提交只在交接前检查 RC。回执返回后，该循环不再转发旧 RC，任务由 BPM.stop/aclose 等入口控制自己的标志。 |
| 基于操作系统新建进程并传入参数，父子进程间用管道接收输出 | 主线正确。create_task 只安排协程；Runner 执行 loop.subprocess_exec，经本机 asyncio 子进程传输到 subprocess.Popen 才创建 OS 进程。Runner 指定 stdout=PIPE、stderr 合并及 stdin 策略，框架建立管道并回调 ProcessProtocol，之后交给 capture。不是子进程创建时自动向项目保存输出。 |

## 固定对象与运行地图

```text
SessionService
├─ background_tasks → BPM
│                      └─ _entries[task_id] → _Operation
│                                             ├─ requested / status / 原 run_id
│                                             ├─ capture：ProcessCapture
│                                             └─ worker → BPM._drive → runner.run(req, consume, item)
├─ task_queries → TaskQueries(shell=同一个 BPM)
└─ AS：AgentSession
   ├─ _runtime → SR：SessionRuntime → run=None/当前 AR
   └─ lifecycle → RL：RunLifecycle(_process_tasks=同一个 BPM)

本轮准入：新建 HostFileSystem → 新建 HostProcesses(files) → AR.files/processes
调用图前：AR 的能力引用 → RunScope.capabilities → RuntimeContext → 图的 context 参数
框架：Runtime.context → 为工具建立 ToolRuntime；授权可创建局部 context，仍共享 scope
工具：ToolRuntime.context.scope.capabilities
      ├─ processes → 本轮 HostProcesses
      ├─ process_tasks → BPM
      └─ task_queries → TaskQueries（正常应用装配路径）
```

SessionRuntime 管会话占用与状态，不是工具函数参数中的 ToolRuntime。RuntimeContext 由应用为图调用创建，既有能力通过引用传递，不由类型标注或模型生成。

## 已讲清的运行边界

- 显式 background=True：执行前授权与环境校验 → _register 检查本轮 RC、按 (run_id, tool_call_id) 核对重复调用 → 固定请求/配置并新建记录、采集器、worker → 返回 task_id 回执。starting 不表示进程已创建；running 不表示 HTTP 服务就绪。
- 自动转换：根 Agent 具备 BPM 时，background=False 走 foreground。达到前台等待阈值且未停止、未退出、原期限未到等条件成立，先 promote 采集策略，再检查条件，标记后台并返回。归档准备有 await，因此必须复核期间到达的停止、退出等变化。原期限较早或相等时不靠转换延期；短命令交回 ForegroundResult，正常清理后移除临时记录。
- 输出采集与进度观察不同：worker 的管道回调 → 字节队列 → deliver(consume) → capture.record 持续存在；前台额外取 snapshot 并 on_progress。转后台后这次工具调用返回，旧进度回调和 RC 转发停止，底层采集/监控继续，不向原 tool_call 再补第二份最终结果。
- 查询：TaskQueries 分发到真实拥有者，BPM 核对 task_id、session_id、执行目录，再取状态与输出快照。任务记录不属于新 AR，也不需要用旧 run_id 才能找到；未知/越界任务被拒绝。
- 通知：终态 finished/lost 登记待交付版本，不自动唤醒模型。正常新用户轮准备资源前取有限、不可变快照，固定到 AR 的提示词片段；本轮中途新完成项留给后续用户轮。实际提示词确含匹配状态片段，模型响应通过校验且未停止，才确认该快照的版本；预览、未发送、失败/拒绝/停止保留。确认不删除任务，不等同业务处理成功；当前运行已冻结片段仍可能在后续模型调用出现。
- 停止：当前 RunAPI.stop 改 AR/RC，不遍历已交接后台任务；BPM.stop 设置 item.requested 并等待原 worker。Runner 读 item，执行终止、收束创建操作/进程/管道/消费者，capture 再结束归档。worker.done 不等于 cleanup_confirmed；stop 返回状态也须检查清理事实。
- 清理：正常路径要求 process_reaped、pipes_closed、consumer_settled、capture.closed。无法确认时保留 lost，阻止相关删除/输出清理；finished 不等于命令成功，输出完整性也另行判断。ApplicationLifetime 除停止当前运行外还调用 BPM.aclose，关闭登记入口、请求任务 app_close、等待并核对清理；未确认则报错。
- 跨轮不等于跨服务重启：正常关闭后新 BPM 不恢复旧登记/worker，聊天和归档可保留；异常退出后不能因登记表为空断言旧命令已清理，也不自动重放命令。已交接命令的外部副作用与根运行保存事务不是同一个事务。

## Bash 与 Runner 补读

```text
bash execute → HostProcesses.shell → BashAdapter.build_request
  argv=[executable, '--noprofile', '--norc', '-c', 完整 command 字符串]
  cwd=选中的执行目录；env=父环境副本加配置；有效执行期限单独计算
  → BPM._drive → HostProcessRunner.run
  → loop.subprocess_exec → 本机 asyncio 传输 → subprocess.Popen → OS Bash 进程
  → stdout/stderr 管道 → ProcessProtocol.pipe_data_received
  → 队列/output_ready → deliver(consume) → ProcessCapture.record
  → OutputAccumulator 增量解码/有限尾部 + ShellOutputArchive
  → 最终结果或 task_output 快照 → ToolMessage
```

- command 经 argv 的 -c 参数进入 Bash，由 Bash 解析重定向、管道和命令分隔；它不是 stdin 内容。普通 Shell stdin=DEVNULL，无持续输入、无 TTY；命令自身可用文件/管道重定向。Runner 内部 stdin_fd 供有限输入路径使用，后台禁止借用这种描述符。
- 当前 Shell 合并 stderr 到 stdout；Protocol 收 bytes chunk，不保证一行或完整字符。回调只入队/发信号，消费者把写入交给 capture；增量解码处理跨块字符，队列积压时暂停管道读取并在消费后恢复。
- 课堂测试例子 printf approved > created.txt; pwd：前半 stdout 重定向到文件，后半工作目录进入捕获管道。每次工具调用新建 Shell，某次 cd/export 不自然延续到下一次调用。
