# 云端结果接收、分析与代码交付

当前为云端任务候选界面的S08实现，正式入口切换在S09实机门禁之后。本机测试通过不等于Windows＋Linux公司环境已验收；本轮不部署、不更新真实镜像或配置。

## 三种动作

1. 在任务的“结果与产物”选择固定结果，按需要勾选实际报告，点击“接收到本机”。输出清单和代码patch总会一起保存。文件写入本机项目数据目录下的私有`cloud-results`，不覆盖项目代码。关闭浏览器不会让已接收材料自动变成主会话消息。
2. 点击“交给主会话分析”将说明文字和材料引用放到主输入框；已有草稿保留。只有点击发送才产生用户消息与本机模型调用。`cloud_result_read`按材料ID读取本机已核对文件；离线可用，不自动回源取最新版。报告正文来自真实工具消息，始终标识为云端任务上报，不冒充用户原话或本机验证。未发送草稿保存在当前标签页sessionStorage；正式发送后引用随会话历史持久化。
3. 需要拿到代码时，在“受控代码交付”选择动作并预检，再确认执行。接收、分析、交付分别授权。

| 方式 | 行为与条件 |
| --- | --- |
| 导出新目录 | 填当前授权项目根内的新目录名，完整输出写入该目录；目标已存在即拒绝。失败暂存目录保持同一身份，续补只接受固定输出的正确前缀，不遗忘旧副本。 |
| 创建本地分支 | 仅Git来源且原捕获回执/原HEAD对象存在；包括初始未提交改动与云端改动，保留范围外原HEAD文件及gitlink。不checkout，不改当前index、HEAD和工作区。 |
| 应用到当前目录 | 只改I→O变化路径，当前旧字节必须仍等于输入I，新增路径必须不存在；无关本地改动可保留。预检后仍在发布前复核，新增独占发布，失败显示partial并保留日志/备份。 |

应用前暂停本机Agent和编辑器对相同路径的写入。普通文件系统无法提供跨进程内容CAS，最终复核与替换之间仍可能遇到不合作进程写入；这不是整棵目录事务。遇到冲突先检查现场，再显式继续原ID；系统不会用自动回滚覆盖后来出现的用户内容。

分支按捕获时冻结的text/eol/autocrlf规则处理Git blob；导出和应用保持原始字节。filter、LFS、ident及working-tree-encoding超出支持集时分支明确不可用，可以改用导出/原始字节应用。缺少原HEAD或捕获回执也不猜测新的分支基线。

## 状态、存储与配置

接收台账、材料索引及代码交付台账保存在本机项目SQLite（当前schema23）；实际字节、传输staging、操作日志和备份位于相邻的私有管理目录。云端任务删除或环境释放不自动删除已接收材料。接收记录同时固定本机source_handle，任务删除脱敏创建请求后，代码交付继续使用该固定来源核验本机I，不按相同内容猜测其他来源。主会话正在接收结果本身不会开始分析；正在准备/执行代码交付则阻止并发删除会话，保证worker必要回执有归属。

接收记录状态为reserved/downloading/verifying/available/failed/unknown；代码交付为preparing/prepared/executing/completed/partial/failed/unknown。GET只查询，不下载、不执行、不重新写项目。初次请求回执不明时核对同一ID；接收失败显式继续原ID，available后用户再次接收可建立新ID来恢复丢失缓存。交付也沿原ID核对/继续，不另起覆盖操作。

`AppSettings.cloud_tasks.receive_limits`管理接收并发、文件/缓存/分页预算；`input_limits`控制输入归档恢复，`result_limits`控制patch、输出条目/总量与Git执行预算。均为配置模型中的字段，本轮没有修改用户配置。默认接收单文件64MiB、私有接收缓存512MiB，接收和交付各最多4个producer，读取单页最多64KiB；这些是保守应用准入预算，不宣称操作系统硬磁盘配额。交付临时验证树与导出目标各有真实磁盘IO，不能把元数据比较时间当完整交付耗时。

缓存缺失时，代码交付可通过owner-only固定输入归档下载恢复I，逐段Range/If-Range并最终核对归档SHA与清单。材料读取工具不会偷偷走这条网络路径；缺失本机材料会明确报不可用。

## 下一步：S09.1真实环境门禁

逐步操作见[Windows＋Linux实机手册](cloud-s091-windows-and-linux.md)。保持当前正式A入口。Windows与Linux使用同一份候选代码/包，先按[验收矩阵](specs/143g-acceptance.md)和[143h新增公司差集](specs/143h-s00-backend-gate.md)验证Runner/管理网络、全部模型供应商出站、隧道断开/恢复、必要保存与真实结果取回；另补Windows路径/reparse、文件锁、CRLF、分支和partial恢复。原S00通过记录继续有效，不重复追认为未通过。

门禁前后执行消费者核对：

```bash
.venv/bin/python -m scripts.a_consumer_inventory check
```

发生已审阅源码变更时，先核对差异，再显式freeze；check不会自动批准新消费者。S09.1门禁通过后才切正式Web/CLI与退出A运行消费者；S09.2清理余留工具/打包文档。S10更新管理与S11组合性能验收尚未实施。

当前共享运行上下文变化触发了保留A执行包的源码完整性门禁；`release/envd.json`独立构建版本同步到未发布的0.5.7，执行源码摘要更新，65文件/45依赖锁保持原集合。此文件是本地构建清单，未发布执行包或更新远端镜像；S09正式退出A时再按消费者清单核销。


后台测试服务仍在运行时，可以直接发送下一条提示。上一轮若尚未开始保存，会明确显示“已由后续运行替代”，没有该轮的独立文件快照；开始保存后则先等待保存结束，避免不同轮的文件混在一起。保存失败时可重试或明确放弃，不把失败显示为正在保存。

云端默认保留最新一份完整结果，较旧且无人接收或下载的结果会清理文件并保留执行结论。需要长期保留的代码/报告请接收到本机；完整本机材料后续可离线分析与交付。正在接收的材料有短期保护，进程长期离线导致保护到期后，未下载完整的旧结果可能不可再取回。结果保留数不是会话总轮数上限，仍受历史、存储及运行资源各自的预算限制。
