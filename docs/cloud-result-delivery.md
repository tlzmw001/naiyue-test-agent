# 云端结果接收、分析与代码交付

当前工作区的正式Web入口使用云端任务链，S09实机验收按用户要求留待后续统一执行。本机测试通过不等于Windows＋Linux公司环境已验收；本轮不部署、不更新真实镜像或配置。

## 结果窗口与三种动作

任务详情点击“结果与产物”，在屏幕中央选择该任务的固定运行结果。窗口内部滚动，Escape或关闭返回原入口；关闭观察不会取消已登记的下载/交付，重开查询原操作。列表使用真实创建时间，结果显示创建/捕获时间与辅助短运行ID。

| 入口 | 行为与保存位置 |
| --- | --- |
| 报告与产物 | 只展示本轮专用产物目录中的报告等artifact；勾选后浏览本机目录，选择已有目录或新建文件夹。保存为普通文件，保留产物相对结构，不登记成项目。 |
| 代码取回 | 只提供应用到当前代码，以及Git来源符合条件时创建新分支；先预检，再确认。代码覆盖范围仅为本次变化路径。 |
| 交给主Agent分析 | 自动准备所选报告和同一固定结果的清单/patch，回填来源主输入框，保留已有草稿并去重引用；用户发送后才调用模型。无需先保存报告到普通目录或应用代码。 |

普通UI不再提供浏览器单文件下载或代码导出目录。现有明确对外的export交付API继续保留；底层固定字节传输仍用于预览和本机接收。

文件分类由来源目录决定：默认`.nyt-output/<本轮根run_id>/`内的普通文件属于报告产物；范围外的源码、配置、项目文档和资源统一作为项目文件变化。不是按扩展名或模型的语义判断；实际产物目录受任务固定计划约束。manifest与patch用于内部校验和分析，不混入报告勾选列表。

### 报告同名与中断

保存前固定目标目录观察身份和文件状态。预检完成后直接点击“确认保存文件”，没有额外的“已核对保存位置和文件”勾选；选择目录和预检本身不写入文件。同名同内容可计为已保存；内容不同列出路径，须先勾选确认覆盖，再点击保存。已有保存意图时锁定原报告选择，确认区域列出实际文件；显式更换位置或选择后才能修改。预检后文件再次变化则停止，重新预检后才能覆盖；采用新预检/查询回执会清除覆盖勾选，须重新确认。目录、链接或权限问题不可用覆盖确认绕过。

所有字节先下载并核对固定摘要，复制私有临时副本时持有并复核同一源句柄，成功后再逐文件发布。失败显示真实partial进度，不自动回滚后来的用户修改；继续沿原交付ID和日志进行。新文件夹采用原有独占发布流程，拒绝接管后来出现的目录。

### 代码预检、覆盖与连续多轮

不可变输入I用于校验云端patch、还原完整结果O。本机应用基线B与I分开：首次B=I，后续使用同一目标目录、云实例、task和input下最后完整成功应用的O。变化按B→所选O计算，预检比较这些路径的实际本机状态L。

普通应用要求本机内容匹配基线或已等于目标。内容不同可以明确选择强制应用，仅覆盖或删除本次变化路径，保留其他本地文件。确认针对预检所观察的L；执行前再次变化会拒绝，必须重新预检。完整性、非法路径、目录身份和IO失败不能强制绕过；应用、创建分支和底层导出均在预检阶段列出非便携路径（例如保留设备名或含冒号的名称），不能用强制覆盖绕过；备份保存真实L，包括云端新增路径在本机已有的文件。

完整成功回执与B推进在一个SQLite事务提交。partial/unknown不推进B，保留原日志核对；完成保存失败后可继续原操作。报告保存、分析和创建分支都不推进当前目录B。第二轮可正确识别上一轮新增文件的删除，以及恢复成原输入的文件。非Git项目使用同一预检/应用合同；没有创建分支入口。

新分支要求Git来源的原捕获回执、原HEAD和当前有效仓库；分支包含初始捕获的未提交改动及云端改动，保留范围外HEAD文件及gitlink。不checkout，不改当前index、HEAD和工作区。分支沿捕获时冻结的text/eol/autocrlf规则处理Git blob；filter、LFS、ident及working-tree-encoding等超出支持集时明确拒绝分支，原始字节应用仍受自身预检约束。首版不做自动三方或上下文合并。

同服务内按项目及实际目标目录/父链身份预留写入，阻止不同项目通过同目录、嵌套或大小写别名互相覆盖。普通文件系统不能提供跨进程内容CAS，外部编辑器仍可能在最终复核与替换之间写入；这不是整棵目录事务。

### 主Agent读取与私有缓存恢复

`cloud_result_read`按材料ID和项目/会话权限读取本机已核对的不可变字节，分页返回文本；二进制材料当前只提供元数据，不在此片增加PDF/图片解析。工具读不访问任意远端路径，也不自动下载最新版本。结果标识为云端任务上报，不代表本机验证成功。

材料缓存缺失/损坏时，界面提供显式“重新核对…材料”。它修复原receive_id，保留material_id、原artifact与SHA；损坏的普通单链接私有blob先隔离保留，再按原Range/ETag/长度/SHA接收。完整验证后，按原材料引用及旧文件身份CAS更新该接收记录；其他共享SHA的材料不静默重绑。原partial交付继续使用同一接收ID、交付ID和日志。普通GET、工具读取和普通retry不自动修复。

结果窗口提供“清理未引用缓存”：显式核对本项目全部会话的接收和材料引用，只回收没有引用的 blob，以及不再用于续传的 staging/quarantine。仍被引用的材料、交付日志和备份、用户保存目录均保留；正在接收、交付或读取材料时拒绝清理，稍后可再操作。完成后显示实际删除文件数和释放字节数；没有可回收项时明确提示。清理按条目预算执行，残留较多时可再次点击。若额度主要被仍有引用的材料占用，清理孤儿缓存不会释放这些材料的额度；此入口不提供强制删除材料。

## 状态、存储与配置

接收台账、材料索引及代码交付台账保存在本机项目SQLite（当前schema23）；实际字节、传输staging、操作日志和备份位于相邻的私有管理目录。云端任务删除或环境释放不自动删除已接收材料。接收记录同时固定本机source_handle，任务删除脱敏创建请求后，代码交付继续使用该固定来源核验本机I，不按相同内容猜测其他来源。主会话正在接收结果本身不会开始分析；正在准备/执行代码交付则阻止并发删除会话，保证worker必要回执有归属。

接收记录状态为reserved/downloading/verifying/available/failed/unknown；代码交付为preparing/prepared/executing/completed/partial/failed/unknown。GET只查询，不下载、不执行、不重新写项目。初次请求回执不明时核对同一ID；接收失败显式继续原ID，available后缓存丢失须显式refresh原接收ID，重新验证并保留原材料引用。交付也沿原ID核对/继续，不另起覆盖操作。

`AppSettings.cloud_tasks.receive_limits`管理接收并发、文件/缓存/分页预算；`input_limits`控制输入归档恢复，`result_limits`控制patch、输出条目/总量与Git执行预算。均为配置模型中的字段，本轮没有修改用户配置。默认接收单文件64MiB、私有接收缓存512MiB，接收和交付各最多4个producer，读取单页最多64KiB；这些是保守应用准入预算，不宣称操作系统硬磁盘配额。交付临时验证树与导出目标各有真实磁盘IO，不能把元数据比较时间当完整交付耗时。

缓存缺失时，代码交付可通过owner-only固定输入归档下载恢复I，逐段Range/If-Range并最终核对归档SHA与清单。材料读取工具不会偷偷走这条网络路径；缺失本机材料会明确报不可用。

## 后续统一实机验收

逐步操作见[Windows＋Linux实机手册](cloud-s091-windows-and-linux.md)。S09正式入口已改为B，不再提供旧A菜单或按会话Docker环境。Windows与Linux使用同一份候选代码/包，先按[验收矩阵](specs/143g-acceptance.md)和[143h新增公司差集](specs/143h-s00-backend-gate.md)验证Runner/管理网络、全部模型供应商出站、隧道断开/恢复、必要保存与真实结果取回；另补Windows路径/reparse、文件锁、CRLF、分支和partial恢复。原S00通过记录继续有效，不重复追认为未通过。

门禁前后执行消费者核对：

```bash
.venv/bin/python -m scripts.a_consumer_inventory check
```

当前check拒绝重新引入旧A生产模块/导入/前端入口/脚本，不再提供freeze；原914条清单保留为历史审计。用户已要求先完成S09.1/S09.2后统一验收，正式入口与运行清理已实施。旧envd构建及其发行清单已退出，共享测试工具版本记录在`release/cloud-test-toolchain.json`；未发布执行包或更新远端镜像。S10更新管理与S11验收脚本已实现；真实更新演练与组合性能结果按最终实机验收手册登记。

后台测试服务仍在运行时，可以直接发送下一条提示。上一轮若尚未开始保存，会明确显示“已由后续运行替代”，没有该轮的独立文件快照；开始保存后则先等待保存结束，避免不同轮的文件混在一起。保存失败时可重试或明确放弃，不把失败显示为正在保存。

云端默认保留最新一份完整结果，较旧且无人接收或下载的结果会清理文件并保留执行结论。需要长期保留的代码/报告请接收到本机；完整本机材料后续可离线分析与交付。正在接收的材料有短期保护，进程长期离线导致保护到期后，未下载完整的旧结果可能不可再取回。结果保留数不是会话总轮数上限，仍受历史、存储及运行资源各自的预算限制。
