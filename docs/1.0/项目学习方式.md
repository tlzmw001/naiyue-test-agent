# 项目学习方式

用于 Naiyue Test Agent 的代码走读、架构学习和面试准备。开始或接续课堂前，结合[3.0 当前课程](../3.0/README.md)和当前源码确认本次主题。用户明确说「开始」后进入新一轮课堂。每次围绕一个完整机制，可包含多个分支和测试。讲解和练习一起计入每日 1–2 小时，按实际难度调整节奏。

## 场景如何分段

- 开场列出总段数、每段学什么、实际运行从哪里到哪里。用同一个例子按运行顺序推进。测试准备与正式运行分别标出，提前说明哪些问题留到后续段或其他场景。
- 每段开头用一句话接上上一段的输出，再说明本段起点、终点和要学会的调用链。用 `类.函数（文件.py:行号）→ 类.函数（文件.py:行号）` 标出真实入口和关键节点，说明各类的职责及各函数接收和交付的数据。段末说清本段产物怎样成为下一段的输入。
- 每个场景先定位用户在软件里的实际操作，再对照课堂测试。分别画出真实入口和测试入口，标明进入共同实现的位置。比较应用装配、输入、模型与工具、存储、结果返回和界面显示的差异，指出测试替换或绕过了什么。影响当前机制的差异带读关键代码，其余标明所属场景。
- 测试用于反复观察项目的真实机制。先给测试准备到真实应用准备的对应关系，讲完后回到软件操作，说明相同机制怎样处理实际数据。分别标明源码核对、确定性测试和真实外部运行的证据。
- 对每项前置知识标明已讲、本段先补或后续展开。后续展开要给出具体场景及内容，同时在本段提供足够读懂主链的职责、输入输出和归属说明。通过当前例子检查用户是否能解释每个关键对象的来路和去向，决定是否需要补充。
- 对跨章节协作的多个组件，先提供当前路径的职责与生效时点总览，标明实际启用条件、触发频率、当前深读项和后续所属场景；每段在同一张地图上标出当前位置。总览优先按框架的钩子或触发入口分组，在每组内列出实际执行顺序、组件及方法、主要功能；组件内部的直接调用另行标明。按执行机制区分阶段调度与嵌套包装，同一组件参与多个阶段时分别列出，避免把注册清单当作一条从头到尾执行一次的流程。

## 备课时检查前置知识

沿本段入口向前追准备过程，再沿执行方向追到本段终点，检查以下关系。对当前理解必要而尚未介绍的部分，先补足背景再读函数。

- **存在与归属。** 关键对象是谁创建的、何时创建、由谁持有、服务多大范围、何时复用或结束。参数怎样接到接收对象的属性，传递过程中哪些对象共享、哪些新建。检查辅助函数或工厂隐藏的准备步骤。
- **触发与顺序。** 当前代码为什么会执行、由谁触发，前一步通过什么注册、调用或调度关系进入这里。先说明组件是按阶段依次调度，还是彼此嵌套调用，再画进入方向与结果返回/异常传播方向。同名的函数参数按当前栈帧解释它实际指向的后续动作。说明创建时确定的规则和执行时发生的动作，以及异常、中断等怎样改变路径。

  调用链每个关键箭头都说明连接依据，并选取实际调用语句展示。区分直接调用、属性持有的对象或函数、按键查找、回调注册、依赖注入及框架调度等机制。动态选中的目标先交代选择值、查找位置和当前实际对象，再追其方法；返回箭头标明实际返回的数据及接收位置，按计算发生的位置说明后续处理。
- **数据与时点。** 先说明当前场景为什么需要这份数据，再展示必要的数据形状。沿同一次真实处理追清每份关键数据的生产者、产生阶段、传入路径、消费者及使用结果；字段在实际产生和使用的位置解释，不先列完整字段表。区分用户原文、程序读取或构造的数据、模型提议和最终保存结果，不把它们当成同一份内容。
- **当前执行实例。** 同一个函数可能被多次调用，讲计算前先明确当前是哪次调用、具体参数是什么、引用哪些共享对象。用具体值逐步展示计算和状态变化，区分声明顺序、实际执行顺序和完成顺序。
- **跨层传递。** 沿同一个例子追踪每层收到和交出的具体值，标出哪里发生包装、转换、拦截或重新抛出。把下层发生的事实、当前层收到的返回值/异常与最终业务状态分别说明，再解释当前层为何选择这个分支。
- **结论与条件。** 解释一个字段或检查结果能说明什么，并核对下一步还需要哪些条件。对控制动作标出适用对象、处理阶段与生效时点，分别检查尚未开始、正在执行和已经完成的操作会受什么影响。把设计理由关联到具体正常与失败例子，按源码和测试判断成立范围。

备课完成后，用当前例子检查能否连续回答「它从哪里来 → 为什么轮到它 → 当前拿到什么 → 如何处理 → 结果交给谁」。有缺口时回查并补充相应前提。

## 一节课怎么走

1. **先说清代码要完成的事。** 从用户在软件中的操作出发，先用普通语言说明本段要解决什么问题、必须判断哪些关键条件、最终需要构造或交付什么状态，以及它在整套系统中的位置。再进入职责图、对象关系、调用链和代码，让每个函数都能对应到先前说明的一项任务。关键问题的数量按机制决定，不硬套固定条数；避免先堆类名、函数名或行号，再要求用户反推用途。
2. **先看职责和类关系。** 用职责图展示相关模块、类或函数。逐一说明它为什么存在、谁创建它、它依赖谁、它持有什么状态、谁有权修改关键状态。讲清谁决定规则、谁执行规则、谁转换或传递结果，核对项目与依赖组件的实际分工，以及对象的创建、使用与生命周期。跨章节沿用系统地图，复访已讲机制时引用原有输入、输出和结论，再补本节涉及的边界。

   第一次出现连续属性访问时，逐层标出实际类名、职责、主要属性、构造或赋值位置，再说明末端是属性还是方法。用对象关系图连接到真实状态持有者，解释同名属性在不同类里的含义，及多个对象何时共用同一个依赖。涉及锁前先指出锁所在对象和保护的数据。调试时给出 `type(...)`、有限字段和必要的 `is` 身份比较，帮助用户把对象关系对应到实例。

   对象结构图同时标明关键构造参数和来源，按初始化顺序画出「先创建哪个对象 → 赋给哪个属性 → 再把哪个已有对象传给其他构造函数」。用同一个标记连起共享对象的实际参数和接收属性，逐项区分新建对象与传入已有对象的引用，让用户能从构造代码推导共享关系。跨段反复使用核心对象地图，复访时先用小图恢复对象关系，标出本次动作由谁编排、输入从谁取得、结果交给谁；类名与具体实例标记同时给出并保持一致，实例重新创建或角色变化时明确说明，不默认用户记住上一段所有属性。对象缩写按类名各单词的首字母取名，首次出现同时标全名，例如AS=AgentSession、SR=SessionRuntime、AR=ActiveRun、CQ=ControlQueue；同类多个实例可加数字。缩写重名或仍不易辨认时直接写全名，不使用与名称无关的任意字母；更换既有标记时先给出对应关系。
3. **挑一个设计决定讲理由。** 用实际需求、约束或失败例子解释为什么这样分、保护了什么、需要付出什么代价。按当前源码核对真实接线。有 Spec 或重构记录时引用它们，其他拆法标为课堂推演。需要开源对照时，按项目规则围绕当前问题追真实调用链，说明哪些思路适用、如何在本项目验证。
4. **用同一个例子沿时序图走一次。** 展示具体输入，再逐站看调用者、函数、参数、中间状态、正常返回或抛错、状态变化和下一位消费者。先展开对象与字段的实际形状，再读属性访问和遍历。用图或表列出正常、失败和边界分支，标明触发条件、负责层和结果，先走通正常路径，再细讲最能检验设计的分支。分支密集的算法先给与源码一致的流程图，再按图讲代码；标明提前返回、候选搜索顺序和失败出口，区分中间定位值、初选结果、最终校验和状态提交。优先用同一组数据对照不同条件，不能把连续步骤误画成多个独立策略。

   介绍 batch、请求、上下文等中间对象前，先说明它承接上一步的什么结果、解决当前哪项问题、下一步由谁使用。若同一数据先供模型阅读、稍后又用于核验，必须把两次用途连在同一条链中；转换前后并排展示，标出保留、交付、回填或检查的字段。先选能走通的最小正常例子，旧状态、相关检索、预算和协议等分支在确实影响当前步骤时再加入。此前字段介绍不清楚的原因是先列结构和值，再并列讲准备步骤和可选机制，缺少同一场景下的数据产生与消费关系；即使逐个解释字段含义，也不能替代这条完整链。用户反馈字段缺乏关联时，先缩回同一个例子重建链路，不继续补字段清单。
5. **拆关键函数和语法，再调试。** 主动展开 1–2 个决定分支、跨层约定或关键副作用的函数。常规 `import`、函数定义、容器和参数解析默认略过，遇到疑问再补。遇到 `await`、装饰器、闭包、嵌套推导式、相邻字符串字面量或异常传播，先用普通写法解释求值顺序，再代入当时的值。用户想逐行看时，在当前函数展开关键行和复杂语法。
6. **把同一个例子讲成面试答案。** 用「问题和约束 → 职责怎么分 → 一次正常或失败运行 → 设计代价与验证证据」来组织。完整主题讲完后，按需要做模块复述、本人调试、小改动、独立复写或模拟追问，逐级给提示。已确认内容直接接着讲。

职责图回答「这些对象平时怎样组成、状态归谁」，时序图回答「这一次请求按什么顺序走」。图、分支表和逐步示例围绕当前问题选用。第一次用术语时先解释它在例子里的作用，随后再对应源码名称。

## 框架和证据

- 先定位当前分支的调用点和职责边界。关键机制需要理解框架内部时，用本机安装版本的源码、官方文档和最小探针核对。沿注册、调用或调度关系解释自动执行的来源、实际顺序和参数注入，区分语言本身的行为与依赖组件提供的机制。
- 标明数据来自课堂示意、模拟模型或工具、本机确定性测试，还是实际外部请求。讲断言时说明变量由谁产生、当时是什么值、断言能证明什么。面试描述以真实参与和已有证据为准。

## VS Code 调试

- 给断点前先带读测试：按准备、执行、断言划分行范围，说明断点前准备了什么、该行启动什么、走过去以后检查什么。标出需要认真读的代码、只需听概括的辅助代码，以及暂缓内容的归属场景。
- 按 Python 初学者的视角讲本段实际出现的语法。测试装饰器、列表推导式等先解释它们在这段代码里做了什么。第一次给列表推导式做观察表达式时，同时给出普通 `for` 和 `append` 的等价写法，并代入一个实际值。
- 每个要展开的分支优先复用一个可独立运行的确定性测试。给出精确测试命令、输入、预期结果，以及模拟对象替换的位置。跨层分支可用确定性集成测试，并说明它覆盖的范围。缺少可观察入口时按授权范围补齐，优先使用现有实现和测试设施。
- 默认用 Test Explorer 的 **Debug Test**，从测试入口设一个断点。给出 F10、F11、Shift+F11 的单步路线，标明主要函数的输入、返回和副作用。中途断点按需要加。对预期异常，用断点或 `--trace` 主动进入。Pdb 作为终端备选。
- 每个关键栈帧给两三个 WATCH 或 Debug Console 表达式，说明变量何时产生，优先投影当前需要的字段。`justMyCode` 控制单步代码范围。查看返回值时用 `showReturnValue` 观察原调用的返回，避免在 Debug Console 重跑有副作用的函数。异常分支沿抛出和捕获位置走，另外观察状态变化。IDE、环境配置和调试依赖按项目授权规则处理。

## 记录与更新

- 每章讲解结束后，先由用户用自己的话总结。助手逐项核对并反馈纠正，再在[3.0 课堂笔记](../3.0/README.md)保存简短的用户总结、对应纠正、必要关系图和待检验点，从第一课编号。课堂索引维护当前学习位置。按用户要求补充具体内容。
- 分开记录已讲解、自述理解、引导后理解、独立调试或实现、可应对追问和功能已验证。用户说「懂了」记为自述理解。独立能力用用户自己的调试、代码或追问表现判断。
- 当用户明确确认某种讲法、调试方式或学习节奏要作为后续默认时，在本页直接更新对应段落。单节的例子、临时节奏和疑问放在该节笔记。后续课堂从本页读取最新约定。
