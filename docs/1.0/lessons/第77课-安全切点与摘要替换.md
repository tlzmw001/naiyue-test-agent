# 第77课：安全切点、工具配对与摘要替换

日期：2026-10-20。接续75请求装配、76预算；本课核对当前context_compaction/context_summary_io、现有测试及本机LangGraph add_messages源码。只读生产/测试，不重跑测试或调用供应商，不改产品。消息、短ID、单条估算和摘要文本均为示意，不是实际业务证据。

## 1. 问题与例子

超过阈值后，要选择可压缩的前缀和保留后缀，保住工具调用/结果的结构，再将历史转成摘要请求，校验产物和预算，最后提交图更新。不能按字符/消息数任意删除，也不能将摘要模型返回直接等同正式替换。

示意消息：

| index | 消息ID/类型 | 内容或关联 |
|---:|---|---|
| 0 | h0 / Human | 先确认测试环境 |
| 1 | a0 / AI | 环境已经确认 |
| 2 | h1 / Human | 测试创建订单缺少product_id，不修改业务代码 |
| 3 | a-read / AI | tool_calls=[{id:call-read,name:read,args:{path:docs/api.md}}] |
| 4 | t-read / Tool | tool_call_id=call-read，接口说明 |
| 5 | a-test / AI | tool_calls=[{id:call-test,name:bash,args:{command:测试命令}}] |
| 6 | t-test / Tool | tool_call_id=call-test，HTTP400及结果正文 |

AIMessage.id是消息ID；tool_calls[].id是工具调用ID；ToolMessage.id是结果消息自身身份，tool_call_id才与调用配对。业务HTTP400不自动等于工具执行error。

```python
AIMessage(id='a-read', content='', tool_calls=[
    {'id': 'call-read', 'name': 'read', 'args': {'path': 'docs/api.md'}}])
ToolMessage(id='t-read', tool_call_id='call-read', status='success', content='接口说明……')
```

## 2. 模块/分支地图

| 阶段 | 函数 | 产物/副作用 |
|---|---|---|
| 完整回合初选 | _cut_at_complete_turn | cutoff整数；不改消息 |
| 边界验证 | _validate_removed_prefix | pending集合检查；不合法抛ContextCompactionError；也被用于候选后缀 |
| 后移切点 | _compaction_steps内候选循环 | 选择Human/AI边界，验证两侧和两个请求预算 |
| 摘要输入 | _serialize_text_history/_summary_request | 消息对象转历史数据，再生成摘要专用System/Human消息 |
| 摘要IO | arun_summary_steps | 驱动局部生成器，await摘要模型，将结果/异常送回算法 |
| 产物/预算校验 | _compaction_steps后段 | 合格则构造summary HumanMessage和图消息更新 |
| 正式提交 | prepare_request返回hook更新 → 图messages reducer | replace当前消息；保留历史checkpoint/归档合同 |
| 应用确认观察 | ContextOperationObserver.observe | 比较消息身份，报告applied；不执行替换 |

主要分支：完整回合可保留→正常摘要；仍太大→回合内部安全边界；无切点但原输入可发→允许skipped；无合格方案/摘要非法/预算失败→阻断；特定摘要失败且原输入仍安全→按76课条件fallback；manual只在Human候选边界；force要求候选减少输入且不能回退已拒绝原请求。

## 3. 初选切点怎样走

示意K=100，最后三条单消息估算依次为：index6=40、index5=20、index4=80。倒序累计40→60→140，在index4跨过K。随后从index4往前找HumanMessage，找到index2，因此cutoff=2：removed=messages[:2]，preserved=messages[2:]。

保留区比K多是正常的：K是规划目标，完整用户回合可能更大；并非留下刚好100 tokens。初选不是字符串裁剪，也不直接移除任何消息。返回0表示这条初选路径没有可移除前缀，不意味着自动截断最新消息。

## 4. 工具配对怎样验证

调用call-read出现时pending={call-read}，结果tool_call_id=call-read到达后变回空集；一批两个调用必须等两个结果都到达。前缀末尾有pending、结果没有对应pending、调用ID无效或未结算时重复，均不合法。完成后的其他批次可复用调用ID，检查不是跨全历史永久禁止重复。

不能切在a-read与t-read之间，也不能从孤立t-read开始保留。本例在index5前切，则旧read调用/结果一起进入摘要，新的bash调用/结果一起保留，可以通过这项验证。

历史invalid_tool_calls不作为已解析有效调用加入pending；序列化为invalid_tool_call并带原解析字段。当前同AI消息的有效/无效调用同ID会判ambiguous_tool_call_id。这个验证只覆盖明确结构约束，不是摘要事实正确性检查。

## 5. 完整回合太大时，后移边界

初选cutoff=2若候选预计仍超过发送预算，代码从后续边界依次试：index3是AI，可验证两侧并计算预算；index4是Tool，跳过；index5是AI，可验证且可能放得下。假设5合格，removed=0..4，preserved=5..6。

此时当前任务h1也进入被压缩区，所以先找到该AI之前的最近非摘要Human索引2，将它记为split_turn_start=2。摘要请求把0..1放conversation、2..4放turn-prefix，让摘要保留原任务、约束与早期读取事实，不能推断后面的测试结果。

候选循环不是试所有字节/字符切割，也不在ToolMessage中间裁剪。当前候选范围不包括最后一条，保留非空后缀；manual候选仅Human，不走这种AI边界。初选成功时验证待压缩前缀；后移候选同时验证前缀和后缀，force还预先验证整份历史，不能笼统说所有路径做完全相同的一遍校验。

## 6. 摘要请求的实际形状

```python
summary_request = [
    SystemMessage(content='Summarize completed conversation history ...'),
    HumanMessage(content='''<conversation>
<message type="human">先确认测试环境</message>
<message type="ai"><content>环境已经确认</content></message>
</conversation>
<turn-prefix>
<message type="human">测试创建订单缺少product_id，不修改业务代码</message>
<message type="ai"><content></content><tool_call id="call-read" name="read">{"path": "docs/api.md"}</tool_call></message>
<message type="tool" tool_call_id="call-read" status="success">接口说明……</message>
</turn-prefix>
Summarize the original request, early work, and facts needed to understand the retained suffix. Do not infer later results.'''),
]
```

历史内容被XML转义后作为数据放入一个HumanMessage，不重放为摘要模型的原生工具调用；错误ToolMessage的status同样保留。摘要专用System提示要求保留路径、函数、工具调用ID、错误、约束和决策，建议Goal/Constraints/Progress/Decisions/Next Steps/Critical Context。没有强制这些标题的结构化验证，也不证明模型一定遵守。

若removed首项已有摘要marker，函数抽出previous-summary，其他新历史仍序列化，要求更新摘要；拆回合时调整移除首项带来的索引偏移。只有旧摘要、没有新历史则no_new_history_to_summarize。已识别图片在文本投影中仅成描述，不传原像素；不支持内容块拒绝，不能说所有多模态都被原样保真。

## 7. 局部生成器和异步IO

调用_compaction_steps创建生成器；next(steps)才执行前半算法，可能直接return/raise，也可能yield (限制摘要输出后的model, summary_request)。arun_summary_steps解出这对数据，await model.ainvoke(messages, config={tags:[SUMMARY_TAG]})。成功后steps.send(response)继续验证；失败由steps.throw(error)送回yield位置的try/except。算法return update时产生StopIteration，驱动器取得completed.value返回_acompact_messages；finally关闭生成器。

这条摘要调用不跑主Agent工具循环。旧tool_call是数据，摘要返回的新tool_calls也不会执行，而是作为非法摘要拒绝。

## 8. 结果门禁与提交

摘要须是AIMessage，无有效或无效工具调用；普通文本可用，Responses的受支持文本/思考块列表按既有投影取文本。拒绝错误/工具调用结束原因，拒绝空白和length截断；当前不以unknown结束原因一律拒绝。最后重估system+实际摘要+保留消息+工具定义，须符合B；force还须比原输入更小。

这些是结构/结束/预算门禁，不核验每个事实是否真实完整；输出写错HTTP码或漏掉约束，可能仍通过这些机械条件。这是当前能力限制，不自动增加语义审查机制。

合格summary为HumanMessage(content=SUMMARY_PREFIX+text, additional_kwargs={naiyue_compaction_summary:True})，与原AI摘要响应不同；Human是容器，不是用户新输入。返回：

```python
{'messages': [RemoveMessage(id=REMOVE_ALL_MESSAGES), summary, *preserved]}
```

prepare_request把该更新交给before_model图提交。LangGraph add_messages先给缺ID消息分配uuid；遇REMOVE_ALL_MESSAGES返回它后面的列表。本例成为[summary-new,a-test,t-test]，a-test/t-test的原ID和tool_call_id继续保留，随后才发主模型。不会因替换而重新执行bash，也不删除原聊天归档或旧checkpoint。

失败摘要/校验/预算不返回此更新。可回退失败返回None；不可回退继续raise并进入原turn/run收尾。取消/停止沿已有合同，不以生成半截摘要宣布成功。手动/overflow提交差异引用场景6/7，不重复本课。

## 9. 事件身份与确认

逻辑C1关联准备/turn，压缩操作P1由观察对象生成并保存记录，摘要callback另有实际invocation_id。prepare_compaction记录summary对象、kept/removed消息ID。图赋予summary.id后，observe检查summary是Human、当前ID前缀等于(summary.id,*kept)、removed不再出现，才报告compaction_finished(applied)。使用的是消息ID，而不是tool_call_id；本例期望(sum-new,a-test,t-test)，h0/a0/h1/a-read/t-read不再出现。

compaction_started早于摘要完成；model_call_finished(purpose由配对start关联)只报告摘要调用返回，不确认替换。applied不等于必要保存全完成，更不证明摘要事实正确；run必要收尾引用场景11。
