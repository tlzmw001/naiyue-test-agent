# 第76课：输入估算、压缩阈值与发送预算

日期：2026-10-20。接续第75课的当前请求装配。核对本机工作树及langchain-core1.6.6源码；Spec118三片已由开发会话记录完成，119-01耗时观测不属于本课上下文预算。只读源码/测试，未重跑测试、未调用供应商、未改产品。短ID和数值是教学示意，不是真实供应商计数或当前用户配置。

## 1. 问题与数据形状

一次模型请求的输入估算包含完整SystemMessage、当前messages、工具定义；消息中的模型工具调用、工具结果也计入。未提交输入框文字、单独的SQL全历史、其他子调用累计用量不自动加进当前请求。命中缓存不从这个本地计数中扣除。

示意模型条目：

```python
{
    'context_window_tokens': 32000,              # W，窗口
    'max_output_tokens': 4000,                  # O，主模型输出上限/预留
    'compaction_reserve_tokens': 8000,          # R，压缩触发留白
    'compaction_keep_recent_tokens': 4000,      # K，近期保留目标
    'compaction_summary_output_tokens': 1000,   # S，摘要调用输出上限
}
```

模型目录将条目变成model.metadata中的naiyue_model_limits、naiyue_compaction_reserve、naiyue_compaction_keep_recent、naiyue_compaction_summary_output等字典，同时给供应商适配设置实际输出上限。source标记config/default；本地配置/default不代表自动验证了远端模型真实窗口。

## 2. 当前公式与边界

令E为整份请求输入的本地估算：

```text
发送预算 B = W - O = 28000
触发留白 H = max(O, R) = 8000
压缩阈值 T = max(0, W - H) = 24000
```

R与O取max，不相加。R不是请求中额外一段文本，也不是再从发送预算扣一次。R<=O时T与B相等，并非所有配置都有两个不同数值。

普通请求且H<W时，E<=T不主动压缩，E>T尝试压缩；等于T不触发。压缩后按E'<=B判断可发送，等于B允许。force明确overflow恢复不采用普通阈值跳过，且要求实际减少输入。

示意输入：系统5000+工具定义2000+已提交历史16000+新输入1000=24000，暂不压缩；工具结果增加3000后下一请求E=27000，触发准备阶段压缩。若新摘要加保留历史使E'=25000，虽仍高于T但低于B，本次可发送；不要求反复压到T以下。下一次请求会重新检查。

E=29000则先尝试压缩，不能直接原样放行；候选仍大于28000或无法验证，不提交候选、不调用本次主模型。不是超过B就禁止尝试压缩。

## 3. 两条估算职责

| 路径 | 输入/输出 | 作用 |
|---|---|---|
| context_compaction._compaction_steps | 必要输入适配→检查配置→整份计数→压缩计划/摘要/重估→图更新或None/异常 | 请求准备中的执行决策 |
| context_usage.estimate_context | 整份计数，再独立计算system/tool_definitions/user/assistant/tool_results/summary等明细 | 生成可观察的无正文统计 |

二者可调用同一计数工具，但观察快照不授权发送、不触发压缩；统计故障和必要准备失败分别处理。

本机count_tokens_approximately默认按字符/4近似、每条消息加3，并计角色/名字、工具调用、工具结果调用ID及schema；图片用固定默认估算，不数base64字符。模型能力适配先于计数，按本次实际输入副本估算。中文/图片/供应商封装等不能据此宣称精确。

示意HumanMessage('hello')按当前默认规则：(5个正文字符+4个user角色字符)/4向上取整为3，再加3，结果6；不是供应商tokenizer的实测。项目没有开启根据历史usage自动缩放的可选计数参数；实际usage用于结果观察，不能冒充本次发送前已知值。

当前estimate对象可以是：status=available、estimated_input_tokens=27000、groups_status=unavailable、groups=[]。表示总量有值但明细失败，不表示输入为0或必需阻断。总量未知则status=unavailable、estimated_input_tokens=None。

## 4. 正常主链

```text
根控制消息合入图
→ select_model.abefore_model固定当次配置
→ prepare_request固定tools与SystemMessage
→ _acompact_messages / _compaction_steps
→ prepare_model_messages完成必要适配
→ 校验预算元数据并估算E
→ 低于阈值返回None；否则准备压缩候选
→ 按K选择保留目标、按S检查摘要及候选预算
→ 调用摘要模型并校验产物
→ 最终以同一system/tools重估E'
→ E'<=B才返回RemoveMessage+summary+preserved更新
→ LangGraph提交正式上下文
→ 模型wrapper消费prepared → 输入适配/观察/callback → 主模型
```

K是保留规划目标，不是公式中额外扣除的预算；实际安全切点可能调整保留范围。S约束摘要调用；摘要请求有自己的输入和系统提示，须summary_input+S<=W，不能只保证压缩后主请求能放下。最终E'按实际摘要重估，不再额外扣一次S。切点/摘要校验细节留下一课。

## 5. 失败与降级地图

| 情况 | 当前处理 |
|---|---|
| E<=T且H<W | 不调用摘要，继续主模型 |
| T<E<=B且无安全切点 | 可skipped(no_safe_cut_within_send_budget)，保留原输入继续；其他候选分支按算法处理 |
| 已压缩且E'<=B | 提交替换，再发主模型，不要求E'<=T |
| 原输入E>B，候选或最终计数失败/候选不适用 | 阻断，不能把未知候选当合格，也不能回原超限输入 |
| 摘要临时错误、空或截断 | 只有非force、原输入仍<=B且历史验证通过等条件允许fallback；不是所有摘要错误均可回退 |
| 首次整份估算异常或缺预算元数据，普通请求 | context_budget_unverified日志诊断，保留原输入尝试发送；不宣称预算验证通过 |
| 明确overflow后的force恢复遇估算未知 | compaction_unavailable；不原样重试已被拒输入 |
| 必要消息转换失败、已提供配置非法、O>=W | 按原失败传播，不算普通估算不可用，不调用主模型 |
| 仅统计明细失败 | 保留可用总量、groups为空；不影响准备决策 |
| 外部取消/停止 | 依原控制及必要结算合同处理，不虚构未开始的主模型调用 |

“首次估算”指当前这次准备的初始整份计数，不只指会话首个请求。摘要生成后是更晚的候选验证，不能套用首次未知的放行规则。

本地估算通过仍可能收到供应商明确overflow；context_recovery仅对明确分类的错误强制压缩，并以同一模型/system/tools局部重试一次，不重跑此前工具。普通网络/参数错误不冒充overflow。候选及响应接受/提交合同引用场景6。

## 6. 观察、身份与前端

逻辑model_call_id=C1关联本次准备、turn及context snapshot；compaction操作另生成operation_id=O1并记录当前C1；摘要callback和主callback有各自invocation_id。快照相同C1不意味着两次实际调用是同一笔。

compaction_started在越过阈值、开始计划时发，摘要尚未完成；compaction_finished(applied)由观察确认新summary/保留ID前缀及旧ID已移除后报告，不能仅凭摘要模型返回就宣布替换。正式图提交是直接执行，观察不执行提交。

主请求输入观察在准备完成后发布model_context_snapshot，前端显示总量及可用明细；model_call_started/finished报告实际callback，返回usage不回填为“发送前精确预测”。context_budget_unverified是结构化日志诊断名称，不是新增RuntimeEvent类型。

Web当前预估由application/session_context.context_view只读计算，不附加输入框草稿；忙时不伪装提供稳定的下一请求估算。读取期间重核会话/工具视图及checkpoint身份，变化则使预估不可用。最近请求和会话累计是另两个口径，累计含主子/摘要/Auto，不能用累计数字对单次W做比较。
