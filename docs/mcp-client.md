# MCP 客户端：配置、发现与 Agent 调用

当前源码已提供 `nyt mcp list`。它连接用户配置的 MCP server，握手、分页读取工具目录、
校验名称与 JSON Schema，然后关闭临时连接。它不调用工具、不请求模型。04已将明确
选中的工具注册到正式 Agent，05已接显式子角色调用、实例资源释放和持久恢复边界，
复用现有活动工具选择、审批、结果回填与会话资源。06已补齐CLI/Web来源、结果状态与归档展示。
09已支持应用运行中新增MCP服务、调整允许名单与服务启停，见下节。
当前list命令仍检查后关闭临时连接。本说明不代表已发布到 PyPI。

默认只读取用户目录 `~/.naiyue-test-agent/settings.toml`，Windows 对应
`%USERPROFILE%\.naiyue-test-agent\settings.toml`。不会在项目目录自动查找 MCP 启动配置。

```bash
nyt mcp list
nyt mcp list --settings /path/to/settings.toml
```

没有启用的 server 时输出 `{"servers": []}` 并退出0。显式指定而不存在的配置文件、
无效配置或任一启用服务发现失败时退出1。每个服务返回原工具名、计划注册名、
schema检查结果、是否在 allowed_tools 中以及目录指纹；不输出 URL、argv、描述、
schema正文、环境变量或第三方异常正文。成功的检查不是本地授权或 Agent 已注册工具。

## 本地 stdio

以下是配置格式，路径与程序均须替换为实际值；示例默认禁用，不是内置业务服务。

```toml
[mcp.servers.local]
enabled = false
transport = "stdio"
command = "/absolute/path/to/server-program"
args = ["--actual-server-option"]
cwd = "/absolute/path/to/server-workspace"
allowed_tools = ["actual_remote_tool"]

[mcp.servers.local.env]
SERVER_KEY = "${MY_MCP_SERVER_KEY}"
```

command 与 args 直接作为 argv 执行，不经 Shell；`&&`、重定向、变量展开等 Shell
表达式不会解释。服务器程序及其依赖由用户准备，客户端不会自动安装。相对路径按
调用进程及显式 cwd 的正常进程语义处理，建议使用绝对路径。

env 只接受完整 `${ENV_NAME}` 引用，源变量缺失时在创建进程前失败。子进程获得 SDK
最小系统环境及这些显式映射，不自动继承模型 Key/Web token。stdout 必须供 MCP
协议使用；stderr 持续排空，最多保留4096字节尾部作内部计数，内容不会直接打印或
写入日志。运行外部程序具有该用户的 OS 权限，此配置不构成沙箱。

## 远程 Streamable HTTP

```toml
[mcp.servers.remote]
enabled = false
transport = "streamable_http"
url = "https://example.invalid/mcp"
allowed_tools = ["actual_remote_tool"]

[mcp.servers.remote.headers_env]
Authorization = "MY_MCP_AUTHORIZATION"
```

`MY_MCP_AUTHORIZATION` 的环境变量值应是服务端要求的完整请求头值，例如包含相应的
认证前缀。配置内保存的是变量名。URL 禁止 userinfo/fragment/控制字符；不提供 OAuth
登录流程。禁止覆盖 Host、MCP session/version 及传输控制头。

TLS 始终验证证书；代理复用 settings.toml 已有 `[network]` 的 auto/direct/proxy
选择。auto 服从系统/环境代理与 NO_PROXY，不做代理健康探测或故障后直连回退。
SDK使用独立 httpx2 客户端；只允许 SDK 在同源内跟随重定向，不跨源转发请求。

手动认证可分别填写 `proxy`、`proxy_username`、`proxy_password`，用户名密码按原文填写；
保留旧的URL内认证，但两种来源不能混用。配置 `no_proxy` 列表命中的主机直接连接，
优先于proxy/auto的代理选择；支持主机、域名及子域、精确IPv4/IPv6及CIDR（如`10.0.0.0/8`、`fd00::/8`）。
也支持IPv4尾部整段通配`10.*`、`10.20.*`、`10.20.30.*`，按等价CIDR规范化；
`*.corp.example`仅匹配子域，不含主域本身，原`.corp.example`仍匹配两者。单独`*`表示全部直连。
不带协议/端口/路径；不支持任意位置glob或IPv6星号。匹配URL主机，不额外解析域名后匹配网段。
以上扩展只适用于配置`no_proxy`，auto的系统/环境`NO_PROXY`仍按标准库处理。
网络修改需重启，MCP刷新不会重载它。代理失败不切直连；stdio程序自身的联网仍独立配置。

顶层 `default_active_tools` 可包含已登记的 `mcp__服务ID__原工具名`，用于CLI/Web新根会话
默认选中。须先启用服务、加入allowed_tools并发现成功；未知名称启动失败，选中仍需审批。
省略字段保持原默认，`[]`表示零工具；旧会话和子角色工具名单不被覆盖。

loopback HTTP 可用于本地服务；其他 HTTP 要显式设置 `allow_insecure_http = true`。
所有明文 HTTP 都禁止 headers_env，避免发送自定义认证头；需要认证时使用 HTTPS。
stdio 字段与 HTTP 字段互斥，不接受独立旧 SSE transport。

## 目录、预算与错误

server ID 为1—16位字母/数字/下划线；远端工具名为1—40位字母/数字/下划线/点/连字符。
计划注册名为 `mcp__<server_id>__<remote_tool>`，总长最多64，不静默改名。

allowed_tools 可以暂时省略以查看候选；此时 selected 为 false。显式列表中的名称
必须全部存在，不能重复。发现会检查所有候选，不把不合法的未选工具悄悄跳过。
输入采用01已有 Draft2020-12 与本地引用合同，不访问外部 schema；输出 schema保留
自己的引用根，其 runtime/config 等输出字段仅作为数据。目录快照不可原位修改；
指纹包含完整工具定义，工具顺序变化不影响指纹，定义变化会改变指纹。

| 字段 | 默认 | 当前行为 |
| --- | --- | --- |
| connect_timeout_seconds | 15 | 创建、协商和发现的整体时限，严格正数；退出时等待SDK必要清理 |
| read_timeout_seconds | 0 | 0映射SDK的None；正数设置协议读取超时 |
| max_tools | 64 | 所有分页累计工具数；重复游标/名称及超过max_tools+1页失败 |
| max_schema_bytes | 65536 | 每工具输入与输出schema合计的JSON编码预算 |
| max_response_bytes | 1048576 | HTTP JSON解析前字节预算与SDK单SSE事件预算；压缩响应拒绝 |
| call_timeout_seconds | 0 | 执行工具的总时限，含资源等待、连接/目录、全部尝试及退避；0无总截止，list不执行tools/call |
| max_result_bytes / max_concurrency | 65536 / 1 | 结果限制留后续执行片；03内部资源按应用内server限制并发借用 |
| idle_timeout_seconds | 0 | 0不自动回收；有限正数按server显式启用空闲回收 |

目录的schema/数量预算是解析后的限制。SDK stdio没有公开的解析前单行硬上限；
HTTP单事件预算也不等于整个进程的内存硬限制。只配置可信的本地程序。

本地校验错误返回固定代码，例如 invalid_schema、schema_limit、tool_limit、
repeated_cursor、missing_allowed_tool；连接/认证/协商等失败以
connection_or_discovery_failed 返回，整体超时为 discovery_timeout。第三方日志在
连接上下文中脱敏，保留来源、级别及项目错误类型；不会展示服务端响应/凭证正文。
失败不会自动执行工具或重放调用。

## 运行中配置刷新（09）

可以先不配置任何MCP服务启动应用，之后编辑上述用户级settings.toml：

1. 新增server，设enabled=true，将远端原工具名加入allowed_tools，保存文件。
2. Web打开输入区的“工具”，点击原有“刷新工具与模式”；它先应用MCP配置，再读取有效工具/模式，
   完成后勾选新增工具。MCP刷新失败仍读取当前有效列表，保留失败说明。
3. 终端nyt chat中输入`:mcp-refresh`刷新，`:tools`查看，使用
   `:tools +mcp__local__echo -mcp__local__other`增减当前主Agent的选择。
4. 调整allowed_tools后再次刷新。同服务已有执行连接继续复用；新增工具不会自动
   加入任何根会话或子角色。子角色名单仍取启动时显式配置。
5. 服务设enabled=false或移除该server，保存并刷新即可停用；重新启用并刷新后，
   同名工具原有会话选择恢复，旧“本会话允许”需要重新审批。

刷新只重读mcp段；不会应用模型、权限、网络、子角色或.env变化。Web接口不接受文件
路径。每个服务先临时发现、校验、关闭临时连接，再整体发布；失败保留该服务原有
有效配置，其余有效服务独立应用。文件缺失、TOML损坏或配置非法则整次刷新不应用。
显式空`[mcp] servers = {}`会停用全部服务。未变服务不会重复发现或改变授权身份。

启用中更改地址、command/args、凭证引用值或连接预算会返回
connection_configuration_changed，需停用并收尾后重新启用，或重启应用。
本片没有文件监听，也不自动响应服务端工具目录通知；仅远端目录变化而配置不变时，
重复点击刷新不会更新目录，需要按上述停用/启用流程重新发现。

服务开关影响全部会话：停用后立即阻止尚未提交的工具调用；旧审批或批次得到配对
“未执行”反馈，Agent可以继续。已提交RPC正常收尾，之后关闭连接；停用会阻止后续尝试；
重新启用时新借用等待旧连接退出。Web显示服务状态与不可用原因，原选择仍保留。
普通会话取消勾选只影响之后的模型请求，与全局停用的撤销语义不同。停用定义只在
当前进程内保留；重启恢复仍遵循05的可用配置和旧审批处理要求。

## 根 Agent 使用（04）

1. 准备服务程序/地址，在用户设置中显式启用server，并把远端工具原名加入allowed_tools。
2. 启动应用时，所有启用服务均完成目录发现；任何失败都会阻止本次装配。只注册选中的
   工具，空allowed_tools只发现、不注册。临时发现连接随即关闭，不进入用户会话。
3. 在现有工具选择入口启用完整名称`mcp__server_id__remote_tool`；新会话默认活动工具
   集合保持原来的内置集合。根 Agent 才会获得选中的工具定义。
4. 默认每次需要审批。参数先经过JSON Schema校验；名称、readOnlyHint等服务端声明
   不改变默认ask/unknown/sequential。显式Deny优先；NoAsk/Auto/Bypass沿用已有语义。

“允许”仅批准当前参数的一次调用。“本会话始终允许此工具”按完整工具名记住，之后
同一会话的其他合法参数也可执行；不授权整个server、其他会话或另一份定义。配置身份、
完整目录、工作区或执行环境变化后不匹配。内置工具现有记忆规则保持。此记忆不承诺
跨进程重启保留；同一会话根/子角色都可匹配此工具记忆，但角色仍必须显式包含工具，
每次一次许可仍绑定具体实例、调用及参数，不能跨实例消费。

每次执行复核一次许可与当前目录，再用SDK低层session.call_tool单次提交；目录漂移
会拒绝旧定义；可停用服务并刷新，再启用并刷新以获取新目录。目录指纹不能证明远端业务实现没有改变。
同会话正常调用跨消息复用连接。网络错误、超时、停止或丢响应均不自动重放，错误反馈
明确区分未发送与已提交后结果未知，停止不能撤销已经发生的远端副作用。

支持text与structuredContent；isError=true返回配对错误结果，保留有界正文。正文按
max_result_bytes截断，超长原JSON复用已有安全输出目录和配额归档，正文给出路径/状态。
归档单次上限复用max_response_bytes；Spec125-01已移除tool_output工作区总上限，不自动删除归档。Spec128-01使用应用提供的外部归档范围：已绑定项目在data_dir/workspaces/项目UUID/artifacts下，临时会话在data_dir/sessions/session_id/artifacts下。缺少归档范围、
配额满或路径不安全会明确标记归档不完整，保留已返回的远端结果且不重发调用。模型及历史只存有界投影，完整归档按现有
输出文件清理命令管理。媒体、resource URI、input_required及扩展结果明确拒绝，
不自动取媒体、不发起交互后续请求。

## 子角色与重启恢复（05）

子角色的tool_names必须显式包含完整MCP工具名；根会话启用了某工具不会自动把它
加入子角色。子实例使用自己的连接，在同一次委派中跨模型轮次复用；审批暂停保留，
最终完成、失败或停止后释放。停止一个子实例不会关闭兄弟或根会话的连接。
两实例即使调用相同工具名、使用相同call id，也必须使用各自的当前一次许可。

MCP普通调用错误仍回填子模型，子模型可继续报告；子checkpoint失败按现有失败反馈
交给根模型，不能把未保存的子报告当作完成。根会话必要保存失败会阻断后续执行。
应用退出会先标记停止并收束连接；清理失败保持可观测，不保证撤销已发生的远端操作。

重启后不恢复外部进程/连接状态，也不保留临时授权。若旧根批次包含MCP调用且停在
审批前，历史只提供“结束旧运行并继续会话”，不会直接恢复旧审批。该动作只取消旧
批次、补充未执行说明并保存，不调用工具或模型；之后发送新消息，由新调用按当前
定义重新审批。无MCP的旧待审批仍按原合同恢复。

若旧父任务中断时子实例已经运行，恢复只给父工具补“结果未确认、可能已发生副作用”
说明，不复活旧子driver、不重放MCP请求。已完成会话可恢复历史和工具选择，但下一次
调用建立新连接，不能据此推定远端业务状态恢复。停用服务/取消工具注册导致旧选择
不可用时，历史仍可读取，恢复受阻；需先恢复可用配置，不会静默改选其他工具。

## 会话资源（03—05）

应用在自己的event loop管理资源，按会话ID、Agent实例路径与server配置身份拥有
独立客户端。每个客户端由专门任务进入/退出SDK上下文；调用只在借用期间使用它。
同会话跨run保留，根与子实例隔离；默认不因普通run结束、审批暂停或可见页面切换关闭。
会话删除、子实例最终结束、应用退出会取消并收束相应借用，再退出客户端。

连接相关配置与显式凭证引用值在每次启用时冻结；启用中改变会明确拒绝，可先停用
并刷新，再启用并刷新。连接身份使用带随机salt的HMAC，允许名单变化不改变连接
身份；授权配置身份随名单/目录发布或重新启用更新。不把凭证明文或可离线比对的
直接凭证hash放进目录/日志。用户会话的执行
连接按需创建；启动时的临时发现连接在装配前关闭。max_concurrency在当前应用内按
server约束所有会话/实例的借用。

取消排队不会破坏其他会话连接；最后一个创建等待者取消会收束创建；在途异常/取消
保守地标记本主体连接失效，等待该连接已有借用退出后关闭。下一次显式调用可以新建
连接，但不重放失败请求，不承诺恢复进程状态或撤销远端副作用。HTTP客户端独立也
不保证远端业务数据独立，必须由服务端定义业务作用域。

正常legacy HTTP关闭会尝试结束协议会话；致命读取失败可能先取消SDK内部任务组，
使尽力DELETE未能发出。本机HTTP客户端仍关闭；远端遗留会话需按服务端策略回收。
07已实现显式空闲回收，默认仍为0。对确认可以重建的服务，设置有限正数
idle_timeout_seconds（单位秒）启用；这是对连接内状态可能重置的明确接受，不根据
readOnlyHint自动开启。没有周期ping或预建连接，默认0不创建空闲计时器。

当前session的run（含模型思考、子任务审批等待和必要保存）或根待审批仍存在时，
保护该session现存的根/子连接；真实借用从排队前到finally释放也受保护。最后一次
占用释放后才计满TTL，其他session独立计时，页面订阅不延长业务idle。子实例最终
结束、会话删除或应用退出仍直接关闭，不等待TTL。

新调用先声明使用权，尚未提交的回收让开；如果已开始关闭，新调用等待旧连接退出
再建新的。回收不删除工具注册、改变勾选或本地授权配置身份；新连接不恢复服务端
隐藏状态，也不重放旧工具请求。关闭失败有安全诊断，同主体/连接不能未确认关闭
就建替代连接，应用最终关闭仍报告清理失败。

TTL也是连接配置：启用中修改正值或0会明确拒绝本次应用，需先停用并刷新，再修改、
启用并刷新。合成stdio/HTTP、正式Agent和本机安装证据见[07 Spec](specs/117-07-mcp-idle-reclamation.md)。

## CLI / Web 来源与结果（06）

Web 的主 Agent 工具菜单显示服务 ID、远端原工具名和传输方式；明确配置该工具的
子角色显示在同一项下。勾选只修改主 Agent 下一次模型请求的活动工具，不改变子角色
的 tool_names，也不会停止在途调用。尚未注册的 allowed_tools 外工具不在菜单里。

CLI 与 Web 审批都显示 MCP 来源及记忆范围。“本会话始终允许此工具”对完整工具名
生效，参数可变化，同会话根与子任务共用规则；配置/目录定义变化或重启后失效。
这不会绕过显式 Deny、参数校验、实例检查或每次调用的一次许可。

结果状态分别表示：

| 展示 | 含义 |
| --- | --- |
| 成功 | 已收到可支持的正常响应 |
| 工具返回错误 | 服务端返回 isError=true，模型仍可继续处理 |
| 未执行 | 权限拒绝、无效参数、预检失败等明确未发送 tools/call 的情况 |
| 结果未知 | 已进入 tools/call 后超时、断连或停止；可能已有副作用，默认不重放（显式安全名单见下节） |
| 返回内容暂不支持 | 收到媒体、资源或交互等不支持的响应；不自动读取地址或发送后续请求 |

实时消息、根/子结果卡与历史分页使用同一份安全投影。旧版本成功/服务错误 artifact
可据其明确来源显示；没有来源事实的历史错误保持普通工具结果，不按名称猜测。
较早中断造成的父任务“结果未确认”仍沿原恢复合同展示，不被升级成已知结果。

长结果显示原字节数、截断与归档完成状态，并列出实际产生的绝对归档路径；旧工作区相对引用仍可显示，旧文件不会自动迁移。
归档不完整或不可用会说明原因；未截断时不显示“归档失败”。可用现有 read 工具按
路径读取归档，仍受原文件权限检查，NoAsk会拒绝未经允许的外部归档读取；这片没有新增浏览器文件下载接口。历史显示预览不代表归档正文丢失。

来源/状态字段只输出有限标识及本地枚举，不输出配置 URL、argv、env、headers、
凭证引用值、配置身份或目录指纹。工具正文仍是受限的不可信外部数据，不能当指令
或权限。当前SDK/模型的合成验证及本机安装结果见[06 Spec](specs/117-06-mcp-presentation.md)；
不代表任意业务服务、多模态、交互认证或全部发行平台交付已完成。

## 外部调用重试（Spec121，当前源码）

顶层`[tool_retry]`统一选择适用工具，默认含`mcp__*`，`max_retries=2`、`attempt_timeout_seconds=30`及指数退避/Full Jitter；字段见[完整样例](examples/settings.example.toml)。本策略保留原工具JSON Schema、会话连接隔离和一次调用授权，不新增单次代理覆盖或临时连接。

一次逻辑调用的总截止由服务原`call_timeout_seconds`决定，审批等待不计，获准后的槽位/连接/目录、所有尝试与退避共用剩余时间；0取消总截止，不取消已启用策略的单次上限。每次尝试还受连接/读取子时限约束。超时/停止结束本地尝试并完成必要清理，清理可能超过期限；不保证服务端停止或撤销已发生副作用。

未发送`tools/call`前，仅可信临时传输/超时可重试。进入提交后，默认任何未知结果均不重放。只有本地`replay_safe_tools=["mcp__服务__完整工具名"]`明确承诺业务只读、幂等或去重保证时，才允许对临时故障重放；不支持通配，也不以服务端hint或模型判断作为证明。返回`isError=true`、普通协议/业务错误、目录/配置变化、停用和权限拒绝均不自动重试。每次重检有效身份与目录，失败连接退休后再借用；跨尝试保留曾提交事实，后续预检失败仍显示结果未知。

重试仍处于原工具批次槽位内，共用原`tool_call_id`，进度及安全日志不输出入参、URL、鉴权或正文。普通失败回填原工具结果，图控制/外部取消继续传播；本策略不覆盖整个Agent任务或模型SDK重试。该段设置需重启，运行中刷新MCP可新增/启停工具并消费既定策略，不能热更新`tool_retry`。此行为尚未发布至PyPI 0.2.0。
