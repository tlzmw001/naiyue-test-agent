# 0.5.1：SSH 远端执行与精简沙箱镜像

本版支持控制端通过本机 OpenSSH 操作 Linux 开发机上的 Docker。Windows 复用用户已有的 SSH Host、key 和跳板机配置，无需安装 Docker CLI、Docker Desktop 或 WSL。模型调用、会话、记忆及界面继续运行在控制端。

## 用户可见变化

- 新增可选 `[sandbox.ssh]`，指定 Host 别名、SSH 程序、远端 Docker 程序、Unix socket 和连接超时。当前支持已准备好的 key/ssh-agent；普通账户密码的后台交互尚未实现。两跳认证和主机身份均需预先核对。
- 连接事实随会话保存，刷新配置只影响未来新选择；失败不会切换到本机 Docker。未知写入继续按原操作 ID 核对，不能通过重试重放命令。
- 基础沙箱镜像改用独立的 `naiyue-test-agent-envd` 执行端安装包，保留文件、进程、Git输入/结果和日志恢复，以及必要的共享框架依赖；不再打包完整Agent业务、Web/CLI或模型供应商SDK。控制端安装包和已有工具行为保持。
- 新增 `nyt service stop` 和 `nyt service logs [--follow]`，分别请求已有服务正常收尾和读取本机诊断日志；退出日志查看不会停止服务。
- 点击已展开的当前项目名称可以收起项目；选图入口移至输入框加号菜单的“添加图片”，粘贴、拖入、预览和发送行为保留。

## 安装与升级

需要 Python 3.12.4 或更高版本。先让原服务的活动任务完成，并通过原版本可用的正常退出方式停止服务，再在现有安装环境升级：

```bash
python -m pip install --upgrade naiyue-test-agent==0.5.1
nyt --version
nyt
```

升级不会删除模型配置、会话或项目数据。使用自定义配置/数据目录时继续指定原路径；新客户端不会静默替换版本不一致的已有服务。0.5.1及以后可用 `nyt service stop`；0.5.0正式版没有该子命令，不能把关闭网页视为服务已退出。不要在尚有未确认写入时强制结束旧进程。

## 离线执行镜像附件

[下载 Linux x64 离线包](https://github.com/tlzmw001/naiyue-test-agent/releases/download/v0.5.1/naiyue-envd-0.5.1-linux-amd64-offline.zip)，以及同页的 `.sha256` 校验文件。源码仓库保存[归档清单](../../release/offline/0.5.1-linux-amd64.json)和使用说明，镜像ZIP作为Release附件，不进入普通Git历史。

镜像标签为 `naiyue-envd:0.5.1-amd64`。在Windows解压后，把整个company-kit目录传到Linux新目录，核对原Docker socket、新标签及SHA，再按包内README导入和执行check.sh。它只启动一个非root、只读根、禁网、无宿主挂载和端口映射的临时检查容器。导入使用磁盘/I/O；不会重启Docker或停止/删除已有容器。

执行端与控制端保持同版本，旧0.5.0开发镜像不能作为0.5.1新环境的兼容镜像。以后新会话选择0.5.1镜像；已有会话仍冻结原镜像和连接，不会随模板刷新换绑。不要覆盖旧镜像或删除既有卷来绕过版本不符。

自行构建继续使用标准入口：`scripts.build_envd` 生成Linux执行端wheel，`scripts.build_sandbox_image` 构建镜像；不再接受完整Agent wheel作为镜像输入。完整Agent与执行端包安装在各自独立环境，不混装。业务镜像可按需要增加项目工具和依赖。

## 验证边界

本机确定性测试、安装检查和真实Docker探针使用离线模型，不能证明真实模型效果。发行门禁包括main CI、四平台候选安装、PyPI上传及公开安装校验，实际结果以Actions为准。

离线x64镜像在本机kernel6.8/Docker29.5.2验证，并以Docker19.03官方seccomp规则做兼容性预检。公司TencentOS/kernel5.4/Docker19.03、Windows跳板机端到端、实际网络策略仍须原机验收；本版不宣称这些已通过。不会为验收关闭seccomp、使用privileged或更改宿主已有服务。
