# 0.5.0：多项目共享服务与可选 Docker 执行环境

本版将 Web 与终端接入同一用户、同一数据目录下的本机共享服务，支持普通对话和多个项目，并提供每会话独立的 Docker 执行环境。仍通过 PyPI 安装，入口保持 `nyt` 和 `nyt chat`。

最低 Python 版本为 **3.12.4**；该补丁版本开始支持 Windows 新建私密目录所需的 `0700` 行为，见 [Python 官方说明](https://docs.python.org/3.12/library/os.html#os.mkdir)。已有服务目录仍须保持私有权限；升级不会自动修改外部放宽的 Windows ACL。

## 用户可见变化

- 普通对话和项目分组展示在同一侧栏。项目可选择已有目录或新建文件夹，并明确确认信任；各范围保留自己的会话与草稿。终端可用 `nyt projects` 查看已登记项目。
- `nyt` 连接或拉起共享服务，输出私有浏览器链接后退出。多个 Web 页面和终端可以共用同一服务；关闭客户端不会结束持久任务。同一会话仍只允许一个活动运行。
- 本机文件与进程工具按会话保存的执行位置工作。项目重定位、目录失效、旧审批、历史读取和后台任务管理分别核验；不把目录存在等同于允许执行。
- 可在输入框上沿或 CLI 选择 Docker 环境模板。首次发送才创建会话及独立容器；镜像、预算和选择指纹随会话冻结。模板刷新只影响新选择，已有会话不会自动换绑。
- 沙箱输入通过 Git 快照和 bundle 传入，并显式选择额外未跟踪文件；不挂载宿主项目目录和凭据。进程操作有稳定 ID、未知结果核对与输出续读，不因丢失回执重放执行。
- 可以取回沙箱结果、审查逐文件差异，再明确选择交付到当前本机分支或新分支。结果不会自动写回；丢弃任务引用与销毁环境是独立操作。
- “管理沙箱”提供原绑定的启动、停止、核对和确认销毁。默认最多运行占用 2 个、保留 10 个环境，空闲 30 分钟停止；活动/审批/未确认后台操作受保护。停止保留文件，正常服务退出会排空任务并停止原容器，不自动删除卷。
- 模型 `request` 新增 `tool_stream` 与 `stream_chunk_timeout_seconds`，按模型控制工具参数流式和数据块等待时间。省略保留原行为，具体范围见 README 和模型示例。
- 修复直接粘贴 XML/HTML 的用户消息显示为空气泡：标签作为文字安全显示，Markdown 展示保留。

## 升级与使用

先让旧版任务完成并正常退出旧服务，再升级：

```bash
python -m pip install --upgrade naiyue-test-agent
nyt --version
nyt
```

从 0.4.x 升级时，在原运行终端使用 Ctrl+C 并等待收尾。使用过开发版共享服务的用户还需先正常停止那个服务；新客户端会明确拒绝连接不同产品版本的旧实例，不会静默替换它。0.5.0 的启动器退出、关闭网页或退出持久终端只关闭客户端。

模型配置、用户数据和旧聊天不随 pip 升级删除。旧项目身份与数据库沿项目登记、既有迁移前备份和恢复合同导入/升级；请使用原数据目录，按启动提示核对项目和信任状态。不要手动清理旧库来绕过升级错误。

纯本机使用不需要 Docker。使用沙箱需先提供可用的 Docker daemon/context 和兼容 envd 镜像，按 [沙箱配置](../examples/settings.example.toml) 配置模板；应用不会自动识别并预装所有项目依赖。公司远端 SSH 部署仍未交付，图片输入草案未包含在本版。

## 边界与验证口径

共享服务是本机同一操作系统用户的产品形态，不是多用户 SaaS。Agent 推进、会话历史和记忆仍依赖控制端本机服务。MCP 仍按既有本机执行边界显式开放；选择 Docker 不自动把全部集成变成沙箱内执行。

Git bundle 可能包含可达的提交历史；未跟踪文件选择不等于历史净化。传入前须核对项目历史与选定文件。容器数量额度不是磁盘字节额度，停止环境不会删除用户文件。

前期真实 Docker 验收覆盖两套镜像、环境隔离、生命周期及结果交付，使用固定离线模型；本次发行的确定性测试、安装验证与各平台 CI 结果分别记录，不替代真实模型效果或公司网络/远端环境验收。此前记忆整理超时的具体耗时阶段未确认，本版不宣称已修复该偶发问题。
