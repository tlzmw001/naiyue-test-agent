# Naiyue Test Agent 0.5.12

本版提供模型配置刷新、上下文用量校准、本机缓存清理和云端文件成果交付。新构建的云端 Runner 模板锁定 AITest Kit 0.7.0。

## 本机

在原虚拟环境升级。

```sh
python -m pip install -U "naiyue-test-agent==0.5.12"
```

- 保存 `models.json` 后，打开模型菜单，点击「刷新模型配置」。有前台运行或后台记忆任务时，等任务结束再试。旧模型或推理档位失效时，打开原会话重新选型即可继续。
- 上下文估算使用与当前请求兼容的模型输入用量校准。按供应商实际额度配置模型窗口和输出上限，字段见全量参考。
- 左下角「本机设置 → 清理缓存」由用户勾选执行，按最后修改时间保留工具输出归档 7 天及云输入缓存 3 天。清理后仍可读会话历史。已另存到项目的文件由用户管理。
- 新版长期记忆默认使用分个人和项目的 Wiki。升级前备份数据目录。如果启动报告 `memory_config_migration_required`，按错误所列字段及全量 TOML 迁移。旧会话历史和概览可继续使用，旧长期记忆条目不会自动导入 Wiki。

[本机全量 TOML](../examples/full/settings.full.toml) · [模型样例](../examples/models.example.json) · [全量配置与字段说明](../examples/full/cloud-configuration-reference.md)

## 云端

Coordinator 及独立 Updater 在各自原环境升级。Windows 如果仅运行 SSH 转发，可继续使用现有转发配置。

```sh
python -m pip install -U "naiyue-test-agent[cloud]==0.5.12"
```

用 Updater 选择 `v0.5.12`，完成 Runner 模板构建和预检后再激活。将 `update.json` 的可信前缀更新到实际使用的 Release 下载地址。已有任务仍受原模板绑定及历史恢复条件约束。首次验收可创建一个新任务，运行只读测试，再从结果窗口保存文件，或让项目 Agent 通过 `cloud_result` 保存。新版文件交付不再提供旧的「应用代码／创建分支」流程。云端回收以完整删除任务和引用核验为准。

[升级器手册](../cloud-updates.md) · [云端成果与共享输入](../specs/143bq-cloud-results-and-input-reclamation.md) · [云端原机验收](../cloud-final-windows-acceptance.md)

## 发布文件

- 四平台 Agent wheel，适用于 macOS arm64、Linux x86_64／arm64、Windows x86_64。
- `naiyue-cloud-0.5.12.zip`、ZIP 校验文件和 `SHA256SUMS`。ZIP 包含同源四平台 wheel、Kit 0.7.0 wheel、冻结测试依赖清单、配置示例及验收脚本。安装时仍需要 Python 和依赖来源。
- `index.json`、`v0.5.12.json`、Kit wheel、`cloud-test-requirements.txt` 和 `cloud-test-toolchain.json` 供 Updater 和模板构建使用。最低 Coordinator 版本为 0.5.12。
