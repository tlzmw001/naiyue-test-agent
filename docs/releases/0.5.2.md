# 0.5.2：修复 Windows 沙箱 Git 输入误报

Windows 上，路径 `stat/lstat` 与文件句柄 `fstat` 可能给出语义不同的 `ctime`。0.5.1 将两者的完整时间戳直接比较，可能把未改变的 Git 输入误判为 `git_input_source_changed`，使沙箱启动失败。

本版在路径与句柄的跨来源检查中比较设备号、文件号和大小；读取前后的句柄检查及最终路径复查仍各自比较完整时间戳。读取期间发生的同大小文件修改仍会被拒绝。

Agent 与 envd 的版本现在独立管理。沙箱握手核对协议、环境和会话身份，不再要求两个包的版本号相等；包版本仍用于识别执行端。先等待旧服务活动任务完成，使用 `nyt service stop` 正常退出旧服务，再升级现有安装环境：

源码中的 envd 构建版本由独立清单维护。该清单当前为 0.5.2，表示从本次共用源码构建**新**执行端时应使用的版本；它不要求把正在使用的 0.5.1 镜像升级。

```bash
python -m pip install --upgrade naiyue-test-agent==0.5.2
nyt --version
```

新沙箱环境可继续使用已发布的 `naiyue-envd:0.5.1-amd64`，离线镜像及校验文件见[0.5.1 Release](https://github.com/tlzmw001/naiyue-test-agent/releases/tag/v0.5.1)；导入和核对方法见[远端 SSH 使用说明](../remote-docker-ssh.md)。本版不要求或发布新镜像。已有会话仍保留原镜像绑定，不通过覆盖镜像或删除旧卷升级。

回归测试模拟了 Windows 两种 stat 时间语义，也验证了读取后同大小文件变化仍被拒绝。旧镜像复用以执行协议兼容为前提；未来 Agent 若需要旧 envd 没有的能力，须先增加能力协商或提升协议和镜像版本。公司 Windows 与 Linux 原机的端到端运行仍须用新控制端及现有镜像验收；本机模拟不能替代原机结果。
