# 0.5.11 · 本机与云端 MCP 认证

本机和云端的远程 MCP 可以按服务配置 `headers_env`，支持 Bearer token、API Key 和多个认证头。获准连接的明文 HTTP 可以携带认证头。非回环明文 HTTP 仍需 `allow_insecure_http = true`，HTTPS 继续校验证书和服务名。

Coordinator 从启动环境读取配置引用的凭证，随现有控制连接交给 Runner。Runner 发起请求，可直连或使用原有 Windows 反向隧道。配置快照保存变量名，实际凭证由 Runner 持有。

## 更新与配置

1. Windows 若要更新本机 Agent，先按原方式退出服务，再在原 Python 环境执行 `python -m pip install --upgrade naiyue-test-agent==0.5.11`，用原入口启动。只承担 Windows 隧道转发时，可以沿用已有安装。
2. Linux 正常停止 Coordinator，在原环境执行 `python -m pip install --upgrade 'naiyue-test-agent[cloud]==0.5.11'` 后沿原命令启动。用现有 Updater 选择 `v0.5.11`，构建、预检、登记并激活 Runner 模板。新任务使用激活后的模板，已有任务可按显式升级流程换代。[启动与配置](../cloud-startup-and-configuration.md) · [模板更新](../cloud-updates.md)
3. 在 Coordinator 的 `cloud.json` 对应 `mcp.servers` 条目加 `"headers_env": {"Authorization": "NACOS_MCP_AUTHORIZATION"}`。在 Coordinator 的服务启动环境设置完整的 `Bearer <token>`。本机调用则在 `settings.toml` 的对应服务条目配置，并在本机 Agent 的服务启动环境设置变量值。[云端配置](../examples/full/cloud-configuration-reference.md#云端-mcp143ay) · [本机配置](../mcp-client.md#远程-streamable-http)
4. 私有 CA 由实际发起 MCP 请求的进程信任。云端使用 Runner，Windows 本机使用本机 Agent。Windows 隧道入口的主机、端口和 TLS 类型须与 MCP URL 匹配。更新凭证环境变量后重启相应服务，再刷新 MCP 工具。

## 验收

在使用新模板的云端任务点「MCP 工具 → 刷新工具」，确认服务可用并调用一次只读查询。若同时使用 Windows 本机 MCP，按同样方式验证本机调用。可分别验证直连和 Windows 隧道。使用离线 ZIP 时，选取与机器架构匹配的 wheel，并沿用现有环境与配置。
