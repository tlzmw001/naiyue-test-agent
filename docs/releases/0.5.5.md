# 0.5.5：补齐进程与沙箱失败诊断

沙箱准备、恢复、后台任务或输入回收失败时，旧日志有时只包含退出码或异常类型，难以判断失败在哪一步。本版补充控制端的失败阶段、已有会话／环境／操作标识、退出与超时状态、OS／SQLite 错误码，以及有上限的 stderr 类别，便于沿同一次操作定位原因。

覆盖 Docker／SSH、Git、Host 与后台进程、MCP 连接和输出读取、沙箱生命周期与 watcher、结果归档及交付。默认服务日志会展示允许记录的事件字段；诊断不复制原始命令、环境变量、凭证或响应正文。日志投递和事实提取失败不会替换业务原异常。

输入回收新增失败操作、Windows 错误码、相对于应用缓存目录的失败路径及只读／链接属性。该改动用于定位 PermissionError，尚未修复 Windows 删除失败，也没有新增手动清理入口或自动删除重试。

工具返回给模型的命令输出、失败信息及 ToolException 合同保持；进程清理失败仍按原规则阻止继续执行。审批、并发额度、锁、操作结果未知后的原 ID 恢复、持久诊断协议与数据库结构均不改变。

## 升级控制端

等待活动任务结束，在原安装环境执行：

```sh
nyt service stop
python -m pip install --upgrade naiyue-test-agent==0.5.5
nyt --version
```

随后按原方式启动应用。升级后应显示 `0.5.5`；如仍遇到沙箱或回收失败，可使用 `nyt service logs` 查看新增诊断。此版本同时包含 0.5.4 的 Windows OpenSSH PROGRAMDATA 继承修复。

## 继续使用原镜像

远端继续使用 `naiyue-envd:0.5.3-aitest-0.6.0-reviewed-amd64`，包含 envd 0.5.3 与 AITest Kit 0.6.0，无需重新导入、重建或更换镜像。本版不新增镜像附件；首次安装镜像仍从 [0.5.3 Release](https://github.com/tlzmw001/naiyue-test-agent/releases/tag/v0.5.3) 下载离线 ZIP 和 SHA256。

本次源码同时补充 envd worker 的执行及状态保存诊断，独立构建清单记录为 envd 0.5.4；本次仅发布控制端包，不发布该执行端包或镜像。原镜像中的容器内部新增日志不会因控制端升级而生效；控制端侧的 Docker／SSH、RPC、生命周期及输入回收诊断会生效。运行时继续按协议与环境／会话身份判断兼容，不要求控制端和 envd 版本号一致。

完整 Windows→SSH→Docker→输入／执行／结果及恢复链仍需用户原机验收；本版日志增强不作为原机问题已全部解决的证明。
