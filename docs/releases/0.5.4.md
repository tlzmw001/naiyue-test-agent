# 0.5.4：修复 Windows SSH 静默退出 255

Windows OpenSSH 启动需要继承系统环境变量 PROGRAMDATA。0.5.3 控制端启动 SSH 时的环境白名单遗漏此变量，导致普通 PowerShell 中连接及 Docker 查询正常，Agent 后台却可能无错误输出地退出 255，沙箱准备、恢复和销毁均可能受影响。

本版在本机 Docker/SSH 客户端的环境白名单中保留系统原有 PROGRAMDATA，继续过滤其他无关变量。隐藏控制台、认证策略和操作结果未知的处理保持原合同。原机对照确认完整环境普通/隐藏均成功，过滤环境普通/隐藏均255；仅补回 PROGRAMDATA 后四组全部成功。回归覆盖变量继承、无关环境过滤及真实子进程静默255。

等待活动任务结束，在原安装环境执行：

```sh
nyt service stop
python -m pip install --upgrade naiyue-test-agent==0.5.4
nyt --version
```

随后按原配置启动应用，新建沙箱会话验证。SSH 探针成功不等于完整沙箱链路通过。

## 镜像继续使用 0.5.3

本版仅修改控制端 Docker/SSH 启动，不修改 envd 协议或执行源码。继续使用 `naiyue-envd:0.5.3-aitest-0.6.0-reviewed-amd64`，无需重新导入、重建或更换镜像。本版不新增镜像附件；首次准备镜像可从 [0.5.3 Release](https://github.com/tlzmw001/naiyue-test-agent/releases/tag/v0.5.3) 下载包含 AITest Kit 0.6.0 的离线 ZIP 和 SHA256。

## 会话与并发边界

正式会话入口中，一个沙箱会话固定绑定一个环境及一个容器，后续轮次复用。一个会话同一时刻只允许一个 Agent run，但根 Agent 可启动多个后台代码任务，在同一容器内并行运行。

容器默认 `max_active_operations=16`，这是 journal 中 starting/running 操作的共同额度，包括 shell/argv 和写入/编辑等操作；达到上限拒绝新操作，并非排队。每条命令内部创建的子进程不另算 journal 操作，但仍计入容器的 PID 和资源约束。默认资源为2 CPU、2 GiB内存、256 PID/线程额度，均为容器总资源。任务共享工作区和环境，没有逐任务独立容器或目录隔离；并行写同一路径需由任务自行协调。输入安装和结果捕获要求相应独占条件，活动后台任务会阻止取回结果。环境参数在创建时冻结，修改模板影响新会话。

## 尚未包含的修复

日志中的输入回收 PermissionError 仍需独立定位失败路径和Windows错误码；本版不宣称修复此项。完整 Windows→SSH→Docker→输入/执行/结果及恢复链仍需用户原机验证。
