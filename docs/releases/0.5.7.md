# 0.5.7：云端任务、结果取回与运行维护

独立云端任务成为正式入口：本地主Agent保留本机工作区，云端Coordinator管理任务与模型转发，Runner在受信模板中执行。侧栏支持任务标题/时间、模型选择、即时发送反馈和断线原ID回执收敛；停止跨轮后台服务前弹出确认。

结果取回在居中窗口完成。报告选择文件后保存到本地已有或新建目录，不同内容同名时显式确认覆盖；代码先预检，再应用当前目录或创建Git分支。非Git项目支持应用到当前目录；强制覆盖仅处理本次变化路径，成功后推进取回基线。保留主Agent分析结果入口。

云端增加显式发行预检/更新、已有任务换代、维护、备份恢复与引用感知清理。修正Windows只读句柄fsync、编码/路径/权限、状态恢复和删除清场预算；准入拒绝返回业务失败而非拆断控制连接。记忆后台状态简化为少量可读状态，详细原因和保存计数写入日志。

## 升级与兼容边界

- 从正式0.5.6升级：先用旧CLI执行`nyt service stop`，再安装0.5.7。旧`[sandbox]`、`[delivery]`、`mcp.servers.<id>.allow_sandbox`配置已删除，旧sandbox会话不迁移、不兼容，也不会静默转成本机执行。旧数据/卷/镜像不自动清理。
- 已用S11 R4候选：主配置格式保持，记忆补充无新增必填项；本地与Coordinator均升级到0.5.7，再准备同版Runner模板。已有云端任务固定旧模板，需要显式upgrade，安装新wheel不会自动换代。
- 本机共享服务协议2与云端Owner协议1分别检查；不能用新版CLI假定能停止不兼容的旧服务。模型配置格式未改变。
- Coordinator可使用`python -m pip install 'naiyue-test-agent[cloud]==0.5.7'`；本机使用`python -m pip install 'naiyue-test-agent==0.5.7'`。真实配置、凭证和数据目录由用户保留并显式迁移。

完整启动命令和配置差异见[两端启动与配置迁移](../cloud-startup-and-configuration.md)。更新/维护流程见[云端更新](../cloud-updates.md)。

## Release附件

- 四平台Agent wheel：Windows x64、Linux x64/ARM64、macOS ARM64，来自同一提交的CI。
- `naiyue-cloud-0.5.7.zip`与`.sha256`：同源四平台wheel、AITest Kit 0.6.0、固定工具链、云端构建/验收脚本和文档；不包含Python解释器、完整依赖wheelhouse、真实配置或公司镜像。
- `v0.5.7.json`、`index.json`、Kit wheel、`cloud-test-requirements.txt`、`cloud-test-toolchain.json`：云端Updater所需的公开发行材料。默认最低Coordinator版本为0.5.7。
- `SHA256SUMS`：Release资产校验；旧envd离线镜像不属于本版云端Runner。

Runner镜像须在目标开发机按实际backend、UID/GID及包源构建并预检；公开包不能替代这一步。固定基础镜像沿此前已核验digest，不隐式追随latest。

## 验证口径

发布门禁包括完整后端/前端测试、四平台原生安装、同提交CI候选核验、PyPI发布及四平台公开安装。实际运行链接和产物身份在GitHub Release中记录。

此前Windows反馈的40轮链路通过与本轮CI属于不同证据；公司网络、Docker宿主策略及尚未实测的性能门禁不因发版自动转为通过。记忆状态与日志修复不等于真实模型提取质量改善。
