# 0.5.9：云端文件与统一连接

新任务不再要求Git基线：创建只选连接、模板和服务网络，打开任务对话后按需上传文件或文件夹（目录递归展开，链接与特殊文件明确拒绝），默认单文件20GiB、每批20GiB；上传后可在下一轮保持待发送消息。output产物支持直接下载、保存或交给主Agent分析，已开始的云端运行不依赖浏览器保持打开。

Windows改为单一connections配置文件，Linux更新器派生连接同步；同一connections条目只写一次connection和ssh。旧Git范围前端退出，新任务不生成diff；已发布CLI与旧冻结结果按实际消费者保留。共享输入未新增自动GC，本机下载链接不是公开分享链接。

服务入口扩展为按网络配置的通用TCP端口列表，替代0.5.8固定的HTTP/gRPC两个入口；0.5.8页面不支持新的入口列表响应，两端应同步升级。项目侧栏新增“移除”按钮：确认后从列表移除登记，保留磁盘文件、本地历史数据库和归档；有运行、审批、恢复、后台工作或仍保留的云端任务关联时提示先处理。

## 更新范围

Windows本机、Linux Coordinator、独立Updater统一为0.5.9。附件上传/安装由Runner执行，需要用0.5.9 Linux wheel重新构建并激活新Runner模板；已有任务继续使用原模板，不做自动迁移。Windows从0.5.8的profiles合并为单一connections文件时沿用已有profile_id、network_id和instance_id，不要重新生成实例ID；`connections_file`和旧`profiles_file`不可同时配置。

配置、点击与Windows步骤见[云端文件与连接手册](../cloud-files-and-connections.md)，通用入口配置与迁移见[服务隧道手册](../cloud-service-tunnels.md)。不要把新版默认值当作旧配置的自动迁移，不覆盖真实配置或数据根。

## 发布材料与验证

正式流程依次要求本机验证、同提交完整CI、标签触发PyPI、四平台公开安装、Release附件哈希核验；实际运行证据记录在GitHub Release。本机验证：后端6541项（含材料读取分配上限回归）、前端76文件633项通过，TS/Vite构建与标准Mac wheel/Twine通过，证据见本机报告。Playwright视觉实测、Windows原机、公司SSH/TLS/gRPC链路与真实20GiB传输待原机验收。未自动部署公司实例。
