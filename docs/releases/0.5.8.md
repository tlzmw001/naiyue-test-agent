# 0.5.8：大项目导入与个人服务隧道

输入总量默认2GiB，增加目录/文件选择、Git能力检测和导入预览；Git项目缩小范围仍保留来源回执。配套归档、清单、缓存、结果工作区和响应预算同步调整，旧显式配置需按指南对齐。

云端任务列表新增居中的“服务连接”窗口。管理员为每台Windows分配network_id和HTTP/gRPC两个端口，本机服务拥有SSH控制连接与反向隧道，支持保活、重连、主动断开和静止热切换。任务持久绑定入口，每轮获得最新路由；共享SSH账号可用，不新增强租户权限隔离。

Windows审查修正Git范围大小写匹配，并保留无网络任务对0.5.7 Runner的命令兼容。新增四平台安装烟测覆盖中文/空格目录、真实输入归档、状态文件替换、子进程回执与回收；正式Windows OpenSSH成功日志CRLF/IPv6/错误回执有确定性回归。公司SSH/容器网络与真实TLS/gRPC仍由原机验收。

Updater状态读取增加有界重试，解决与状态文件原子替换并发时的偶发unsafe_store_file；仍执行完整安全校验并保留其他IO失败。

## 更新范围

Windows本机、Linux Coordinator、独立Updater和新Runner模板统一为0.5.8；AITest Kit保持0.6.0。旧任务不自动添加network_id，需要个人隧道的任务在profile配置和新模板激活后重新创建。未绑定网络的旧任务可继续使用原模板。

[按Linux/Windows分开的完整升级与点击指南](../cloud-143an-upgrade.md)列出配置增量、启动/维护、模板更新和验收步骤。不要把新版默认值当作旧配置的自动迁移，不覆盖真实配置或数据根。

## 发布材料与验证

Release提供同提交四平台wheel、naiyue-cloud-0.5.8.zip与校验、v0.5.8.json/index.json、Kit和固定工具链。正式流程依次要求本机验证、同提交完整CI、标签触发PyPI、四平台公开安装、Release附件哈希核验；实际运行证据记录在GitHub Release。未自动部署公司实例。
