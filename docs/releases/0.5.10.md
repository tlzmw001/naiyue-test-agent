# 0.5.10 · 云端 MCP 与任务对话

本机工具菜单的「刷新工具与模式」和 CLI 的 `:mcp-refresh` 会重新拉取启用服务的工具定义。MCP Server 修改同名工具的参数后，原会话刷新一次，再发送新消息即可使用新定义。

云端 Runner 支持 Streamable HTTP MCP，可以从开发机直连，也可以使用任务绑定的 Windows SSH 反向隧道。云端主智能体自动获得启用服务的有效工具。模型选择旁的「MCP 工具」面板可以查看目录并刷新，正在运行时登记刷新，轮结束后应用。服务端关闭请求超时会有界退出，排队消息遇到明确的刷新中拒绝会回到等待。

Windows 任务附件可在同一个目录浏览器批量混选文件和文件夹。目录发生变化时，可放弃待确认的选择并重新选择。此版本包含 Windows 上传日志长路径修复、附件提交后的输入区清理、详情折叠、临时消息同步、侧栏拖动和项目右键移除入口。项目移除沿用原有确认与关联保护，磁盘上的项目文件和历史保留。

## 更新顺序

1. 在各自原有的 Python 环境中更新。先按原入口正常停止待升级服务，再执行相应安装命令。保留原配置路径、数据根、连接和实例 ID。

   | 组件 | 命令 |
   | --- | --- |
   | Windows Agent | `python -m pip install --upgrade naiyue-test-agent==0.5.10` |
   | Linux Coordinator 和独立 Updater | `python -m pip install --upgrade 'naiyue-test-agent[cloud]==0.5.10'` |

2. 用 0.5.10 Linux wheel 构建、预检、登记并激活新 Runner 模板。已有任务如果还绑定旧 Runner，会显示当前环境不支持 MCP。需要使用新模板时，按现有模板升级流程操作。[启动与配置](../cloud-startup-and-configuration.md) · [模板更新](../cloud-updates.md)
3. 在 Coordinator 启动时 `--settings` 指向的 JSON 中添加可选 `mcp.servers`。省略时没有云端 MCP 服务。本机 MCP 继续使用原 `settings.toml`，Windows 云端连接继续使用现有 `connections.json`。中转服务的 `network_slot` 引用现有入口 ID，在 Windows 连接页把该入口指向与 MCP URL 同主机、端口和 TLS 类型的目标。[完整示例](../examples/full/cloud.example.json) · [字段说明](../examples/full/cloud-configuration-reference.md#云端-mcp143ay)
4. 打开云端任务，点击「MCP 工具 → 刷新工具」。等状态更新后发送消息。后续 MCP Server 只改工具定义时，按同一路径刷新即可。[MCP 验收步骤](../specs/143ay-cloud-mcp-and-manual-refresh.md#5-验收入口)

## Release 附件

真实 Windows 原机、公司 SSH/VPN 和公司 MCP 端点按验收手册复验。
