# Agent健壮性设计：失败事实、恢复决策与终局合同

日期：2026-10-11。状态：需求与架构讨论稿，不是全部能力已实现声明，也不是本轮实现授权。依据用户本轮需求、粘贴的异常设计原则、当前代码与固定版本参考源码。Spec080仅解决失败描述回传基础，不能代替本设计的重试/熔断/降级验收。

## 1. 决策原则

来源决定责任/治理范围，处理方式决定动作，二者都保留。可重试、可反馈等不是互斥错误类：一次瞬时故障可先安全重试，耗尽后反馈；控制信号与副作用未知优先。不能按KeyError/TypeError等类名猜可反馈或程序bug，要看发生阶段。

抽象职责（先定义职责，不预建每个类/模块）：

1. 失败事实：发生在哪个调用/阶段、类别/原因、原异常类型、实际依赖。Model Access归一模型错误；参数/权限/协议检查在各自边界提供事实。
2. 恢复决策：Runtime结合事实、重放安全性、授权、预算和依赖状态选择反馈、重试、备用、停止、失败或控制转移。
3. 执行动作：只对当前逻辑调用做有界尝试/等待/切换，不重放整个run或已执行工具。工具治理前置/审批/批次/事件与内部attempt层次明确。
4. 观察与合同：调用/attempt/切换事实关联，App负责收尾、保存确认与终局；程序接原异常，模型接可修复反馈，用户接安全提示。

```text
App注册配置/能力/授权/预算 → Runtime治理已授权的一次逻辑调用
   → 调用前检查 → 模型/工具执行 → 失败事实 + 调用上下文
   → 控制/副作用检查 → 安全重试/备用/反馈/终止
   → 成功或工具反馈继续图；未处理失败标注原异常→App收尾终局
```

恢复决策不依赖App是否能回读异常属性；捕获点已持有事实。Spec080标注仅负责最终未处理错误上行，丢失诊断不改变权限/控制判断。

## 2. 当前能力与差距

| 能力 | 当前源码/证据 | 本设计目标 |
|---|---|---|
| 在线模型重试 | 配置默认SDK max_retries=2，timeout=60；本机OpenAI/Anthropic SDK有指数退避、随机抖动和Retry-After处理；项目有Mock SDK取消验证 | 统一attempt观测/总预算/重试资格与所有者 |
| 通用工具重试 | 未装配ToolRetryMiddleware；本地write/edit/Bash并非默认可重放操作 | 对已声明且验证安全的依赖调用接入 |
| 工具错误反馈 | 参数/ToolException已有安全ToolMessage；无效模型tool_calls仍整轮拒绝 | 补完整反馈矩阵及可修复协议分支 |
| 熔断/依赖隔离 | 没有通用熔断；已有批次有限并发不等于跨run依赖隔离 | 配置实例作用域的熔断及资源上限 |
| 工具备用提示 | 无统一同能力/授权候选机制 | 告知当前可用授权候选，由模型选择 |
| 自动模型故障切换 | 用户选模已支持，不等于自动failover | 有界候选链、能力/预算/数据限制和真实模型轨迹 |
| 正常返回质量验证 | 已有消息/工具协议门禁，不是事实正确性保证 | 业务校验、固定评测、独立质量指标及有界修复 |
| 原异常描述回传 | Spec079双路回报已实现；Spec080属性方案未实施 | 结构收敛，保持原异常/原因/控制合同 |

默认值来自model_access源码，SDK机制来自本机安装源码；表不表示所有网关、供应商或生产故障已验证。不可把SDK源码能力当业务效果。

## 3. 工具处理合同

| 情况 | 推荐动作 | 是否计依赖熔断健康失败 |
|---|---|---|
| 参数/schema/类型绑定、未知工具、调用前业务校验 | 安全错误结果回模型，说明原因/允许的修正 | 否 |
| 权限拒绝或需要审批 | 拒绝反馈/专门审批流程；不能建议绕过授权 | 否 |
| 临时连接/超时且可确认安全重放 | 次数/总时长/预算内退避重试 | 重试耗尽后逻辑调用计一次 |
| 明确测试结果：断言失败、待测接口5xx/超时 | 作为测试证据保留，不自动重试变成通过 | 否 |
| 重试耗尽的健康故障 | 当前调用错误结果；累计健康失败可触发Open | 是，按逻辑调用计数 |
| 依赖已经Open | 不执行、不重新重试，回不可用反馈/可用候选 | 拒绝请求不再次算实际失败 |
| 结果不确定/重放可能重复副作用 | 不自动重试/换工具，走停止与核对策略 | 单列，不拿熔断代替核对 |
| 工具内部非预期bug/框架内部故障 | 保留原异常，上抛失败；安全诊断 | 不默认当下游故障 |

测试执行器的“运行并产出失败报告”可能是工具执行成功；SUT失败与Agent基础设施失败必须分开。HTTP/RPC用例若定义重试，保留第一次结果和重试事实，这是测试业务策略，不能由Agent工具重试悄悄覆盖。

用户再次明确：404等接口响应本身不触发工具重试，结果仍回ToolMessage让模型分析；外部工具网络中断、超时、临时限流、MCP/插件服务临时不可用才是重试候选，另外检查重放资格和预算。这不是本轮增加重试的授权范围。

可重放资格至少要求：操作只读，或使用同一幂等键且有已验证的服务端去重，或有证据操作尚未提交。任意Bash、未知MCP副作用工具、写入结果未知默认不符合；超时本身不是资格。

一次逻辑调用可有多个attempt，但授权与目标绑定不因重试扩大；实际执行前检查不能被绕过，审批不能盲目再次弹出或重复消耗grant。工具批次调度/调用生命周期在外层，重试在具体执行/传输内层；不能在已经失败/完成的batch槽位外重新调用同ID。新增网络工具先用一个有安全契约的样本验证。

### 无效工具调用与协议恢复

用户希望无效调用也反馈，与当前invalid_tool_calls整轮拒绝不同。已通过选择回复明确确认：保留唯一有效call_id且能恢复正确消息配对的可修复错误，形成未执行错误反馈并有界修复；缺失/重复ID等无法配对的响应先停止本轮。此为目标合同确认，不是该功能已实现或批准所有后续能力立即编码。

框架invalid_tool_calls不一定进入ToolNode，因此不能只加工具异常handler就声称覆盖；需要独立响应归一/配对验证切片。不能创建孤立ToolMessage或把无效参数当有效调用执行。若选择所有无效消息修复，需要模型级反馈通道与修复上限，另定Spec。

## 4. 重试合同

重试只针对一次调用，不是自动重跑Agent。每个调用只有一个明确所有者：当前sdk模式保留既有配置；未来runtime模式启用项目attempt治理时，SDK重试必须关闭并显式验证配置，避免两层次数相乘。工具SDK也遵守同样规则。

预算覆盖首次请求、重试、退避、排队和备用调用；等待可被用户停止/外部取消打断。单次60秒不代表整个run最多60秒。支持服务端Retry-After的受限安全提示；超出剩余预算不等待。不因认证/权限/错误参数/额度耗尽/安全拒绝执行盲目重试；未知故障也不默认重放。

未来项目重试推荐采用有上界的指数退避与随机抖动；具体初始/最大间隔、次数、总期限按每个实施切片配置/评测，不在未启用架构中硬编码。已有SDK算法不为形式统一而重写。

基础设施attempt与模型修复回合分别计数，有不同上限。同一次attempt错误事实只生成一次；后续策略复用它。早期失败若已恢复，不生成run failed；最终未恢复时传播最终那次原异常，早期原因留在轨迹。

## 5. 熔断与隔离

熔断状态：Closed正常放行→健康故障达到配置阈值→Open快速拒绝→冷却后HalfOpen有限探测→成功Closed/失败Open。冷却不直接全部恢复；并发只允许有限探测，避免恢复瞬间请求洪峰。

计数对象是重试后的逻辑依赖调用，attempt单独观测。Open拒绝、参数/权限/测试失败、程序bug不重复计数。第一次重试耗尽不必自动打开整个工具；阈值/窗口/冷却属于配置和实验选择。

作用域先按App实例内的依赖配置区分：工具名+目标/连接配置身份，模型按供应商配置+模型ID。无效文件路径不标整个read工具下线；不使用裸密钥/完整URL作公开标识。未来多租户/多worker共享健康状态另定隔离，不用全局变量跨用户共享。

熔断控制“要不要发请求”；资源隔离控制“故障依赖占用多少并发/队列/时间”。可用按依赖的有限并发/队列/总预算，第一版先本机内存状态。它们都不是OS沙箱或权限审批。已开始同步工具仍须settle，不能因超时释放槽位却让操作继续无界执行。

## 6. 备用与降级

工具不可用时，反馈当前实际注册、可用且授权的同能力候选。模型决定新工具调用；不同参数格式或目标不能静默重路由，除非明确提供转换与授权绑定。备用工具不能继承原工具的宽泛授权。

历史信息可以作为带来源/时间的背景，不冒充本次工具结果。实时状态/测试断言要求新证据时，历史不可使任务显示通过；告知无法确认或暂停给用户。

模型failover使用显式候选顺序和边界，不循环切换。切换前确认工具/结构化输出/多模态能力、上下文窗口、输出预算、数据限制、成本；按实际候选重新装配请求并记录requested与actual model_id。默认只覆盖本次调用，不悄悄改用户会话选模。

默认只对未输出内容且无已执行副作用的当前模型请求透明恢复。已有流式片段时先标草稿未完成；若恢复须显式废弃/替换草稿，不拼成一条回答、不自动重放工具。不通过备用模型绕过安全拒绝。当前客户端工具前提下的重试资格，不能直接迁移到服务器工具或托管Agent。

## 7. 模型正常返回与质量

分开传输可用性、协议正确性和业务质量。HTTP成功不代表消息符合协议，协议合法不代表答案正确。已有无效调用/stop reason门禁是前两者的一部分，不是完整语义验证。

首选可验证检查：工具schema与结果配对、结构化结果schema、引用证据、测试产物及执行报告。语义判断用固定样本/评分标准/必要独立评审；不靠模型自评或“隐式判断”宣称事实正确。修复回合有界，质量失败不直接作为依赖离线熔断；质量低于阈值是否换模型另用实验决定。

## 8. 分层、框架复用与可观测性

Model Access负责SDK适配、失败归一和供应商提示，不认识会话/UI；现SDK内部重试是底层调用能力。Runtime在模型/工具执行边界治理恢复、控制/副作用和反馈，复用create_agent，不重写运行时。App注册配置/权限/候选、管run与存储；test_agent定义测试业务结果与质量验证，不将测试缺陷改成工具健康故障。

LangChain已有ToolErrorMiddleware、ToolRetryMiddleware、ModelRetryMiddleware、ModelFallbackMiddleware。默认优先验证可复用；工具retry应在错误反馈内侧且on_failure=error，让外层产生安全反馈；模型耗尽继续抛异常，不默认返回错误AIMessage。不能全工具打开通用重试，需验证本项目批次、审批、控制及流式配合。熔断/依赖资源上限/候选能力治理作为独立最小切片，不一次造“大一统异常引擎”。

轨迹区分逻辑call与attempt，关联run/session/call/attempt、实际依赖、耗时、退避、重试原因、熔断转移、备用/恢复结果。调用级与终局各记其事实，同一诊断不每层重复打印。原异常给程序，安全反馈给模型/用户；开发诊断可记录经脱敏的栈帧，不默认记录SDK正文、请求/响应、URL、headers或局部变量。原粘贴文本的“完整原始错误日志”不能覆盖本项目脱敏规则。

## 9. 推进顺序与验证边界

| 阶段 | 独立交付/完成判据 |
|---|---|
| A 行为与诊断基础 | 先确认本表与协议恢复边界，再锁定Spec080；原异常标注/一次分类/安全反馈事实及控制不回归 |
| B 工具反馈闭环 | 参数/未知工具/校验/权限/可配对无效调用回流，修复有界；不可配对/bug/未知副作用不误当可恢复 |
| C 安全工具重试 | 一个受控外部工具、明确重放契约、退避/停止/次数/总预算；重试耗尽反馈、不掩盖SUT失败 |
| D 模型attempt治理 | 选择唯一所有者，原SDK模式兼容；实际attempt事件、总预算、停止、耗尽原异常和部分输出保护 |
| E 熔断与隔离 | Closed/Open/HalfOpen、有限探测、实例作用域/配置更新、资源预算与安全候选提示 |
| F 模型故障切换与质量 | 候选能力/窗口/授权/成本/流式草稿，正常返回验证及对照评测；无悄悄会话选模变化 |

每阶段先Spec、红灯测试、真实接线、确定性/实际集成分开验证。测试使用可注入时钟/随机与事件同步，避免靠短sleep猜状态。以后实现才锁定各参数默认与公开字段，不将本讨论稿当这些实施细节已批准。工具核对策略与上述结构/治理分为独立切片。
